Creating a form

New forms from an existing or a new table, or written by an AI.

For: Users with rights on: nuform

Forms → Add first asks how to start (New form or page): Step by step (the wizard below), Describe it – AI creates it (Forms with AI, one form or a small app), – for the globeadmin – Copy an existing form (the Form cloner), and Custom page (your own PHP app: a short dialogue asks for the description, the code – the folder name – and how it opens, then the page editor opens). The last choice is marked the next time.

Step by step asks in three steps – Form (description, code, type), Table and fields and Layout and access; Next checks each step, a finished step can be opened again by clicking its title. The new form then opens in design mode – on its first record or an empty one, a browse form on its list; custom pages open their own editor.

  • Existing table: pick the table (type part of its name to search the list) and primary key – objects and list columns are generated from its columns. By default every column gets an object (an auto-increment key is left out) and the first six get a list column. Choose columns and order opens the column list: untick columns you do not need, type a label of your own (empty = the label shown in grey), choose which columns go into the list and which of them get a Filter (a select above the list, as the column filter in design mode), and change the order by dragging a row at its grip, with the arrows or with Alt+↑ / Alt+↓ – the order is the order of the objects on the form and of the list columns. Reset goes back to the default.
  • A view: when the database has views, the list shows them under their own heading Views, below Tables. Picking one suggests its key column (a column named <view>_id, else the first one ending in _id, else id, else the first column) and says whether the database can save changes to it. A view it cannot save to (with GROUP BY, DISTINCT, UNION, aggregates …) switches the form type to Browse; a key column with repeated or empty values is pointed out – choose a column that is unique for each row. On a view that joins several tables the database may allow changes but not new or deleted records.
  • New table: enter columns (name, label, type, length, required). The table gets a text primary key – nuBuilder ID (nuBuilder Forte's ids, VARCHAR(25)) or UUID (VARCHAR(36): new records get a UUID, easy to exchange with other systems; the column type Record ID – UUID is for columns that point to such records) and optionally audit columns (created/updated at/by), filled on every save, and/or a record log <table>_nulog (JSON: who added the record and who last edited it, and when; shown in the record's ⋮ menu). crosses a column out – it is not created; brings it back.

After creating (not for sub-forms):

  • Add a button to User Home (on by default): as nuBuilder Forte's Fast Design mode does, a run button for the new form is placed on the tab Fast Forms of nuBuilder Forte's launch form User Home (nuuserhome) – nuBuilder Forte shows the same button; a message after creating says so. User Home opens from the house icon next to ☆ in the start page's search row, the user menu and the start page tile User Home.
  • Access for access levels (with the right to change access levels): the levels you tick get all rights on the new form, and their users find it on their start page – on the automatic one at once, on a saved start page layout as a new tile in its first group. Select all ticks (or clears) the levels shown; when access levels have a group, a select above the list shows only the levels of one group – levels already ticked stay ticked while hidden, and the counter shows how many are ticked in all.
  • Changing User Home: Design on the form (or Forms → User Home) opens it like other forms – tabs, objects with their events and the Before Edit PHP can be changed, also as a draft. nuBuilder Forte's updates keep exactly these parts; its form settings, other code and list stay read-only.
  • A database without User Home gets it on installation and with every update – nuBuilder Forte's launch form nuuserhome with its tabs Main and Fast Forms, as nuBuilder Forte's installation creates it. An existing User Home is never changed.
  • A user whose access level has User Home as its home form may open it and finds it on the automatic start page, as in nuBuilder Forte.

Forms with AI

A form – or a small app of several forms – can be created or changed with any AI chat (Claude, ChatGPT …) – no API key, nothing is sent from nuBuilder Next: Forms → Add → Describe it – AI creates it for something new; Ask AI in design mode (panel → Tools) for the form you are designing.

The page is a wizard in three steps; a finished step can be opened again by clicking its title.

  1. What to create: One form or Small app, and the description (fields, lists, lookups, the table – new or existing). Next needs a description.
  2. Existing tables the AI should know with their columns: None – new tables only (the default for something new, the shortest prompt), All tables (up to 80, a long prompt) or Choose tables (searchable, several; the default when changing a form – its own table is preselected). A new table needs nothing here: name it in the request or let the AI choose a name – Check lists it for you to tick. Then click Copy prompt and paste it into the AI chat. The prompt holds a short description of nuBuilder Next's form format, the chosen tables with their columns, the forms lookups and sub-forms can use and – when changing – the current form.
  3. Paste the AI's whole answer – Paste takes it from the clipboard, and pasting into the field checks it at once – or click Check: errors (unknown types, forms or columns that do not exist, duplicate ids …) are listed – ask the AI to correct them or edit the JSON. Otherwise you see what happens: a new table, new columns, new / changed / removed objects, tab and list changes.
  4. Create draft: a missing table or columns are created first, only after you tick the box (they stay even if the draft is discarded). A new form is created with status Draft – only designers see it; check and publish it in design mode. A change becomes a form draft: the live form stays as it is until you preview, compare and publish it. When the form already has an open draft, the change goes into it as one more step (Undo takes it back) – so Ask AI in design mode works step by step: ask, apply, look, ask again; each prompt describes the draft as it is now. A form that was never published is changed directly.

Ask AI: with an AI provider set up, Ask AI (next to Copy prompt, also in design mode's dialogue) sends the prompt to the AI service and puts its answer into the answer box. It is checked like a pasted answer; errors go back to the AI once for correction. Nothing is created before you say so.

Context file: next to Copy prompt (and in design mode's Ask AI), Download context gives a file to attach to the AI chat together with the prompt – the AI then knows this installation instead of guessing: the request format, the chosen tables (structure only), the forms, three complete example forms (the sample application's customers and orders forms), the hash variables, the guide pages on form events, object types and validation, and the PHP and JavaScript functions nuBuilder Next has. The main button downloads one Markdown file (nunext-context-form-<version>.md, or …-form-<form code>-… when changing a form, …-app-… for a small app) that every AI chat reads; ▾ also offers a zip with one file per section, and Full function reference adds the parameters, results and examples of every function and more guide pages (larger – for chats that take big files). The prompt asks the AI to read the file first. The file holds no data of your tables, no settings and no passwords; it does contain the code of the form being changed.

Small app: several forms with their tables from one description, e.g. projects with their tasks. The forms may refer to each other – a sub-form, a lookup – before they exist; tables and columns are created in one go (the foreign key of a sub-form gets an index), and every form gets status Draft. After Create tables and forms the forms are listed with Design links and Publish all; give access levels their rights on the forms afterwards.

Code: the AI may also write the form's JavaScript (list, record, both), CSS, PHP hooks (Before Browse, Before Edit, Before Save, After Save, Before Delete, After Delete) and events of objects (onchange, onclick …). PHP is checked for syntax errors before anything is created, and an answer with PHP is flagged: it runs on the server once the form is published, so read it in the draft (Code) first. Code the answer leaves out stays as it is.

  • The format describes inputs (all input types), textareas, selects (options or SQL – a list kept as written while its options do not change, so a JSON list stays JSON), lookups, sub-forms (an existing form of type sub-form), display and HTML objects and words, tabs and the list columns. Other objects (calculations, run buttons, charts …) are marked “keep” and stay unchanged, as do the SQL builder rows. Columns no object shows (a sub-form's foreign key) are listed under the form's columns.
  • Existing objects keep their place; new ones are placed below the object before them (or next to it with same_row) and move the following ones down.
  • Not for nuBuilder Forte's system forms and custom pages. Since the prompt contains the table names and columns, check what your AI provider may receive.
