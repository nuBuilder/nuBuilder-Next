Creating a form

New forms from an existing or a new table, or written by an AI.

For: Users with rights on: nuform

  • Existing table: pick the table (type part of its name to search the list) and primary key – objects and list columns are generated from its columns.
  • New table: enter columns (name, label, type, length, required). The table gets a nuBuilder-style text primary key and optionally audit columns (created/updated at/by), filled on every save, and/or nuBuilder's record log <table>_nulog (see below). crosses a column out – it is not created; brings it back.

Forms with AI

A form can be created or changed with any AI chat (Claude, ChatGPT …) – no API key, nothing is sent from nuBuilder Next: Forms → With AI (also in the new-form page) for a new form, Change with AI in the form builder for an existing one.

  1. Describe it (fields, lists, lookups, the table – new or existing) and click Copy prompt. The prompt holds a short description of nuBuilder Next's form format, the tables and columns of the database, the forms lookups and sub-forms can use and – when changing – the current form. Paste it into the AI chat.
  2. Paste the AI's whole answer and click Check: errors (unknown types, forms or columns that do not exist, duplicate ids …) are listed – ask the AI to correct them or edit the JSON. Otherwise you see what happens: a new table, new columns, new / changed / removed objects, tab and list changes.
  3. Create draft: a missing table or columns are created first, only after you tick the box (they stay even if the draft is discarded). A new form is created with status Draft – only designers see it; check it with Open form and publish it in the builder. A change becomes a form draft: the live form stays as it is until you preview, compare and publish it.
  • The format describes inputs (all input types), textareas, selects (options or SQL), lookups, sub-forms (an existing form of type sub-form), display and HTML objects and words, tabs and the list columns. Other objects (calculations, run buttons, charts …) are marked “keep” and stay unchanged, as do events, custom code, hooks and the SQL builder rows.
  • Existing objects keep their place; new ones are placed below the object before them (or next to it with same_row) and move the following ones down.
  • Not for nuBuilder's system forms and page forms. Since the prompt contains the table names and columns, check what your AI provider may receive.
