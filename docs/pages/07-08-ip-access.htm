IP access

Allow signing in only from certain addresses or networks – for all access levels, with exceptions per level and a rule of its own for the globeadmin.

For: the globeadmin

Settings → Sign-in & security → IP access (index.php?p=ipaccess) is off until you switch on Restrict sign-in by IP address. The page shows the address you are using now.

The rules

  • All access levels: the allowed addresses, one per line (or separated by spaces or commas) – a single address such as 203.0.113.7 or 2001:db8::1, or a network with a prefix such as 10.0.0.0/8 or 192.168.1.0/24. Text after # is a comment. An empty list allows every address.
  • Exceptions per access level: Default uses the list above, Any address lets the level sign in from everywhere, Own ranges replaces the list for that level. A user with several access levels (the main level and active additional levels) may work when any of them allows the address.
  • Globeadmin: Same as all access levels, Any address or Own ranges. This rule also applies while the globeadmin acts as a user.

When it is checked

  • When signing in – with the password, an auto-login link (?u=…&p=…) or a one-time login link – before the second factor is asked. The user sees “Signing in is not allowed from this network”; the log has an entry Refused because of the IP address with the address, and the attempt counts as a failed sign-in.
  • On every page: a session that suddenly comes from an address that is not allowed ends (e.g. a stolen session cookie used elsewhere, or a laptop that left the office network).
  • Not checked: clients of the REST API (they have their own Allowed IPs) and demo sessions. Sessions taken over from nuBuilder Forte are checked like any other.

nuBuilder Next uses the address the web server sees. Behind a reverse proxy or a load balancer that is the proxy's address – set $nuConfigTrustProxy = true in nuconfig.php there (the page warns when a request came through a proxy while it is off).

Testing and getting back in

  • Test an address shows, for the saved rules, whether the globeadmin and which access levels could work from an address.
  • Saving is refused when the new rules would block the address the globeadmin is using now; saving also asks for the password again.
  • Locked out anyway (e.g. a new address at home)? On the server: php cron.php iprules off switches IP access off; the rules stay stored, so switching it on again brings them back.
