CSV import

Advanced Importing CSV files into tables, and importing users.

For: Administrators (globeadmin, admin roles)

Admin tools → CSV import (also Forms → Tools; globeadmin only) imports a CSV file into a table of the database in three steps. nuBuilder's and nuBuilder Next's own tables (zzzzsys_…) cannot be chosen.

  1. File: choose or drop the file (up to $nuConfigImportMaxMB, default 20 MB). The encoding (UTF-8, UTF-16, Windows-1252 from Excel) and the separator are detected; separator, text qualifier and "first row holds the column names" can be changed – the preview shows the first 10 rows.
  2. Mapping: choose the table; Map automatically matches CSV columns by name (also with the table's column prefix like cus_, German and English synonyms). Each column gets a CSV column, a fixed value or – for nuBuilder ids – Generate nuID(). Date columns get a format (detected from the file; Unix timestamps and Excel numbers too); numbers follow the chosen decimal separator (detected), yes/no values (ja, x, true, 1 …) become 1/0. The preview column shows converted values and problems right away.
    Options: add new records, update existing ones or both (found by a key column), empty values as NULL or empty text, trim spaces, fill created/updated columns, and what happens on errors: all or nothing (default) or skip faulty rows.
  3. Check runs the whole import as a trial in a transaction that is rolled back – it shows new, updated and faulty rows with line, column, value and problem, including database errors such as duplicate keys. The problem list can be downloaded as CSV. Import now then writes the data.

Save configuration downloads the mapping and options as JSON; Load configuration applies it to the next file (columns are matched by name). The uploaded file is kept only for this session in a private temp folder and deleted after the import. Every import is written to the Log.

Importing users

Users → Import… (whoever may add users: the globeadmin, an access level with Add on the user form, or an admin role with Users) opens the CSV import in a new tab with the target Users (zzzzsys_user). Users with only that right see no other target; the target is not a plain write into zzzzsys_user but runs the checks of the user form:

  • Download template (step 1, next to Load configuration): a CSV file with the column titles of the user import in your language (header row only, separator $nuConfigCSVSeparator or ;, UTF-8 for Excel). Fill in one row per user in Excel, save as CSV and upload it – Map automatically recognises every column.
  • Columns: login name (required, not the globeadmin's name), full name (empty = first and last name), first and last name, e-mail (checked), code, position, department, team, additional 1/2, valid until (date), language and password.
  • Access level: a CSV column with the access level code (or ID), or – Fixed value – one level chosen from the list for all rows. With Only the globeadmin grants admin rights (Security check) admin-equivalent levels are refused.
  • Language: de, de-CH, en-US, German, Deutsch, English (US) … – stored as nuBuilder's language name plus the variant.
  • Logins that already exist are skipped (nothing is changed) and listed after the check and the import. A login twice in the file is an error.
  • Password (optional column): stored as a hash (bcrypt; md5 while $nuUseMd5PasswordHash is on), at least $nuConfigPasswordMinLength characters; every imported user must change the password at the first login. The preview never shows passwords. Rows without a password get a random one; with Send a welcome e-mail to users without a password (needs a configured e-mail, see Welcome e-mail) they receive the welcome e-mail with the link to set their own – such rows need an e-mail address.
  • Check only reads – nothing is written. Import nothing (all or nothing) writes no user if any row has a problem. Every user created is logged as User created (source CSV import).
