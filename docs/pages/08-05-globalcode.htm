Global code

Advanced JavaScript and CSS for form pages (nuBuilder Forte's Setup) and for every page (Global JS & CSS).

For: Administrators (globeadmin, admin roles)

Admin tools → Global code (globeadmin or the admin role right Global code – a full-access right, because the code runs for every user) has two groups of tabs. Each tab has its own code editor; the tab is part of the address (#header, #style, #include, #gjs, #gcss) and stays open after Save. The editor reaches down to the bottom of the window, so a taller screen shows more lines; its toolbar has undo / redo, search, replace, toggle comment, show spaces and tabs, format, copy / paste and full screen (F11).

Templates

Every tab has a Templates menu next to its hint with ready-made code for that tab, grouped by kind: Buttons & look (round or coloured buttons, labels, compact forms, striped lists, tabs, navigation bar, side bar, start page tiles, sign-in page), Page-specific examples (a banner on the start page, hiding an element on one page, colouring browse rows of one form), Form helpers (nuBuilder Forte's hooks, a confirmation before saving, upper-case input, an info bar) and Ready-made functions (a toast message, a debounce helper, external links in a new tab, fonts and files to include).

  • A click on an entry inserts its code at the cursor of the tab's editor, on lines of its own – nothing is saved until you click Save.
  • Preview all … opens a dialogue with every template of the tab: pick one to read its description and code, then Insert it or Copy it to the clipboard.
  • The templates are examples: change the colours, page names and form codes to your own. The JavaScript templates of the global tab use the page hook, so they run only on the pages they name.

Form pages – nuBuilder Forte's Setup

The three code fields of nuBuilder Forte's Setup form in zzzzsys_setup, so nuBuilder Forte (4.x) and nuBuilder Next stay in step. They run on form pages only (browse and edit), as in nuBuilder Forte. The (i) next to each tab's hint names the field in nuBuilder Forte.

  • Form JavaScript – nuBuilder Forte's Header (set_header): on every form page after nuBuilder Next's runtime and before the form's own code – your global functions and nuBuilder Forte's nuLoadEditGlobal, nuLoadBrowseGlobal, nuOnLoad.
  • Form CSS – nuBuilder Forte's Style (set_style): on every form page after nuBuilder Next's styles.
  • Form includes – nuBuilder Forte's Include (set_include): its <link>, <script> and <style> elements are added to every form page (after the runtime and $nuConfigIncludeJS, before Form JavaScript); other text, HTML comments and /* … */ blocks – such as nuBuilder Forte's default text – are ignored. Addresses on other servers are allowed by the page's Content-Security-Policy. (nuBuilder Forte 4.9 saves this field, but in our tests did not output it.)

All pages – Global JS & CSS

JavaScript and CSS for the pages of nuBuilder Next itself – start page, lists, admin tools, record pages, form pages, and on request the sign-in pages. They are kept in nuBuilder Next's own settings, never in zzzzsys_setup, so nuBuilder Forte is not affected.

  • Runs on: three switches, the same on both tabs – Form pages, Other app pages (on by default) and Sign-in pages (off by default: they are public, so anyone could read the code there – never put secrets into it).
  • Never on the Global code page itself and on the Update page, so a mistake can always be repaired or a release rolled back.
  • Safe mode: add ?safe=1 (or &safe=1) to the address – the page opens without Global JS & CSS. It works for the globeadmin and for admins with the right Global code; everybody else always gets the code.
  • The code is delivered as files of this server, so the strict Content-Security-Policy of nuBuilder Next's pages stays on. That is also why there is no Include tab here: code from other servers is not allowed on these pages.
  • Global CSS comes before each page's own styles – on form pages before Form CSS and the form's style, so these win. It is loaded as a CSS file, so it takes plain CSS only: a surrounding <style>…</style> (e.g. pasted from Form CSS, where either form works) is removed on Save, with a note.
  • Global JavaScript comes at the end of the page – on form pages before Form JavaScript and the form's code, so a form's nuOnLoad or nuLoadBrowseGlobal always wins. Do not define nuBuilder Forte's hook names (nuOnLoad, nuLoadBrowseGlobal, nuLoadEditGlobal, nuBeforeSave …) here; the page and the Compatibility check warn when you do. Use the page hook instead.
  • jQuery and nuBuilder Forte's functions exist on form pages only. On the other pages write plain JavaScript (document.querySelector …).

Page hook – which page is this?

Every page names itself, so global code can target single pages and skip the ones it was not written for.

On <body>ValueSet on
data-nu-pagethe page name – the ?p= part of the address: home, form, users, reports, login …every page
data-nu-modebrowse or editform pages
data-nu-formthe form code, e.g. customerform pages
data-nu-admin1 for the globeadmin and users with an admin roleevery page, when it applies

For CSS, select with these attributes – page names stay stable (they are in addresses and bookmarks), class names may change with an update:

body[data-nu-page="home"] .nuHomeTile { min-height: 140px; }
body[data-nu-page="login"] { background: #12355b; }
body[data-nu-form="customer"][data-nu-mode="browse"] #nuBrowseTable { font-size: .9rem; }

For JavaScript, once the page is ready nuBuilder Next calls nuOnPageLoad(page, info) when it is defined, and then fires the event nu:pageload, so several snippets can react without replacing each other. info (and the event's detail) is {page, mode, form, admin}. On form pages both run after the form's nuOnLoad. Put everything inside them and check page first – a call at the top level such as nuSetTitle() fails on pages without a form.

function nuOnPageLoad(page, info) {
    if (page === 'home') {
        const note = document.createElement('div');
        note.className = 'alert alert-info';
        note.textContent = 'Maintenance on Friday from 18:00';
        document.getElementById('main').prepend(note);
    }
    if (page === 'form' && info.form === 'customer' && info.mode === 'browse') {
        nuBrowseLoop([2], function (cell) { if (cell.textContent.trim() === 'US') cell.closest('tr').style.setProperty('--bs-table-bg-type', '#eef5ff'); });
    }
}

document.addEventListener('nu:pageload', function (e) {
    if (e.detail.page === 'reports') { /* … */ }
});

Pages that build their own page (error pages, print views of lists, e-mails, page forms) do not get Global JS & CSS.

  • Only changed fields are written. A field someone else changed since the page was opened (in nuBuilder Forte or another tab) is not overwritten: the page says which one and keeps your text – saving again overwrites. Saves are logged (Global code (form pages) changed with the fields, Global JS & CSS changed with the parts).
