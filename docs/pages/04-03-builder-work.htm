Designing a form

Design mode: change a form where it runs – objects, properties, the list, code, history and drafts.

For: Users with rights on: nucodesnippet, nuform

Forms are changed in design mode, on the form itself: open a record (or the list) and click Design in the form's toolbar – or click a form in the forms list. The globeadmin and everybody with the Save right on the form nuform (through their access level or the admin role right Forms) can use it. The form stays as it is, with its data and tabs; a bar at the top, an icon bar on the left (from the top: Form settings, Structure, Add, Code, Validation rules, History, Browse list; the keyboard help at the bottom) and a properties panel on the right (a sheet at the bottom on phones) replace the record buttons. Buttons and links of the form do not run while designing. Custom pages keep their own editor (Custom pages); old links to the design mode open design mode.

Only the globeadmin renames or deletes tabs (the tab menu shows them greyed for others) and deletes forms; Publish needs the admin right Publish forms (drafts) – without it a change stays in the draft for someone who has it. Safe mode ( in the bar) opens the form without its own code: no form JavaScript and CSS, no Before Edit PHP, no Setup header or include, no scripts of HTML objects. Use it when the form's code breaks the page; the bar shows Safe mode – form code off, the same button leaves it.

  • Selecting: click an object; Ctrl/⌘ + click adds or removes one, dragging on an empty place selects every object the box touches (absolute layout); Esc selects nothing and shows the form's settings. Objects the form's own JavaScript hides are shown faded with Hidden by form code, so they can still be selected.
  • Changing: drag to move, the corner handle to resize, arrow keys move by 5 px (Alt: 1 px), Shift + arrow keys change the size; auto and grid layouts take a drop before, after or into a content box. With several objects selected the panel's Arrange section aligns (top, bottom, left, right), spaces (vertical, horizontal) and sizes them (shortest, tallest, thinnest, widest); Order in Layout moves an object up or down in the tab order. Right-click an object for the same menu as on the form (properties, rename, actions, access, alignment, validation). Delete deletes the selected objects after a question that names them; Ctrl/⌘ + D duplicates them with their events.
  • Fixed gap (two or more objects): enter the gap in pixels at Horizontal gap / Vertical gap and click Apply. The first object stays; each next one follows the previous one at exactly that distance – vertically from bottom edge to top edge, horizontally from the right edge to the next object's label (so labels never overlap). The gaps you use are remembered in this browser.
  • Properties panel: Content, Behaviour (access, access condition, validation, the object's events), Layout (top, left, width, height in absolute layout; the width in columns – and row, column, content box in grid – otherwise; the tab), Style (alignment, icon, style type and value, HTML attributes with the attribute editor) and Tools. More settings opens the less used ones. Every object type has all its properties: formats with the format designer (+ creates one, the pencil edits it), text masks, datalists, nuScroll lists, auto-number start, the file target with the Uppy template, display SQL and procedure, select SQL, calculation, lookup form / code / description / table / JavaScript / After Browse PHP, sub-form form / link / table / Add and Delete rows, chart settings, image file, run form / procedure / report with method, target, record id and filter. Lists of forms, procedures and reports are searchable. A field is saved when you leave it or press Enter; label, position and size already change on the form while you type, Esc puts the saved value back. Code fields have next to their label: a larger code window with the code editors' toolbar and, for SQL and HTML, the # menu of hash variables. After a change only the form's body is drawn again; the form's own JavaScript (nuOnLoad) runs again with Reload the form. A content box is selected and dragged by its frame and title.
  • Form settings (nothing selected, or the window icon in the icon bar): description, code (required – marked * in the new form wizard), group, type, status, breadcrumb title, table and primary key, the layout – absolute (pixel positions as in nuBuilder Forte (4.x); objects stack as there, content boxes behind), auto (responsive rows from the positions) or grid (12 columns; converting writes the auto result as a start) – and Show tab order: a red number on every object the Tab key stops at. Tools: Change with AI, Access levels (the rights of every level on this form), Translations (the form's texts per language, with the number of missing ones – see Translations of a form), Data access and Delete form.
  • Structure (icon bar, Ctrl+K; on phones a button in the bar): the tabs with their objects in order – search by ID or label, filter by tab and object type, fold a tab section with a click on its title (the number shows its objects), click an object to select it (the tab opens), drag a row to change the order or onto another tab (or its title) to move it there.
  • Keyboard (? or at the bottom of the icon bar lists them): arrow keys move by 5 px (Alt: 1 px, Ctrl/⌘: 20 px), Shift + arrows change the size; Tab / Shift+Tab select the next / previous object in tab order; F2 renames the selected object (label and ID; on the list: the column title); Ctrl+C / X / V copy, cut and paste objects with their properties and events – onto the open tab, also of another form (the copy stays in this browser); Ctrl+D duplicates, Delete deletes, Ctrl+A selects all objects of the tab, Ctrl+Z undoes the last change, Ctrl+S only says that every change is saved at once, Esc selects nothing. Keys the operating system takes for itself (on macOS Ctrl+↑ / ↓ open Mission Control) do not reach the page – use ⌘ there.
  • Add: the columns of the form's table that are not on the form yet (with a matching object type: checkbox for yes/no, date, number, text area for long text) and every object type. Input opens a second page, What kind of input?: the frequent kinds as tiles – text, number, date, checkbox, e-mail, phone, button, file, time – and the others below All input types; the new input gets the kind and its name as label, the page stays open for the next one, the arrow goes back to all elements (dragging the Input tile itself adds a text input). The kind can be changed later in the panel. A click adds it at the bottom of the open tab, dragging places it where you drop it (absolute layout). An object's ID / field may contain only letters, digits and _ and must not start with a digit; when it has no column in the table, the panel offers to add the column.
  • Tabs: double-click a tab to rename it (Enter saves, Esc cancels), + after the tabs adds one, drag a tab to move it; right-click for Rename, Hide / Show, Hide for users, Move left / right and Delete (its objects move to the first tab). Hidden tabs are shown faded while designing.
  • The list: Design on a form's list (or Design the list in the form settings) opens design mode on the list page. Click a column title to select the column – title, display (a column of the browse SQL or an expression), format, width (0 hides it), alignment, filter and Show as badge – the values become coloured badges (as nuBrowseStyleBadge()); Colour rule adds rules such as "is Urgent → red", "contains", "starts with" or "any other value", the first that matches wins. Badges are drawn before the form's nuOnLoad, so a call of the form's own code still wins; nuBuilder Forte ignores them; drag titles to reorder, ← / → move the selected one, + asks which column to add – a column of the table that is not shown yet, or an expression – and adds nothing before that choice; the bin removes it. A right-click on a title opens the column menu, as in nuBuilder Forte: the object name (click to copy), Properties…, Rename…, Align (left, right, centre), Width (type it and press Enter), Filter, Move left / right, Hide / Show and Delete. The browse SQL is in Code; Design the edit screen goes back to the record. Without design mode, the ▾ next to Design on the list offers Edit browse SQL… (Ctrl+Shift+B): a pane on the right with the SQL in the code editor – Save (Ctrl+S) stores it in the form at once (in the open draft while you look at its preview) and reloads the list. The pin keeps the pane open – after saving, on the next page and on other lists – until you close it. Comment lines at the end of the browse SQL are ignored when the list is built. The columns keep their stored widths, spread over the width of the list (as nuBuilder Forte's auto resize), whatever the rows of a page contain – a longer value ends in …
  • Sub-forms: a sub-form object links to Design the sub-form, which opens the sub-form's own form in design mode (its columns are its objects).
  • Change column… (an object's Tools, for objects that store a value; as nuBuilder Forte's Alter Database Column): shows the column's current type, the number of rows and whether it is the primary key or the table is used by other forms. Pick a new type and length – the dialogue shows the exact ALTER TABLE and checks the data first: values longer than the new length, texts that are not numbers or dates, numbers too big or rounded, dates losing their time, values that are not 0 / 1, empty texts in a NOT NULL column – each with the count and a few examples. When values would change, Change column needs a tick. Nullability, default and comment are kept. The globeadmin may write their own statement instead (Own SQL statement: one ALTER TABLE of this table; it runs without a data check). It needs the password again when it was last entered more than the confirmation time ago (afterwards you are back in design mode with the dialogue open), runs at once on the database (no undo – back up the table first when its data matters), is logged (Column changed) and, in a draft, listed in the publish summary. Not for auto-increment columns, nuBuilder's own zzzzsys_ tables or SQLite.
  • Browse list (icon bar , forms of type Browse or Browse and edit; also from the form settings): every setting of the list in the large window, as a tab next to Code and History – on the left rows per page, row height, what a click on a row does (open the record here as a new breadcrumb, here in place of the list, in a new tab or in a popup), the form that opens the records, column titles on several lines, columns that fill the width; buttons for the Browse SQL, the PHP Before Browse and the list's JavaScript; on the right the columns as a table – title, column or expression, width, alignment, show / hide, order (drag a row by its number, or the arrows), delete, Add column. These are nuBuilder Forte's list settings, stored in the same fields. On the list itself, a click on a column title still selects that column.
  • Validation rules (icon bar , edit form): rules the record must meet before it is saved – builder or expression, error or warning, sub-form rows, only for some access levels – with Test rule against a saved record; see Validation rules without code.
  • Access levels (form settings → Tools): which access levels may open the form and with which buttons – the same dialogue as ⋮ → Access levels… on the form (see Access levels of one form).
  • Delete form (form settings → Tools, globeadmin only, not while a draft is open) deletes the form with its objects, tabs, list columns, events, PHP hooks and access rights. The globeadmin can also tick Also delete the table (with the number of records): the button only works after the table name is typed exactly as shown (pasting is not possible), and the password must have been confirmed in the last minutes. The table is not offered when it is a view, a zzzzsys table or used by another form. Both deletions are logged. A deleted table can only be restored from a backup.
  • Code and History (icon bar): a full-width view over the form (Back to the form or Esc closes it). Code holds the form's JavaScript (browse & edit, edit, browse), CSS, the PHP hooks (Before Edit, Before Save, After Save, Before Browse, Before Delete, After Delete) and the browse SQL in one editor; a dot marks the parts that hold code, an orange dot the ones changed and not saved; Save or Ctrl+S saves all of them; changed JavaScript, CSS and Before Edit PHP take effect when you go back to the form (it is reloaded). On nuBuilder Forte's User Home only Before Edit is offered. History lists the saved states of the form (every change of the published form – the last 100 – and every published version, badge vN, kept for ever): Compare shows what changed from that state to now (to the draft while one is open), Restore brings the form back to it – only while no draft is open; the current state is saved first. Table changes (new columns) are not part of it.
  • Draft: the first change of a published form starts a draft (an open draft is continued): users keep the published form until you click Publish (a short note on what changed is optional – without one, History records the number of changes); Undo (Ctrl+Z) takes back the last step and Redo (Ctrl+Y) does it again, Discard drops the draft, Changes of the draft shows everything it changes (code line by line) with the checks before publishing, and warns when the published form was changed after the draft started – Publish then asks to type the form's code to overwrite those changes. A form that was never published is changed directly, and Publish form makes it available. Done leaves design mode – an unpublished draft stays open for later; while there are unpublished changes Done asks first: Publish now, Leave as draft or Cancel. The ▾ next to Publish switches Ask for a note before publishing off (kept in this browser): Publish then works with one click, and the window only opens for warnings, errors or when someone else changed the published form; Publish with a note… always asks.
  • Messages of the form: what the form's own JavaScript shows while you design (toasts, nuMessage()) does not cover the panel – the bar collects them behind the button with their number. Safe mode (shield) opens the form without its own code.
  • Selecting: a click selects an object, a double-click also puts the cursor into its label in the panel; the icons of the bar and the icon bar name themselves when the mouse rests on them.
  • On click of a column (list, column selected → Behaviour): what a click on a value of the column does instead of opening the row's edit form – the rest of the row still opens it.
    • Open a form: the form, the record (the row's record, the id in this column – e.g. a foreign key – or a new record) and where it opens (this tab, a new tab, a popup; Ctrl + click always opens a new tab).
    • Open a list for this row: another form's list in the context of the clicked row – from apartments to the people who live there, from customers to their orders. The row's id goes along as the hash variable named in Row id as property (default PARENT_ID), so the target's browse SQL filters with it: WHERE apartment_id = '#PARENT_ID#'. #PARENT_FORM_ID# holds the form the click came from. To open the list also on its own (all rows), write WHERE ('#PARENT_ID#' LIKE '#%' OR apartment_id = '#PARENT_ID#') – an unknown hash variable stays as it is.
    • Run a procedure / Run a report: with the row's id as that hash variable.
    • Call a JavaScript function: a function of the form's JavaScript or the Global code, by name; it gets one object with pk (id of the row), value (the cell), row, column, formId and $cell, and the click event as second argument.
    Look: Link (the value, underlined), Button (optional icon and text; empty text = the value) or Icon button (the text is the tooltip and the screen reader label). A user who may not open the target (form, procedure, report – the same check as for run buttons) sees the plain value; lookups and the print view never show the actions. A column with an action shows no badge. nuBuilder Forte ignores the setting: there the row opens its edit form as before. Stored in the column's sbr_json (nunext.action).
  • Phones: the bar is one line – Done, a dot for the state (grey: no changes, orange: a draft, blue: a new form), Structure, Add and a ⋯ menu with the rest (Publish, Undo, Redo, Changes, Code, History, Validation rules, Reload, Safe mode, Maintenance, Discard); it slides away while you scroll down and comes back when you scroll up. The panel is a sheet at the bottom with three heights: it peeks with the name of the selection, a tap on its handle (or a swipe up / down) makes it half or full height, and typing in a field opens it half way. The sections are tabs. Above the selected object a small toolbar offers Label and ID, Move up, Move down, Duplicate, Delete and All settings; the form scrolls so the selected object stays visible above the sheet.

Editing code

Fields that hold code – PHP, SQL, JavaScript, HTML or CSS – are shown in a typewriter font. Double-click such a field to open the code editor: syntax colours, line numbers and a full-screen button. Ctrl+Enter (or Ctrl+S, or OK) takes the code over into the field; Esc or Cancel closes the editor and asks first if you changed something. Save the record afterwards as usual.

The Source code of a code snippet needs no double-click: it is edited in place, with the editor and its toolbar right in the form; the Language field decides the syntax colours and the functions the editor offers.

The toolbar of every code editor (double-click editor, design mode, procedures) offers Undo / Redo, Search (Ctrl+F, then Enter / Shift+Enter for next / previous), Replace (Ctrl+H), Toggle comment on the selected lines (Ctrl+/), Show spaces and tabs, Full screen (F11, Esc ends it) and Format (Shift+Alt+F). Format tidies PHP, SQL (MySQL or T-SQL), JavaScript, HTML and CSS with the same rules as nuBuilder Forte; hash variables such as #RECORD_ID# are kept unchanged. Code with a syntax error is left as it is and a message names the problem. Undo reverts a format in one step.

Syntax check (the ✓ button of the toolbar, Shift+Alt+C): every code editor checks its code a moment after you stop typing and marks a problem in the gutter next to the line number – red for an error, yellow for a warning; hovering the mark names the problem, a click puts the cursor there. The button lists all problems of the editor (a click jumps to the line) or says that none were found. Nothing is run: JavaScript is parsed in the browser, PHP on the server (the same parser PHP uses, without running the code), CSS is checked for unclosed { }, comments and strings plus rules the browser ignores (a warning only – a newer browser may know them), HTML for unclosed <script> / <style> and the code inside them. Hash variables such as #RECORD_ID# count as names. On the Global code page, in procedures and in design mode's code window Save checks first: with an error a dialogue lists the problems – Save anyway saves, Cancel opens the code at the first error. SQL is not checked.

Insert (next to the toolbar, in the code editors) opens the functions of the function reference – PHP functions in PHP code, JavaScript functions in JavaScript and HTML: search (name, signature or description) and group, and for the selected function its signature, description, parameters, return value, example and sample result (on wide screens to the right of the list, on narrow ones below it). Insert call (Enter) inserts the call with the required parameters and selects the first one to type over; Insert example (Shift+Enter) inserts the example; Help opens the entry in the help. The tab Snippets lists the code snippets (nuBuilder Forte's Code Snippets) whose Selectable in matches the editor: Forms / Custom Code in the form's JavaScript, CSS and HTML, Setup / Header on the Global code page, SQL in SQL fields, Procedures/PHP in procedures and PHP events. A snippet without Selectable in appears in the editors of its language. Manage snippets below the list opens the snippets (with the right on them); SQL editors show only this tab. While typing, functions starting with nu or db_ are suggested after two letters (not in strings and comments) – ↑ / ↓ choose, Enter inserts the call, the box next to the list shows the signature and description; Ctrl+Space suggests for any word.

Copy and paste: click the label of a code field (for example PHP or JavaScript on a procedure; editors without a label, such as the double-click editor and the nuconfig.php editor, have a button in the toolbar) for Copy (the whole code), Paste (at the cursor – a selection is replaced, as with Ctrl+V) and Paste (replace existing) (the clipboard becomes the whole code; Undo brings the old code back). The browser may ask once to allow reading the clipboard. Without HTTPS, or when reading is refused, a small box opens instead: paste the text there and click Insert. Read-only editors offer only Copy.
