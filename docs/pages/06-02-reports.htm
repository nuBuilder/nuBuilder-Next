Reports and the report designer

PDF reports in nuBuilder Forte's format, designed and run in nuBuilder Next.

For: Users with rights on: nubuildreport

Forms → Tools → Reports (or the Reports tile): PDF reports – nuBuilder Forte's reports (zzzzsys_report) in the same format, so a report works in nuBuilder Forte (4.x) and in nuBuilder Next, whichever made it. The PDF is written by TCPDF, the library nuBuilder Forte uses. nuBuilder Next looks for it in this order: the folder in $nuConfigTCPDFPath, the TCPDF library pack (Update → Libraries – the usual way), <nuBuilder Next>/third_party/tcpdf, then nuBuilder Forte's copy (<nuBuilder Forte>/third_party/tcpdf, found automatically when nuBuilder Next is a subfolder of nuBuilder Forte). Without it the pages say so.

  • Report: code (used by nuRunReport('code')), description, group, data source and an optional launch form. Data sources, as in nuBuilder Forte: a procedure that creates the table #TABLE_ID# (e.g. nuRunQuery("CREATE TABLE #TABLE_ID# SELECT …")), a query of the SQL builder, or a table / view. Every hash variable that is not a column is added to each row (nuBuilder Forte's criteria) – so the fields of the form that starts the report can be printed and used in the SQL (#cus_country#).
  • Launch form: with one, the report opens that form first (the criteria), with a Run report button; without, the PDF comes right away.
  • The list: filters Group, Source type (table, SQL, procedure) and the source itself; the source links to its SQL builder query or procedure, the launch form to its form, the access count to the Access levels tab.
  • Access levels: users may run the reports ticked for their access level (zzzzsys_access_report); the globeadmin runs every report.
  • Running: a run object of type Report (button: PDF in a new tab; method iframe: the launch form or the PDF inside the form), the PDF button in the list, index.php?p=report&c=code, and in JavaScript nuRunReport(code[, iframeId]), nuRunReportSave(code, tag, callback(filename, id), fileName) (writes the PDF to the server's temp folder and the table pdf_temp (shared with nuBuilder Forte), e.g. to attach it to an e-mail in PHP), and – new in nuBuilder Next – nuPreviewReport(code) (the PDF in a dialogue) and nuEmailReportPDF(code, to, subject, body, fileName, callback) (sends the PDF as attachment with the e-mail settings). The form's values are the criteria.
  • Usage and History as for procedures; a report that run objects use cannot be deleted. A procedure that a report prints from shows the report under its usage.

A report from a procedure

When one query cannot deliver the report's rows – several steps, a value computed from all rows, data from more than one place – a procedure builds them: it creates the table #TABLE_ID#, the report prints that table, and nuBuilder Next drops it afterwards. An example on the sample application: the customers of a country with the number and total of their orders and each customer's share.

  1. The procedure (Procedures → Add, code rpt_cust_orders; it is not run from a button, so it needs no form and no access level):
    // the criteria: the field cus_country of the launch form ('' = all countries)
$country = nuHash()['cus_country'] ?? '';

// one row per customer, with the number and total of its orders
nuRunQuery("CREATE TABLE #TABLE_ID# AS
    SELECT c.cus_name, c.cus_country,
        COUNT(o.sample_order_id) AS orders, COALESCE(SUM(o.ord_total), 0) AS total
    FROM sample_customer c
    LEFT JOIN sample_order o ON o.ord_sample_customer_id = c.sample_customer_id
    WHERE c.cus_country = ? OR ? = ''
    GROUP BY c.sample_customer_id, c.cus_name, c.cus_country", [$country, $country]);

// a second step that one query cannot do: each customer's share of the total
nuRunQuery("ALTER TABLE #TABLE_ID# ADD share DECIMAL(5,1) NULL");
$sum = db_fetch_row(nuRunQuery("SELECT SUM(total) FROM #TABLE_ID#"))[0] ?? 0;
if ($sum > 0) nuRunQuery("UPDATE #TABLE_ID# SET share = ROUND(total * 100 / ?, 1)", [$sum]);
  2. The criteria: a form of type Launch with a select cus_country (copy the one of the customer form). Its fields reach the procedure as hash variables – read them with nuHash()['cus_country'] ?? '': a #name# that has no value stays as it is, so '#cus_country#' in the code would be the text #cus_country# when the report runs without the form.
  3. The report: Reports → Add, data source Procedure rpt_cust_orders, launch form the criteria form. The designer lists the table's columns (cus_name, cus_country, orders, total, share) – it runs the procedure with empty criteria to find them, so the procedure must create the table also when nothing is chosen.
  4. The layout: the four columns in the detail band, #cus_country# in the report header (every criteria field is a column of each row too), and SUM(total) in the report footer.

Pass values as parameters (? and an array) rather than writing them into the SQL. A query that fails writes its error to the Debug results and returns -1, as in nuBuilder Forte – when #TABLE_ID# was not created, the report says so. The SQL here is MySQL / MariaDB; on SQL Server write SELECT … INTO #TABLE_ID# FROM … instead of CREATE TABLE … AS SELECT.

Report designer

Designer opens the layout: the page with its bands top to bottom – report header (once), page header (every page), the headers of the sort groups, detail (each row), the group footers, page footer and report footer (printed once, right after the last detail row – not at the bottom of the page).

  • Fields (left): the columns of the data source and the launch form fields – drag them onto a band, or double-click to add them to the selected band. Below: page numbers (#page#, #pages#), code, description, date, user, and the images of Files.
  • Objects: field, text, box, line and image (toolbar). Drag them – also into another band –, resize with the handles, select several with Shift-click or a frame, then align, make the same size or distribute them. Arrow keys move (Shift 4 mm, Alt 0.25 mm), Ctrl+Z / Ctrl+Y undo and redo, Ctrl+C / Ctrl+V / Ctrl+D copy and duplicate, Del deletes, Ctrl+S saves.
  • Properties (right): content, content type (text, HTML, Markdown – below), summary (SUM(column), AVERAGE(a, b) = sum a / sum b, per sort group), format (nuBuilder Forte's formats), font, size in points, bold / italic, alignment, colours, border, position and size in mm, minimum / maximum lines (fields grow by lines; minimum −1 hides an empty field), layer. A band has its height, a page break and a designer color.
  • Report tab: paper (A4, A5, Letter, Legal), orientation, fields contain HTML, and up to five sort groups (field, ascending / descending, order) – each with a header and a footer band, printed when the value changes.
  • Pictures per row (a photo of each student or product): an image object whose field is a column of the data source. The column holds the full address of the picture (CONCAT('https://myserver/fotos/', first_name, last_name, '.jpg') AS photo), a data URL or a file of Files (JSON) – not an <img> tag and not a short path such as /fotos/x.jpg. The address must be reachable from the web server itself. Alternatively a field with <img src="/fotos/x.jpg"> works when its content is HTML (see below; the path is looked for below the web server's document root, nuBuilder Next's folder and nuBuilder Forte's folder). With TCPDF 7, pictures are read only from these folders and, as addresses, only from this installation's own host – a picture on another server is left out.
  • Texts may contain hash variables; a value starting with #B#rrggbb| or #F#rrggbb| gets that background / text colour (conditional formatting from the data source, as in nuBuilder Forte). A box is nuBuilder Forte's KEEP EXACT HEIGHT label.
  • New page (a band's properties): the new page starts before that band. For a new page per group, set it on the group's header – the first group still starts on the first page, below the report header. On a group footer it would move the footer to the top of the next page.
  • Preview prints the current layout (also unsaved) with empty criteria. The layout is stored in nuBuilder Forte's format (positions in pixels, 4 px = 1 mm), so nuBuilder Forte's designer can open it too.

Rich text: HTML and Markdown

Fields and labels print plain text, HTML or Markdown. The property Content of a field or label chooses it; Automatic follows the report's fields contain HTML (Report tab, nuBuilder Forte's "Use HTML" – for all fields and labels at once). In the designer an HTML or Markdown object carries a small HTML / MD tag.

  • HTML: what TCPDF prints – <b>, <i>, <u>, <br>, <p>, headings, <ul> / <ol>, <table>, <font color="…">, style with colours and sizes, pictures (<img> with a data URL, an http(s) address or a path of the web server's folder). Good for notes kept as HTML (for example from a rich-text editor of a form).
  • Markdown: converted to HTML by nuBuilder Next itself – # heading, **bold**, *italic*, ~~struck~~, `code`, lists with - or 1. (one level of nesting by indenting), > quote, ---, tables (| a | b | with a |---|---| line; --: aligns right), [link](https://…) and fenced code (```). A single line break stays a line break. HTML inside Markdown is printed as text.
  • Height: an HTML or Markdown object grows to the height of the printed content (in steps of its own height, the row height); minimum / maximum lines count these rows. In the page header and footer it keeps one row. A long object that does not fit on the page continues on the next one – the cut can go through a line of text or a table row, so keep such objects short or end the band with them.
  • Hash variables in an HTML or Markdown label (#description#, #page# …) are inserted as text: a value with < or & prints as it is.
  • Safety: before printing, <link>, <script>, <iframe> and the like are removed, pictures with another scheme (file:, phar: …) or .. in the path are left out, and links keep only http(s), mailto: and # addresses – the same for the report-wide switch.
  • nuBuilder Forte does not know the Content property: it prints the report by its Use HTML switch, and a Markdown field there shows the raw text. With the switch on, nuBuilder Forte breaks an HTML field into lines by the length of its raw text; nuBuilder Next measures the printed HTML instead.

Reports with AI

A layout can be written or changed by an AI chat (Claude, ChatGPT …) – by copy and paste, without an API key. On the report page the button Create with AI… (empty layout) or Change with AI… opens the dialogue; the designer's toolbar has the same button. For a new report enter code, description and data source, then Save and create with AI…: the report is saved with an empty layout and the dialogue opens.

  1. Describe the report – or what should change – in your own words, then Copy prompt and paste it into the AI chat. The prompt holds the description format, the columns of the data source, the criteria fields of the launch form, the formats, fonts and stored images, and the current layout. Download context gives a file to attach to the chat as well: the same facts plus the column types and the guide to reports; the first three rows of the data only when you tick it (real data – tick it only when it may leave the application).
  2. Paste the answer. It is checked at once: the bands, every object's place and size, the column names, formats, fonts, colours. Errors (an unknown column, a missing size) are listed for the AI to correct; notes (an object beyond the page) do not stop you. The plan shows paper, sort groups, the bands with their heights and how many objects are kept, new and removed.
  3. Preview PDF prints the described layout with empty criteria – nothing is saved yet. Apply stores it.
  • A query by the AI: with The AI may write a new query the prompt also describes the tables you choose (structure only), and the answer may hold a SELECT – joins, totals per group. It is accepted only when it is a read-only query that runs; the plan shows it with its columns. On Apply it is saved as an SQL builder query and becomes the report's data source. The switch needs the rights to add and save SQL builder queries. Off, the report keeps its data source and an answer with a query is refused.
  • Versions: before a layout is applied, the current one is kept – tab History, Earlier layouts, with Restore (which keeps the replaced layout too). A version holds the layout and the data source; the newest 20 per report are kept.
  • The AI answers in a short format of nuBuilder Next (millimetres, bands by name, objects field, text, sum, average, box, line, image); it is converted to nuBuilder Forte's layout, so the designer – also nuBuilder Forte's – opens the result. Objects the AI keeps carry their id and so keep properties the short format does not describe.
  • Ask AI: with an AI provider set up, the dialogue sends the prompt itself and puts the answer into the answer box – checked, previewed and applied as a pasted one.
  • In the designer, save the layout first: the AI works on the saved layout.

A complete example – criteria form, query with a hash variable and a total, the bands of the layout – is in Your first application. The sample application has two reports: customers by country (from a table) and orders by customer (from an SQL builder query).
