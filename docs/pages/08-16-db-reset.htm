Reset database

Advanced Start a development database again from a nuBuilder Forte SQL file.

For: Administrators (globeadmin) in developer mode

Admin tools → Reset database (index.php?p=dbreset) is shown only to the globeadmin while $nuConfigDevMode = true, and only on MySQL / MariaDB. It deletes all tables and views of the database – nuBuilder Forte's, nuBuilder Next's and the application's – imports a nuBuilder Forte (4.x) SQL file and creates nuBuilder Next's tables, as a new installation does. Use it on development and test installations to start again from a clean nuBuilder or from a copy of a real one – never with live data.

  1. Choose the file: nubuilder4.sql of a nuBuilder Forte folder next to nuBuilder Next, a .sql, .sql.gz or .zip copied into _install/ or _update/, or an upload. Either nuBuilder's own nubuilder4.sql (any 4.x – it is brought to 4.9 like in the installer) or a complete dump of a nuBuilder database with the application's tables (e.g. from phpMyAdmin or mysqldump).
  2. Check file reads and checks it – nothing changes yet. As in the installer only plain statements are allowed: CREATE / DROP / ALTER TABLE, INSERT with literal values, SET, LOCK TABLES and nuBuilder 4.5's views; refused are other databases (USE), users and rights, files (INTO OUTFILE, LOAD DATA), triggers, routines, events and DEFINER. The page shows what the file creates (tables, of them the application's, forms, users) and lists every table that would be deleted.
  3. Options: Back up the whole database first (ticked; the backup is under Update → Backups and can be loaded there) and Install the sample application afterwards (see Sample data – the sample users get random passwords).
  4. Type the database name to confirm and Delete all tables and import (the password must have been confirmed recently).

Afterwards the database counts as set up by nuBuilder Next (not as an existing nuBuilder database, so nothing is blocked), with the security defaults of a new installation (records only through the form's list, read-only and hidden fields never saved from the browser). You stay signed in; Open the setup wizard sets up the rest (Installation). nuconfig.php – the connection and the globeadmin – files, library packs, custom pages and backups are not touched. The reset is written to the log (database_reset).

On the command line (also only with $nuConfigDevMode = true):

php cron.php reset --sql=/path/nubuilder4.sql --check          # check only, list what would be deleted
php cron.php reset --sql=/path/dump.sql.gz --backup --sample --yes

Without --yes nothing is deleted. Exit code: 0 = done / checked, 1 = failed, 2 = wrong call or developer mode off.
