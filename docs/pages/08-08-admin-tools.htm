Admin tools and system status

Advanced System status, phpMyAdmin, Adminer, the File Manager and backups.

For: Administrators (globeadmin, admin roles)

The admin tools are tiles of the start page. System status (tile, user menu, index.php?p=vendor) shows what needs a look: the time zone when only the server's default applies, a missing database tool (with the folder to copy it to), tables that are not InnoDB (Storage engine) and the Demo mode status (demo users, warnings, forms that allow saving, procedures with Demo access). The tile's badge counts these points.

User menu → Database – phpMyAdmin / Database – Adminer / File Manager open the tools in a new tab (phpMyAdmin: MySQL / MariaDB only; the File Manager works with every database). When one is not installed yet, index.php?p=vendor (System status) shows a card with the folder to copy it to (see Files you copy yourself).

  • nuBuilder Next signs you in the way nuBuilder Forte (4.x) does: it writes a session row for you into zzzzsys_session and sets the cookie nu_PMA, which phpMyAdmin's config file checks. The cookie is HttpOnly, SameSite=Strict, Secure on HTTPS and only sent to the tool's folder (e.g. /nunext/vendor/packs/nudb-5.2.3/), not to other applications on the domain. The row is removed at logout, when the session is ended on Logged-in users and after the globeadmin session timeout.
  • phpMyAdmin's config.inc.php (in its pack): phpMyAdmin logs in with the database account of nuconfig.php, so its cookie check is the gate too. The hardened version adds the same age check, accepts only globeadmin sessions (strict), shows no database details, sets blowfish_secret (derived from nuconfig.php), drops nuBuilder Forte's nuConfigDBPasswordBlank cookie and turns off the version check and error reports to phpmyadmin.net. $nuPmaNunextOnly = true; accepts only logins made by nuBuilder Next.
  • The tool login lives as long as your nuBuilder Next session: it ends when you sign out, when your session times out or when another globeadmin ends your session.
  • Database: phpMyAdmin or Adminer. Both are optional and not part of the package; either or both can be installed. $nuConfigPrimaryDatabaseManagement ("phpMyAdmin" / "Adminer", nuconfig.php or Settings) chooses the one the Database buttons open – start page tile, form ⋮ menu (Ctrl+Shift+E); not set: phpMyAdmin when installed, else Adminer. With both, the ▾ next to the tile / card and the user menu offer the other one. In the ▾ menu the star marks the default; clicking the empty star of the other tool makes it the default – saved in nuconfig.php (or, with $nuConfigSettingsFromDB, in the Settings table; the Settings row is updated in both cases).
  • Adminer: install its library pack – or copy adminer.php (or adminer-<version>.php; 5.x or 6.x recommended – 4.8.1 works but writes PHP 8 warnings; tested with 4.8.1, 5.4–5.5 and 6.0–6.1) from adminer.org to third_party/adminer/. It works with MySQL / MariaDB and SQL Server and never opens directly (the folder gets a deny-all .htaccess – on nginx block it yourself; the Security check tests it): dbadmin.php checks the same session row as phpMyAdmin (cookie nu_ADM, only for dbadmin.php, globeadmin, activity within the session timeout) and then logs Adminer in with the database account of nuconfig.php – no password typed, no other server or account possible, no "permanent login". Adminer's Logout ends the access; open it again from nuBuilder Next. The Security check lists its version. Copy the file unchanged (FTP: binary mode): a copy with Windows line endings (FTP text mode, a Windows editor, git autocrlf) breaks Adminer's packed texts – every text shows as a number and its scripts fail. dbadmin.php then uses a repaired copy (.nunext-lf-…php next to it) and the Security check reports it. Adminer lets browsers keep its scripts for a year (same URL for the same version); after such a repair or a new copy, reload once with Ctrl+F5 (or clear the site data) if scripts still fail. Adminer 6's service worker (an offline copy of its files in the browser) is replaced by dbadmin.php with one that removes that copy and keeps nothing.
  • Adminer designs: put adminer.css (and with Adminer 5 / 6 also adminer-dark.css) from adminer.org next to adminer.php in third_party/adminer/. dbadmin.php serves them itself (the folder stays blocked for direct access).
  • In form code, nuVendorLogin('PMA') opens phpMyAdmin with the form's table, nuVendorLogin('ADM') Adminer, nuVendorLogin('DB') the primary database tool, nuVendorLogin('TFM') the File Manager.
  • Opening phpMyAdmin asks for the password again when it was last entered more than 15 minutes ago (Security check).

File Manager (nuFiles)

The File Manager is nuFiles, a page form that comes with nuBuilder Next (apps/nufiles/, updated with every release; an own copy in custom/pages/nufiles/ takes precedence) – Tiny File Manager is gone: the update deletes its library packs and the copy in third_party/tinyfilemanager/ of nuBuilder Next (never nuBuilder Forte's own copy); a copy it cannot delete is red in the Security check. nuFiles has no login of its own: it runs on the nuBuilder Next session, access levels, permission items and CSRF protection.

  • Set up once: the first click on File Manager (start page tile, user menu, form ⋮ menu, nuVendorLogin('TFM') – all open index.php?p=filemanager) offers the globeadmin Set up the File Manager. It creates the page form nufiles with two folders (shares): Uploads – the folder the upload procedure stores files in (nu_uploads/, see uploads) – and Web root (code), the globeadmin only, without .git and nuconfig.php.
  • Who sees it: the entries need the admin role right File Manager (or the globeadmin); the page itself, like every form, the form's access levels – the globeadmin always. Which folders and actions a user gets comes from the grants of the shares (permission items or access level codes, rights view / upload / mkdir / edit / rename / copy / delete / zip).
  • Settings: form builder → the form nufiles → Settings (JSON): shares, limits, recycle bin days, versions kept – the full list is in apps/nufiles/README.md. Code shares ("type": "code") are for the globeadmin only and ask for the password again when it was last entered more than reauth_minutes ago (setting "reauth": "code" – every access, also reading; "code_write" only changes).
  • Data: recycle bin, older versions and upload parts are kept in custom/pages/nufiles/_data/ (closed by custom/.htaccess; nginx: the custom/ rule of the web server rules); the setting data_dir moves it, e.g. outside the web root. The log of all changes is the table nufiles_log (created on first use). An update replaces the page's files but never its settings or _data/ – changes you make to the files themselves are overwritten.
  • Recycle bin entries older than trash_days are purged when the page is opened (at most once an hour).
