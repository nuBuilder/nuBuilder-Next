Databases: MySQL, MariaDB and SQL Server

Advanced Which databases nuBuilder Next runs on and what differs between them.

For: Administrators (globeadmin, admin roles)

nuBuilder Next talks to the database through one thin PDO layer (NuDB) that hides the differences between the supported systems. The database type is set with $nuConfigDBType in nuconfig.php.

Note: SQL Server support is young: the installation, the sample application and the lists were tried on a real SQL Server Express; much else was only checked with simulated data so far.

SQL Server Express (named instance)

SQL Server Express installs as a named instance (PC\SQLEXPRESS) without TCP/IP. nuBuilder Next itself connects with that name, but Adminer needs a host and a port. Give the instance a fixed port:

  1. SQL Server Configuration Manager → SQL Server Network Configuration → Protocols for SQLEXPRESS → TCP/IP: Enabled.
  2. Under IP Addresses → IPAll set TCP Port to e.g. 1433 and clear TCP Dynamic Ports.
  3. Restart the SQL Server service.
  4. In nuconfig.php set $nuConfigDBPort = 1433; (the host may stay PC\SQLEXPRESS, or just PC).

The PHP extension pdo_sqlsrv and Microsoft's ODBC Driver 17 or 18 for SQL Server must be installed on the web server; the installer offers SQL Server only then.

What differs on SQL Server

  • Your SQL: browse SQL, procedures and reports run as written, so they must be valid for the database in use. In PHP, nuMSSQL() tells which one it is.
  • Update checks: before an update, column types are compared on MySQL / MariaDB only; on SQL Server only missing columns are found.
  • App cloner and backups: source and target are always the same kind of database. On SQL Server the export uses collations instead of character sets, INSERT only, and batches separated by GO – run it with SQL Server Management Studio or sqlcmd; SQL Server Agent jobs are not copied (see App cloner).
  • Database tools: phpMyAdmin works with MySQL / MariaDB only (its pack is not offered on SQL Server); Adminer works with both (see Admin tools and system status).
  • MySQL / MariaDB only: importing a nuBuilder Forte SQL dump (installer and Set up the database), Reset database and phpMyAdmin.
  • Design mode: new tables and columns are created with abstract types (text, long text, int, decimal, date …) that are mapped to each database (core/form/nuddl.php).

MySQL / MariaDB notes

  • Every table should use InnoDB; nuBuilder Next creates all new tables as InnoDB and can convert old MyISAM tables (Storage engine).
  • New tables get the character set and collation of nuBuilder Forte's tables, so joins with them do not fail with "Illegal mix of collations".
