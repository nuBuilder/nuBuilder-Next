Differences and functions not ported

Functions that behave differently from nuBuilder Forte 4.9, and those not ported, with the reason.

For: Administrators (globeadmin, admin roles)

Compared with nuBuilder Forte 4.9. nuBuilder Next implements nuBuilder Forte's PHP functions for hooks and procedures (core/form/nuphp_api.php, core/form/nuphp_compat.php) and its JavaScript functions for form code (assets/js/nu/nucompat.js). This page lists where they behave differently and which nuBuilder Forte (4.x) functions are not ported, and why. Your application's own use of them is shown by the Compatibility check.

nuBuilder Forte 4.9 compatibility report: what is supported

The compatibility analysis of a real nuBuilder Forte 4.9 application (findings C1–C6, M1–M9, N1–N10) is worked off in steps; the Compatibility check (Admin tools → Compatibility check) lists each finding found in the application's code with the version that supports it.

Findings What
C1–C6, M2, M3 Browse lists built the nuBuilder Forte way: the form's browse SQL stays as it is (qualified columns, aliases, ORDER BY by alias or position, tables without primary key, duplicate column names, hash variables in column expressions); nu_filter_match; nuAddBrowseTitleSelect; multiSelect title filters. Access 9 (sob_all_access_condition) is evaluated when the form is shown and when it is saved, and offered in design mode.
M1, M7, M8, N1–N4 Scripts in HTML objects run after the runtime (before the form's JavaScript); nuAfterSave / nuAfterSaveGlobal on the reloaded form, nuCloseAfterSaveGlobal; nuFORM methods (getProperty, setProperty, subform, data, calc, scrollList, breadcrumbs …; no table schema in the browser); nuSERVERRESPONSE; hooks nuFormatValueCleared(Global) (an unreadable date is cleared, as in nuBuilder Forte), nuSubformFilterOnAddValue(s), nuSubformOnFilterRows, flags nuBrowseNoData / nuBrowseNoSearchResults; nuAddActionCheckbox, nuGetStartingTab, nuSubformFilterArray, nuSubformFilterAddObject, nuDatalistShowAllOnArrowClick, nuSearchablePopupUtils (property and list helpers); values set while loading no longer mark the form as edited. nuCancel and nuSortElement are local variables in nuBuilder Forte, not hooks.
M6 $nuConfigIncludeJS / $nuConfigIncludeCSS on form pages (nuBuilder Next's folder, then nuBuilder Forte's; other hosts allowed by the CSP); $nuConfigIncludePHP also from nuBuilder Forte's folder
M5 File objects with target File System (sob_input_file_target 1) upload with Uppy, a library pack (not in nunext.zip): the object's HTML code with nuBuilder Forte's replacements (#uppy_div#, #this_object_id#, nuInitUppy_<id>, .cssNumber, Uppy.Core), nuUppyCreate / nuUppySetLanguage / nuUppyGetLanguageCodeAndLocale, the endpoint core/nuapi.php sent to ?p=upload (login cookie + CSRF instead of session_id), the procedure's $result and HTTP status as the answer, nuSetUploadError. Executable file names (.php, .phtml, .htaccess …) are refused before the procedure runs; fresh installations get a hardened nu_upload_file_template
– Setup → Include (set_include) used on form pages – its <link> / <script> / <style> elements (nuBuilder Forte 4.9 itself saves the field but did not output it in our tests); page Setup code edits Header / Style / Include
– Browse search with nuBuilder Forte's syntax: "phrases" and -word / -"phrase" exclusions (before: words only, a minus was searched literally; an empty column counts as not containing an excluded word – nuBuilder Forte drops such rows); search words highlighted after loading (nuHighlightSearch as in nuBuilder Forte, only in searched columns, all occurrences, accent-insensitive). Difference: marks are <mark class="nuHighlight"> – nuBuilder Forte's <span class="nuBrowseSearch"> would clash with the search form's class here; own CSS for highlighting uses mark.nuHighlight or the variable --nu-highlight.

Not ported – and why

These are almost all internals of nuBuilder Forte's own client (rendering, designers, Ajax, breadcrumbs) or server (save/load, login, reports, update). Form code normally does not call them. Unsupported public functions that still exist as placeholders write a console warning instead of failing.
