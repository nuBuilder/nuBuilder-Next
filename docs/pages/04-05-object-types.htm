Object types

Every object a form can hold, and run objects.

For: Users with rights on: nuform

Input (text, date, number, checkbox, button, file, HTML5 types, masks), select (list or SQL, searchable, multiple), text area, WYSIWYG editor (TinyMCE), display, calculation, lookup, sub-form (grid or form), content box, HTML, chart, word, image, run (button or iframe). A WYSIWYG editor that is the lowest object of its tab (e.g. the notes form) takes the free height of the window – 250 to 800 px, also less than designed – so the legend below the form (required / unique) stays visible.

A display object shows the first value of its Display SQL – or, when a Display procedure is chosen, what that procedure echoes (as in nuBuilder; the procedure gets the form's hash variables and #OBJECT_ID#). nuRefreshDisplayObject runs either again with the current values. A run object with method iframe shows a form – or the output of a procedure, run when the form opens.

File uploads to the server (Uppy): a file input has a File target – Database stores the file in the record (JSON, as before), File System uploads files into a folder on the server with Uppy, as nuBuilder 4.9 does. Uppy is a library pack: install it under Update → Libraries (a form that needs it shows the globeadmin a notice while it is missing). Choosing File System in the builder fills the object's HTML with nuBuilder's template (code snippet nu_upload_file_uppy_code_template): a drop area that sends every file to the procedure named in its setMeta – nu_upload_file_template, which decides the folder ($targetDirectory; nu_uploads/ next to the web root, or – where that cannot be created – nu_uploads/ inside it with a deny-all .htaccess, so uploaded files are never downloadable by URL), the maximum size and the allowed types, and answers with $result. Copy it under another code to change those for one object, and name the copy in the HTML. Templates written for nuBuilder run unchanged: nuUppyCreate() sends their endpoint core/nuapi.php to nuBuilder Next's upload address with the login and the CSRF token of the page (nuBuilder's session_id is not needed), and the dashboard follows dark mode. Details:

  • The upload runs the procedure with the user's procedure rights (nuBuilder's template is global) and the hash variables of the form and record (#RECORD_ID#, user …); demo visitors cannot upload. Every upload is logged (File uploaded / File upload refused).
  • File names a web server could run or obey – .php, .phtml, .phar, .htaccess, .user.ini … also inside a name like x.php.pdf – are refused before any procedure runs, also with nuBuilder's own template.
  • New installations (and databases without the rows) get nu_upload_file_template in a hardened version: the extension must fit the content type, no HTML, JavaScript, SVG or XML, and an existing file is never overwritten (name-1.pdf). Files go to nu_uploads/ outside the web root (see above), and the answer names only the file, never the server path. The update replaces an unchanged copy of nuBuilder 4.9's template or of the earlier hardened one by this version (step 0022); an edited procedure is kept – the Security check marks it red while it still stores files in the web root. On nginx add location ^~ /nu_uploads/ { deny all; } when the folder had to go inside the web root.
  • Nothing of the object is saved with the record; nuOnFileUploadComplete('FS', objectId, result, message), a function you define, is called after the uploads (nuBuilder's template). nuBuilder's template shows only Error uploading file(s). for a refused file – the reason is in the log.

ApexCharts: as in nuBuilder, set $nuConfigIncludeApexCharts = true (nuconfig.php or Settings) and use new ApexCharts(element, options).render() in the form's JavaScript or in an HTML object. nuBuilder Next bundles ApexCharts 4.4.0 and loads it on form pages only while the setting is on; a form that uses it while it is off shows the globeadmin a Switch on button. nuChart and chart objects use Google Charts, as in nuBuilder.

Chart (as in nuBuilder): chart type (pie, line, bars vertical or horizontal, each bar type also stacked), JavaScript array – the name of an array set in the form's JavaScript or with nuAddJavascript(), or the array itself, first row = column titles: [['Month', 'Sales'], ['Jan', 10], …] – title and the two axis labels (hash variables allowed). Drawn with Google Charts (needs internet access to www.gstatic.com); see Charts.

Access 0–4 and validation (none / required / unique / required and unique) work as in nuBuilder and are checked on the server. Access 9 – condition (as nuBuilder 4.9): the object's access condition SQL (with the form's hash variables, e.g. SELECT IF('#ACCESS_LEVEL_CODE#' = 'HR', 0, 2)) runs when the form opens; the value of its single row is the access (0 editable, 1 read only, 2 hidden, 3 / 4 as above; no row or several rows = 0). A field the condition makes read only or hidden is never taken from the browser when saving; a condition that fails hides the field.

Browse lists (as nuBuilder): of the browse SQL, FROM, WHERE, GROUP BY and HAVING are kept and the field list is replaced by the primary key and the list's columns – columns may use table names or aliases (customer.name, c.name) and AS aliases, joins may have columns with the same name, and the SQL need not select the primary key. Its ORDER BY is the list's default order (also by an alias or a column number). nuBuilder 4.9's nu_filter_match('column', '<browse id>'[, 'empty value']) works with nuAddBrowseFilter(…).nuSearchablePopup({items, multiSelect: true}) (a list of check boxes) and nuAddBrowseTitleSelect(column, options) sets #nuBrowseTitle<n>_select#. A SQL with UNION or WITH is used as a whole, as before.

Form JavaScript as in nuBuilder 4.9: <script> inside an HTML object runs after jQuery and the nu… functions are loaded, in page order and before the form's own JavaScript (a script with src is loaded first; other script types such as templates stay untouched). nuAfterSave() and nuAfterSaveGlobal() run on the reloaded form after nuOnLoad – nuRecordId() is the saved record; with Save & Close they run before going back, and nuCloseAfterSaveGlobal() returning false keeps the form open. Values set while the form loads (nuSetValue in nuOnLoad …) do not mark it as edited, but are saved with the next save. nuFORM has nuBuilder's methods (getProperty, setProperty, subform, data, calc, scrollList, breadcrumbs …; the table schema is not sent to the browser, so getTables() is empty) and nuSERVERRESPONSE holds the form's properties. A date field that does not hold a real date is cleared when it is left, as in nuBuilder (hooks nuFormatValueCleared / nuFormatValueClearedGlobal); sub-form filters call nuSubformFilterOnAddValue(s) and nuSubformOnFilterRows.

Run objects

  • Open form: record ID empty = list, -1 = new record, otherwise that record (#field# placeholders allowed). Filter = search words always applied to the list.
  • Open in: new breadcrumb, current breadcrumb, new browser tab, popup.
  • Run procedure: hidden procedures run in the background, others show their output in a new window.
  • Run report: the PDF opens in a new tab – or the report's launch form first (see Reports).
  • Method button or iframe (for forms, procedures and reports): an iframe shows the result inside the form when it opens – the form, the procedure's output (with the form's hash variables; errors appear inside the iframe) or the report's launch form / PDF. Access rights are the same as for a button.
