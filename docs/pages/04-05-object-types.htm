Object types

Every object a form can hold, and run objects.

For: Users with rights on: nuform

Input (text, date, number, checkbox, button, file, HTML5 types, masks), select (list or SQL, searchable, multiple), text area, WYSIWYG editor (TinyMCE), display, calculation, lookup, sub-form (grid or form), content box, HTML, chart, word, image, run (button or iframe). Links added in a WYSIWYG editor open in a new tab by default (TinyMCE's link_default_target: '_blank'; form code can pass other options to nuInitTinyMCE). A WYSIWYG editor that is the lowest object of its tab (e.g. the notes form) takes the free height of the window – 250 to 800 px, also less than designed – so the legend below the form (required / unique) stays visible.

A display object shows the first value of its Display SQL – or, when a Display procedure is chosen, what that procedure echoes (as in nuBuilder Forte (4.x); the procedure gets the form's hash variables and #OBJECT_ID#). nuRefreshDisplayObject runs either again with the current values. A run object with method iframe shows a form – or the output of a procedure, run when the form opens.

Suggestions (datalist): text, number, e-mail, tel and url inputs can offer suggestions – while the user types, the browser lists the matching values; any other value can still be typed (unlike a select). Fill Suggestions (datalist) in design mode (nuBuilder Forte's Datalist, column sob_input_datalist) with one of:

  • values separated by commas or lines: Red, Green, Blue
  • a JSON list: ["Red","Green","Blue"]
  • a SELECT – its first column gives the values, hash variables work: SELECT DISTINCT cus_country FROM customer ORDER BY 1

Empty means no suggestions. The arrow at the right end of such a field opens the whole list, also when the field already has a value.

File uploads to the server (Uppy): a file input has a File target – Database stores the file in the record (JSON, as in nuBuilder Forte), File System uploads files into a folder on the server with Uppy, as nuBuilder Forte 4.9 does. Uppy is a library pack: install it under Update → Libraries (a form that needs it shows the globeadmin a notice while it is missing). Choosing File System in design mode fills the object's HTML with nuBuilder Forte's template (code snippet nu_upload_file_uppy_code_template): a drop area that sends every file to the procedure named in its setMeta – nu_upload_file_template, which decides the folder ($targetDirectory; nu_uploads/ next to the web root, or – where that cannot be created – nu_uploads/ inside it with a deny-all .htaccess, so uploaded files are never downloadable by URL), the maximum size and the allowed types, and answers with $result. Copy it under another code to change those for one object, and name the copy in the HTML. Templates written for nuBuilder Forte run unchanged: nuUppyCreate() sends their endpoint core/nuapi.php to nuBuilder Next's upload address with the login and the CSRF token of the page (nuBuilder Forte's session_id is not needed), and the dashboard follows dark mode. Details:

  • The upload runs the procedure with the user's procedure rights (nuBuilder Forte's template is global) and the hash variables of the form and record (#RECORD_ID#, user …); demo visitors cannot upload. Every upload is logged (File uploaded / File upload refused).
  • File names a web server could run or obey – .php, .phtml, .phar, .htaccess, .user.ini … also inside a name like x.php.pdf – are refused before any procedure runs, also with nuBuilder Forte's own template.
  • New installations (and databases without the rows) get nu_upload_file_template in a hardened version: the extension must fit the content type, no HTML, JavaScript, SVG or XML, and an existing file is never overwritten (name-1.pdf). Files go to nu_uploads/ outside the web root (see above), and the answer names only the file, never the server path. The update replaces an unchanged copy of nuBuilder Forte 4.9's template or of the earlier hardened one by this version; an edited procedure is kept – the Security check marks it red while it still stores files in the web root. On nginx add location ^~ /nu_uploads/ { deny all; } when the folder had to go inside the web root.
  • Nothing of the object is saved with the record; nuOnFileUploadComplete('FS', objectId, result, message), a function you define, is called after the uploads (nuBuilder Forte's template). nuBuilder Forte's template shows only Error uploading file(s). for a refused file – the reason is in the log.

ApexCharts: as in nuBuilder Forte, set $nuConfigIncludeApexCharts = true (nuconfig.php or Settings) and use new ApexCharts(element, options).render() in the form's JavaScript or in an HTML object. nuBuilder Next bundles ApexCharts (the version is listed under Update → Libraries) and loads it on form pages only while the setting is on; a form that uses it while it is off shows the globeadmin a Switch on button. nuChart and chart objects use Google Charts, as in nuBuilder Forte.

Chart (as in nuBuilder Forte): chart type (pie, line, bars vertical or horizontal, each bar type also stacked), JavaScript array – the name of an array set in the form's JavaScript or with nuAddJavascript(), or the array itself, first row = column titles: [['Month', 'Sales'], ['Jan', 10], …] – title and the two axis labels (hash variables allowed). Drawn with Google Charts (needs internet access to www.gstatic.com); see Charts.

Access 0–4 and validation (none / required / unique / required and unique) work as in nuBuilder Forte and are checked on the server. Access 9 – condition (as nuBuilder Forte 4.9): the object's access condition SQL (with the form's hash variables, e.g. SELECT IF('#ACCESS_LEVEL_CODE#' = 'HR', 0, 2)) runs when the form opens; the value of its single row is the access (0 editable, 1 read only, 2 hidden, 3 / 4 as above; no row or several rows = 0). A field the condition makes read only or hidden is never taken from the browser when saving; a condition that fails hides the field.

Browse lists (as nuBuilder Forte): of the browse SQL, FROM, WHERE, GROUP BY and HAVING are kept and the field list is replaced by the primary key and the list's columns – columns may use table names or aliases (customer.name, c.name) and AS aliases, joins may have columns with the same name, and the SQL need not select the primary key. A column may also name an alias of the browse SQL's field list (SELECT CONCAT(cus_code, ' ', cus_name) AS code_name … with the column code_name): its expression is used, because the field list is replaced – unless a table of the FROM has a real column of that name (it wins, as in nuBuilder Forte) or a source cannot be checked (a sub-query in FROM). nuBuilder Forte itself does not resolve such aliases: for a form that must also work there, write the expression in the column. Its ORDER BY is the list's default order (also by an alias or a column number). nuBuilder Forte 4.9's nu_filter_match('column', '<browse id>'[, 'empty value']) works with nuAddBrowseFilter(…).nuSearchablePopup({items, multiSelect: true}) (a list of check boxes) and nuAddBrowseTitleSelect(column, options) sets #nuBrowseTitle<n>_select#. A SQL with UNION or WITH is used as a whole, as before.

Form JavaScript as in nuBuilder Forte 4.9: <script> inside an HTML object runs after jQuery and the nu… functions are loaded, in page order and before the form's own JavaScript (a script with src is loaded first; other script types such as templates stay untouched). nuAfterSave() and nuAfterSaveGlobal() run on the reloaded form after nuOnLoad – nuRecordId() is the saved record; with Save & Close they run before going back, and nuCloseAfterSaveGlobal() returning false keeps the form open. Values set while the form loads (nuSetValue in nuOnLoad …) do not mark it as edited, but are saved with the next save. nuFORM has nuBuilder Forte's methods (getProperty, setProperty, subform, data, calc, scrollList, breadcrumbs …; the table schema is not sent to the browser, so getTables() is empty) and nuSERVERRESPONSE holds the form's properties. A date field that does not hold a real date is cleared when it is left, as in nuBuilder Forte (hooks nuFormatValueCleared / nuFormatValueClearedGlobal); sub-form filters call nuSubformFilterOnAddValue(s) and nuSubformOnFilterRows.

Run objects

  • Open form: record ID empty = list, -1 = new record, otherwise that record (#field# placeholders allowed). Filter = search words always applied to the list.
  • Open in: new breadcrumb, current breadcrumb, new browser tab, popup. A button that opens a new tab or a popup says so in its tooltip.
  • Label and Icon (as in nuBuilder Forte): the label is HTML – e.g. only <i class="fa fa-table"></i>; an empty label gives an empty button. Icon (also for input buttons and words; nuBuilder Forte's sob_input_icon) is drawn inside, before the label: fa fa-table = a Font Awesome icon, bi-table = a Bootstrap icon, anything else = HTML, left|right = one before and one after the label. A button without visible text gets its target's description as tooltip and name for screen readers.
  • Run procedure: hidden procedures run in the background, others show their output in a new window.
  • Run report: the PDF opens in a new tab – or the report's launch form first (see Reports).
  • Method button or iframe (for forms, procedures and reports): an iframe shows the result inside the form when it opens – the form, the procedure's output (with the form's hash variables; errors appear inside the iframe) or the report's launch form / PDF. Access rights are the same as for a button.

Look of buttons and HTML objects

  • Buttons (input objects of type button and run objects) are solid, as in nuBuilder Forte: the accent colour of Branding with white text (black on a very light accent), rounded corners and a light shadow; a shade darker on mouse over and when pressed, a ring when reached with the keyboard; dark mode included. Run buttons show only their label and their own Icon – no extra symbol for procedures, reports or a new tab.
  • Your own colours: CSS that gives a button its own background (e.g. #my_button { background-color: #4cae4c; } in the form's Style or Setup → Style, as usual for nuBuilder Forte) keeps working. The text stays white – on a light background it turns dark by itself, so it stays readable; a text colour your CSS sets itself is kept. A button with a Bootstrap class of its own (btn-…) keeps that look.
  • One line: the label never wraps. A label too long for its button ends with … and shows in full as tooltip.
  • HTML objects show their content as nuBuilder Forte does, which loads no Bootstrap: in the absolute layout with 13 px text and normal line height, so content made for nuBuilder Forte fits the object's size; headings (h1–h6) bold in the browser's sizes and margins, paragraphs with the browser's margins. Your own CSS – and Bootstrap classes such as fs-6 or m-0 – still win.
  • Buttons made by your code with nuBuilder Forte's class nuActionButton (e.g. $('<button class="nuActionButton">Export</button>'), also on a span) look like nuBuilder Forte's action buttons: 31 px high, a light surface with a thin border, 8 px space on the left, dark mode included. A rule .nuActionButton { … } in Setup → Style, the form's Style or Global code overrides it, as in nuBuilder Forte; .nuActionButtonIcon exists too.
  • The earlier light look (light surface, thin border, dark text) is a template of Global code (start page tile or Settings → Code & includes) → Form CSS: Light form buttons.
