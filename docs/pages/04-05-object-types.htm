Object types

Every object a form can hold, and run objects.

For: Users with rights on: nuform

Input (text, date, number, checkbox, button, file, HTML5 types, masks), select (list or SQL, searchable with Select2 on, multiple – a list box unless Select2 is on, as nuBuilder Forte; a stored value that is not one of the options shows nothing chosen), text area, WYSIWYG editor (TinyMCE), display, calculation, lookup, sub-form (grid or form), content box, HTML, chart, word, image, run (button or iframe). Links added in a WYSIWYG editor open in a new tab by default (TinyMCE's link_default_target: '_blank'; form code can pass other options to nuInitTinyMCE). A WYSIWYG editor that is the lowest object of its tab (e.g. the notes form) takes the free height of the window – 250 to 800 px, also less than designed – so the legend below the form (required / unique) stays visible.

A display object shows the first row of its Display SQL, one column per line (several lines make it a text area) – or, when a Display procedure is chosen, what that procedure echoes (as in nuBuilder Forte (4.x); the procedure gets the form's hash variables and #OBJECT_ID#). nuRefreshDisplayObject runs either again with the current values; the new value counts as a change, and when the form's table has a column with the display object's ID, saving the record writes it there (as nuBuilder Forte does). A run object with method iframe shows a form – or the output of a procedure, run when the form opens. A run object is only shown to users who may open its target: the view right on the form, the report's access levels, or the procedure's access levels (or Global). For others it is left out (an empty hidden element keeps its ID for the form's JavaScript); the globeadmin and users who design forms always see it. Input objects of type button run your own JavaScript, so they are not checked – hide them in the form's code when needed. nuBuilder Forte (4.x) shows every run object and refuses the run itself.

A lookup reads its code and description from the browse SQL of its lookup form, as nuBuilder Forte (4.x) does; when that form has Before Browse code (for example one that builds the list's table with #TABLE_ID#, like the built-in File form), the code runs first. As in nuBuilder Forte, the description of a stored value is read with the FROM part of that SQL only (its WHERE does not hide a saved value), and a typed code that matches no code exactly finds the rows whose code or description contains it.

A run object can also open a URL (run type Open URL in design mode): an https:// or http:// address, or a path of this site such as custom/report.php – other schemes (javascript:, data: …) are refused. Hash variables (#RECORD_ID#, #field# …) are filled in and URL-encoded. As a button it opens in a new tab (default), a popup window or this tab (unsaved changes ask first); as an iframe it shows the page inside the form – the form page allows that host in its Content Security Policy, but the other site must also allow being framed. Everyone who sees the form sees the button (a URL has no rights of its own; the object's access condition can still hide it). The URL is kept in nuBuilder Next's part of the object (sob_all_json), so nuBuilder Forte shows such a button without a target.

Options of a select: the field Options in design mode (column sob_select_sql) takes the formats of nuBuilder Forte:

  • an SQL – the first column is the value, the second the text: SELECT cty_code, cty_name FROM country ORDER BY 2; also WITH …, (SELECT …) UNION … and SQL that starts with -- comment lines
  • a list of value and text: 1|Open|2|Closed – line ends and tabs are removed, so each pair may stand on its own line
  • a JSON list: ["first", "second"] – each entry is value and text; [["1", "Open"], ["2", "Closed"]] gives value and text (nuBuilder Next only)
  • SHOW TABLES or SHOW FULL TABLES WHERE Table_type = "BASE TABLE" – the tables of the database, without those whose name starts with __ (on SQL Server the same list from its catalog)
  • %LANGUAGES% – the language names of nuBuilder Forte (German, French …)

Hash variables work in every format: in SQL they are passed as values, in lists and JSON they are filled in as text (#USER_ID#|Me|0|Everyone). Only what is written there counts – a hash variable that holds SQL does not make a list an SQL. The PHP function nuSelectOptions($sql) reads the same formats. Texts of a list or JSON are translated when the form's language has translations; SQL results are shown as they come.

Options from a procedure: when a select has a Select procedure (nuBuilder Forte 4.9, column sob_select_procedure), the procedure runs while the form is drawn and the list in its $result gives the options – rows [value, text], plain values, or a text in one of the formats above: $result = [['a', 'Apple'], ['b', 'Banana']]; The procedure gets the form's hash variables and #OBJECT_ID#; nuRefreshSelectObject runs it again.

Blank item: a select whose validation is None starts with an empty item; with No Blanks, No Duplicates or both it has none, as nuBuilder Forte 4.9.2 – until something is chosen no option is selected ($('#id').val() is null, nuGetValue() returns an empty text).

Default value by attribute: an attribute value=… in the object's Attributes fills an empty field of a new record (a lookup takes it as the record id), as nuBuilder Forte; a stored record shows its own value.

Suggestions (datalist): text, number, e-mail, tel and url inputs can offer suggestions – while the user types, the browser lists the matching values; any other value can still be typed (unlike a select). Fill Suggestions (datalist) in design mode (nuBuilder Forte's Datalist, column sob_input_datalist) with one of:

  • values separated by commas or lines: Red, Green, Blue
  • a JSON list: ["Red","Green","Blue"]
  • a SELECT – its first column gives the values, hash variables work: SELECT DISTINCT cus_country FROM customer ORDER BY 1

Empty means no suggestions. The arrow at the right end of such a field opens the whole list, also when the field already has a value.

File uploads to the server (Uppy): a file input has a File target – Database stores the file in the record (JSON, as in nuBuilder Forte), File System uploads files into a folder on the server with Uppy, as nuBuilder Forte 4.9 does. Uppy is a library pack: install it under Update → Libraries (a form that needs it shows the globeadmin a notice while it is missing). Choosing File System in design mode fills the object's HTML with nuBuilder Forte's template (code snippet nu_upload_file_uppy_code_template): a drop area that sends every file to the procedure named in its setMeta – nu_upload_file_template, which decides the folder ($targetDirectory; nu_uploads/ next to the web root, or – where that cannot be created – nu_uploads/ inside it with a deny-all .htaccess, so uploaded files are never downloadable by URL), the maximum size and the allowed types, and answers with $result. Copy it under another code to change those for one object, and name the copy in the HTML. Templates written for nuBuilder Forte run unchanged: nuUppyCreate() sends their endpoint core/nuapi.php to nuBuilder Next's upload address with the login and the CSRF token of the page (nuBuilder Forte's session_id is not needed), and the dashboard follows dark mode. Details:

  • The upload runs the procedure with the user's procedure rights (nuBuilder Forte's template is global) and the hash variables of the form and record (#RECORD_ID#, user …); demo visitors cannot upload. Every upload is logged (File uploaded / File upload refused).
  • File names a web server could run or obey – .php, .phtml, .phar, .htaccess, .user.ini … also inside a name like x.php.pdf – are refused before any procedure runs, also with nuBuilder Forte's own template.
  • New installations (and databases without the rows) get nu_upload_file_template in a hardened version: the extension must fit the content type, no HTML, JavaScript, SVG or XML, and an existing file is never overwritten (name-1.pdf). Files go to nu_uploads/ outside the web root (see above), and the answer names only the file, never the server path. The update replaces an unchanged copy of nuBuilder Forte 4.9's template or of the earlier hardened one by this version; an edited procedure is kept – the Security check marks it red while it still stores files in the web root. On nginx add location ^~ /nu_uploads/ { deny all; } when the folder had to go inside the web root.
  • Nothing of the object is saved with the record; nuOnFileUploadComplete('FS', objectId, result, message), a function you define, is called after the uploads (nuBuilder Forte's template). nuBuilder Forte's template shows only Error uploading file(s). for a refused file – the reason is in the log.

ApexCharts: as in nuBuilder Forte, set $nuConfigIncludeApexCharts = true (nuconfig.php or Settings) and use new ApexCharts(element, options).render() in the form's JavaScript or in an HTML object. nuBuilder Next bundles ApexCharts (the version is listed under Update → Libraries) and loads it on form pages only while the setting is on; a form that uses it while it is off shows the globeadmin a Switch on button. nuChart and chart objects use Google Charts, as in nuBuilder Forte; its loader is added to a form page when $nuConfigIncludeGoogleCharts is on or the form's code calls google.charts / google.visualization.

Chart (as in nuBuilder Forte): chart type (pie, line, bars vertical or horizontal, each bar type also stacked), JavaScript array – the name of an array set in the form's JavaScript or with nuAddJavascript(), or the array itself, first row = column titles: [['Month', 'Sales'], ['Jan', 10], …] – title and the two axis labels (hash variables allowed). Drawn with Google Charts (needs internet access to www.gstatic.com); see Charts.

Access 0–4 and validation (none / required / unique / required and unique) work as in nuBuilder Forte and are checked on the server. Access 9 – condition (as nuBuilder Forte 4.9): the object's access condition SQL (with the form's hash variables, e.g. SELECT IF('#ACCESS_LEVEL_CODE#' = 'HR', 0, 2)) – #ACCESS_LEVEL_CODE# is the main access level; for additional levels see Access levels in your code runs when the form opens; the value of its single row is the access (0 editable, 1 read only, 2 hidden, 3 / 4 as above; no row or several rows = 0). A field the condition makes read only or hidden is never taken from the browser when saving; a condition that fails hides the field.

Browse lists (as nuBuilder Forte): of the browse SQL, FROM, WHERE, GROUP BY and HAVING are kept and the field list is replaced by the primary key and the list's columns – columns may use table names or aliases (customer.name, c.name) and AS aliases, joins may have columns with the same name, and the SQL need not select the primary key. A column may also name an alias of the browse SQL's field list (SELECT CONCAT(cus_code, ' ', cus_name) AS code_name … with the column code_name, or inside an expression such as IF(paid = 1, code_name, '')): its expression is used, because the field list is replaced – also in the ORDER BY, GROUP BY and HAVING of the browse SQL – unless a table or sub-query of the FROM has a real column of that name (it wins, as in nuBuilder Forte); a sub-query in FROM gives the names of its own field list. nuBuilder Forte itself does not resolve such aliases: for a form that must also work there, write the expression in the column. Its ORDER BY is the list's default order (also by an alias or a column number). nuBuilder Forte 4.9's nu_filter_match('column', '<browse id>'[, 'empty value']) works with nuAddBrowseFilter(…).nuSearchablePopup({items, multiSelect: true}) (a list of check boxes) and nuAddBrowseTitleSelect(column, options) sets #nuBrowseTitle<n>_select#. A SQL with UNION or WITH is used as a whole, as before.

Form JavaScript as in nuBuilder Forte 4.9: <script> inside an HTML object runs after jQuery and the nu… functions are loaded, in page order and before the form's own JavaScript (a script with src is loaded first; other script types such as templates stay untouched). nuAfterSave() and nuAfterSaveGlobal() run on the reloaded form after nuOnLoad – nuRecordId() is the saved record; with Save & Close they run before going back, and nuCloseAfterSaveGlobal() returning false keeps the form open. Values set while the form loads (nuSetValue in nuOnLoad …) do not mark it as edited, but are saved with the next save. nuFORM has nuBuilder Forte's methods (getProperty, setProperty, subform, data, calc, scrollList, breadcrumbs …; the table schema is not sent to the browser, so getTables() is empty) and nuSERVERRESPONSE holds the form's properties (objects[i].js = the object's events); nuFORM.getProperty() also returns nuBuilder Forte's breadcrumb keys such as tab_start, form_id and record_id, and a cell of a grid sub-form carries the id <row prefix><field>_nucell and the row's data-nu-primary-key. A date field that does not hold a real date is cleared when it is left, as in nuBuilder Forte (hooks nuFormatValueCleared / nuFormatValueClearedGlobal); sub-form filters (nuSubformAddFilter) list and compare a lookup column by its code and a select by its option text, and call nuSubformFilterOnAddValue(s) and nuSubformOnFilterRows.

Run objects

  • Open form: record ID empty = list, -1 = new record, otherwise that record (#field# placeholders allowed). Filter = search words always applied to the list.
  • Open in: new breadcrumb, current breadcrumb, new browser tab, popup. A button that opens a new tab or a popup says so in its tooltip.
  • Label and Icon (as in nuBuilder Forte): the label is HTML – e.g. only <i class="fa fa-table"></i>; an empty label gives an empty button. Icon (also for input buttons and words; nuBuilder Forte's sob_input_icon) is drawn inside, before the label: fa fa-table = a Font Awesome icon, bi-table = a Bootstrap icon, anything else = HTML, left|right = one before and one after the label. A button without visible text gets its target's description as tooltip and name for screen readers.
  • Run procedure: hidden procedures run in the background, others show their output in a new window.
  • Run report: the PDF opens in a new tab – or the report's launch form first (see Reports).
  • Method button or iframe (for forms, procedures and reports): an iframe shows the result inside the form when it opens – the form, the procedure's output (with the form's hash variables; errors appear inside the iframe) or the report's launch form / PDF. Access rights are the same as for a button.

Look of buttons and HTML objects

  • Buttons (input objects of type button and run objects) are solid, as in nuBuilder Forte: the accent colour of Branding with white text (black on a very light accent), rounded corners and a light shadow; a shade darker on mouse over and when pressed, a ring when reached with the keyboard; dark mode included. Run buttons show only their label and their own Icon – no extra symbol for procedures, reports or a new tab.
  • Your own colours: CSS that gives a button its own background (e.g. #my_button { background-color: #4cae4c; } in the form's Style or Setup → Style, as usual for nuBuilder Forte) keeps working. The text stays white – on a light background it turns dark by itself, so it stays readable; a text colour your CSS sets itself is kept. A button with a Bootstrap class of its own (btn-…) keeps that look.
  • One line: the label never wraps. A label too long for its button ends with … and shows in full as tooltip.
  • HTML objects show their content as nuBuilder Forte does, which loads no Bootstrap: in the absolute layout with 13 px text and normal line height, so content made for nuBuilder Forte fits the object's size; headings (h1–h6) bold in the browser's sizes and margins, paragraphs with the browser's margins. Your own CSS – and Bootstrap classes such as fs-6 or m-0 – still win. Elements an object leaves open (an <iframe> without its end tag, an unclosed <div> or comment) are closed at the end of the object, so they cannot swallow the objects after it.
  • Buttons made by your code with nuBuilder Forte's class nuActionButton (e.g. $('<button class="nuActionButton">Export</button>'), also on a span) look like nuBuilder Forte's action buttons: 31 px high, a light surface with a thin border, 8 px space on the left, dark mode included. A rule .nuActionButton { … } in Setup → Style, the form's Style or Global code overrides it, as in nuBuilder Forte; .nuActionButtonIcon exists too.
  • The earlier light look (light surface, thin border, dark text) is a template of Global code (start page tile or Settings → Code & includes) → Form CSS: Light form buttons.
