Validation and business rules

Advanced Required and unique fields, masks, and rules written in Before Save.

For: Users with rights on: nuform

Built-in checks

Set per object in design mode (nuBuilder Forte's Validation of an object). They are checked on the server for every save, also when the browser's checks are bypassed:

CheckMarker after the labelMessage
Required (no blanks)*"… cannot be blank."
Unique (no duplicates in the table)key (after the * when also required)"… must be unique – this value already exists."
Text mask complete (format with the option "complete")–names the field (and the row of a sub-form)

Fields whose posted value is not saved (field data access; read only and hidden while the Security setting is on – see the rule) are not checked from the post. The markers can be switched off with $nuConfigValidationMarkers.

Your own rules

  • In the browser: nuBeforeSave() returning false – quick feedback, but not a protection.
  • On the server: in Before Save read the posted values ('#field#' or nuGetNuDataValue()) and stop with nuDisplayError('message', 'field') – the field is highlighted. For rules that apply to every form, use the global hook nu_before_save.
  • Who may change what belongs into rights, not code: access levels, field data access, permission items (nuUserHasPermission()).

Required and unique fields of nuBuilder Next's pages

The record pages of nuBuilder Next itself check these fields on the server; the label shows a red * for required and a key for unique (the tooltip of the key explains it). Unique values are compared as stored; the user code ignores spaces at the ends and upper / lower case. Values that must be unique only together with others (e-mail templates, translations) carry no key.
