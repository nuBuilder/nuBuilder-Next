Translations

Your forms' texts in other languages.

For: Users with rights on: nutranslate

Forms → Tools → Translations: texts of your forms in other languages (nuBuilder Forte's table zzzzsys_translate – created by the installer, and on older installations by an update step). They work as in nuBuilder Forte (4.x):

  • A text is translated when English matches it exactly – object labels, button texts, tab titles, list column titles, form titles, and nuTranslate() in PHP and JavaScript.
  • The reader's language is the language of that user (the globeadmin: the language in nuBuilder Forte's setup). If it is empty, it is English, as in nuBuilder Forte. English means no translation.
  • A text starting with | is never translated (the | is not shown).
  • nuBuilder Forte's own translations (nuBuilder Forte badge) cannot be changed – Override creates your own translation, which wins.
  • The texts of fixed select options (a|Apple|b|Banana, lines or a JSON list) are translated too – only the shown text, the stored value stays. nuBuilder Forte shows them as entered. Options from SQL are data and are not translated.
  • The Missing tab lists the texts of your forms that have no translation in a language yet, with where they are used; Translate opens a pre-filled new translation. Besides labels, tab titles, list column titles and form titles it finds the texts of fixed select options and the fixed texts of nuTranslate('…') calls in the form's code – its JavaScript, object events, HTML objects and its PHP hooks (a call with a value, such as nuTranslate(text), cannot be found).

One form in every language

Choose a form on the Missing tab (or in design mode: form settings → Tools → Translations, which also shows how many are missing). The table then lists every text of the form and its sub-forms with its kind (label, tab, list column, choice, code) and a column per language – the translation, or to add it. The languages are the installed interface languages, the languages that already have translations and the languages of your users.

Translate with AI – with any AI chat (Claude, ChatGPT …); nothing is sent from nuBuilder Next:

  1. Tick the languages (those with gaps are ticked) and whether only texts without a translation go in, then click Copy prompt. The prompt is in English: rules for the AI (keep placeholders such as %s, hash variables and HTML, use the English text unchanged as the key, answer with JSON only), the texts as JSON with their context and the translations there already are, so the wording stays consistent.
  2. Paste the prompt into the chat, then paste the AI's whole answer into The AI's answer – text around the JSON or ``` fences do not matter – and click Check.
  3. The preview shows each translation as New, Changes (an own translation exists and is different), Unchanged or Skipped (not a text of this form, not one of the languages, empty or too long); a warning marks a translation whose placeholders or hash variables differ from the English text. Untick what you do not want and click Save selected.

Saving needs the add right (new translations) or the save right (changed ones) on the translations; nuBuilder Forte's own translations are never changed – a translation of yours overrides them. The answer format is {"format": "nunext-translate-1", "translations": {"German": {"Customer": "Kunde"}}}, so a translation can also be written or edited by hand and pasted.

  • The design mode always shows and saves the original (English) texts.
