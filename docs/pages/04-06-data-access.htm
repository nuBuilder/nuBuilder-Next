Data access: fields and list columns per user

Advanced Server-side rules for who sees and changes each field and list column.

For: Users with rights on: nuform

Design mode → Tools → Data access (button next to Change with AI; index.php?p=dataaccess&f=<form id>, right: nuform – view to look, save to change) sets who may see and change each field of a form and its sub-forms, and who sees each column of its list. The server enforces it – unlike nuBuilder Forte's read only and hidden, which only change the display.

  • Rules: each field gets a default (Everyone) and rules for an access level, a user, a permission item, a team or a department. The most specific matching rule wins – user > permission item > team / department > access level > everyone; two rules of the same rank: the more open mode. A rule may have a condition (SQL with the form's hash variables, as nuBuilder Forte's access condition): it counts only when the first value is 1, an error never counts. A field without rules keeps nuBuilder Forte's access (0–4, 9) exactly as before.
  • Masks: last:4 (default), first:2, email (a•••@example.com), text:(hidden).
  • Where it is enforced: the edit form (also sub-form rows – a withheld sub-form field has no column), HTML objects and the breadcrumb title (hash variables of withheld / masked fields are empty / masked there), lookups and display objects refreshed from the page, save (main record and sub-form rows; posted values the user may not write are dropped and noted in Debug results), validation, clone (protected, masked and withheld values come from the database, never from the browser), the list (a column showing a withheld field is not selected at all, a masked one shows the mask and cannot be searched, filtered or sorted), list exports and the record history. Hooks, procedures and reports run on the server and read the real values – use nuFieldAccessMode() / nuFieldAccessAllowed() there.
  • List columns (tab List columns): Visible / Hidden by default and rules per subject (a tie hides). A hidden column is removed before the list query is built: it is not read, searched, filtered, sorted or exported; a sort on it falls back to the default order. Stored in the column's sbr_json, so it travels with the form.
  • By access level: all fields and columns of the form for one access level at once. Preview as user: what a user gets and which rule decided it; a required field that user cannot fill is flagged.
  • The globeadmin keeps nuBuilder Forte's access and sees every column; the Security setting Apply data access rules to the globeadmin applies the rules to him too (for testing). Act as user applies the rules of that user.
  • nuBuilder Forte 4.9 on the same database ignores the rules. A new default mode sets the object's access to the nearest nuBuilder Forte value (Protected, Insert only, Update only → read only; Masked, Withheld → hidden for users), but nuBuilder Forte still sends those values to the browser. Rules are kept in zzzzsys_nunext_object_access; rules of deleted objects are removed by the housekeeping. They are not copied with a cloned form or by the App cloner yet.
