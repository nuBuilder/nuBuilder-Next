E-mail

SMTP settings, OAuth 2, the e-mail log and templates.

For: Users with rights on: nuemaillog, nuemailtemplate, nusetup

Settings and test mail

Menu E-mail → Settings: SMTP server, port, user, password, sender. These are the same settings nuBuilder Forte (4.x) uses. The password is never shown again – leave the field empty to keep it.

  • Port 465 uses SSL/TLS, 587 STARTTLS; on other ports Use SSL selects SSL/TLS (the same hint is behind the next to Use SSL).
  • Authentication method: Automatic lets PHPMailer take the first method the server offers, in the order CRAM-MD5, LOGIN, PLAIN, XOAUTH2. Some servers offer a method and then refuse it (often CRAM-MD5) – choose LOGIN or PLAIN for them (PHPMailer's AuthType). OAuth 2 (XOAUTH2) logs in with a Google or Microsoft 365 account instead of a password – see OAuth 2. Stored in nuBuilder Next's own settings (nuBuilder Forte's zzzzsys_setup has no field for it) and used for everything nuBuilder Next sends, also with the SMTP settings of nuconfig.php; nuBuilder Forte itself always uses automatic.
  • Test mail sends a message and shows the conversation with the server (passwords hidden) – useful when mails don't arrive. With authentication it also shows the methods the server offers and the one used; when sending fails with Automatic it suggests another method, and it warns when the chosen method is not offered. The To address is remembered in your browser for the next test.
  • Check connection (tab Test, also next to Save in the settings) tests the saved settings without sending anything: it connects to the server, switches on encryption (SSL/TLS or STARTTLS), logs in and asks whether the sender address is accepted (MAIL FROM), then resets and quits – no recipient is given, so no mail goes out. Each step shows or with the server's answer; the conversation (passwords hidden) is below. Some servers check the sender only when a recipient is given – a test mail is still the final proof. The check is logged (email_check / email_check_failed) and needs the right on nuBuilder Forte's setup.
  • nuBuilder Forte writes 1 into every field when its settings are reset; nuBuilder Next treats 1 as "not set".
  • Copy settings puts the settings shown (server, port, user, sender, authentication method, switches) as JSON on the clipboard – without the password. Paste settings fills the fields from such a JSON, e.g. from another installation (nuBuilder Forte's set_smtp_… names work too); a password in it is ignored and the stored one stays. Pasted values are only saved with Save. Where the browser may not read the clipboard (http without TLS, permission refused) a dialog opens to paste the text.
  • Active configuration shows what is really used for sending (source, server, encryption, authentication, sender) and the PHPMailer version; hover or focus the next to PHPMailer for the folder it is loaded from – or, when it is missing, the places that were searched.

OAuth 2 (Google, Microsoft 365)

The SMTP login can use OAuth 2 (XOAUTH2) instead of a password – Google and Microsoft are switching off password logins for SMTP. Choose Authentication method → OAuth 2 (XOAUTH2) in E-mail → Settings; a block for the provider appears. It applies to every mail of nuBuilder Next (form code nuEmail(), e-mail templates, notifications, password links, test mail, Check connection). nuBuilder Forte itself keeps sending with its own settings (password).

  • Provider: Google (Gmail, Workspace), Microsoft 365 / Outlook or Other provider (any OAuth 2 service: its authorisation address, token address and scope). Use smtp.gmail.com:587 / Use smtp.office365.com:587 fills server and port.
  • Client ID and client secret come from the app you register at the provider (below). The secret is never shown again – leave the field empty to keep it.
  • Redirect URI: https://<your nuBuilder Next>/oauth.php, shown on the page with a copy button – enter it at the provider exactly like that. It is built from $nuConfigBaseURL when set, otherwise from the address in the browser.
  • Save and connect account saves the settings, opens the provider's sign-in page and comes back with the permission; the block then shows Connected: <mailbox>. nuBuilder Next keeps the refresh token and fetches a new access token (valid about an hour) by itself whenever it needs one. Disconnect forgets the mailbox; another provider, client ID or tenant does that too.
  • User name in the SMTP settings: the mailbox to send from (empty = the connected one). Use the same address as From address – Google and Microsoft refuse or rewrite other senders unless the mailbox may send as them.
  • Client secret and tokens are stored in nuBuilder Next's settings table, encrypted with $nuConfigSecretKey – without a key they are stored as they are and the block shows a warning. They are not part of Copy settings, and the server conversation of the test mail shows AUTH XOAUTH2 ********. Connecting, failures and disconnecting are logged.

Google (Gmail or Google Workspace) – in the Google Cloud console:

  1. Create or pick a project. APIs & Services → OAuth consent screen: user type Internal (Workspace, only your organisation) or External; add the scope https://mail.google.com/. While an external app is in Testing, add the mailbox as a test user – and note that Google then lets the permission expire after 7 days: publish the app (In production) for lasting use.
  2. Credentials → Create credentials → OAuth client ID, type Web application; under Authorised redirect URIs add the redirect URI from nuBuilder Next. Copy the client ID and secret.
  3. In nuBuilder Next: method OAuth 2, provider Google, Use smtp.gmail.com:587, client ID and secret, user name and from address = the Gmail address, then Save and connect account and allow access with that account.

Microsoft 365 – in the Microsoft Entra admin center (Azure):

  1. App registrations → New registration: a name, the account types you need, redirect URI of type Web = the redirect URI from nuBuilder Next. Note the Application (client) ID and the Directory (tenant) ID.
  2. Certificates & secrets → New client secret: copy its Value (shown only once).
  3. API permissions → Add a permission → APIs my organization uses → Office 365 Exchange Online → Delegated → SMTP.Send, plus offline_access, openid and email (Microsoft Graph); Grant admin consent.
  4. The mailbox needs Authenticated SMTP switched on (Microsoft 365 admin center → user → Mail → Manage email apps, or Set-CASMailbox -Identity <mailbox> -SmtpClientAuthenticationDisabled $false).
  5. In nuBuilder Next: method OAuth 2, provider Microsoft 365, tenant = the directory (tenant) ID or your domain (common only for apps that accept any account), Use smtp.office365.com:587, client ID and secret, user name and from address = the mailbox, then Save and connect account.

If it fails: Check connection shows the provider's message at the login step (e.g. invalid_client = wrong ID or secret, invalid_grant = the permission was withdrawn or expired → connect again). redirect_uri_mismatch on the sign-in page means the redirect URI at the provider differs from the one shown – including http/https and the folder. Google sends a refresh token only on the first consent: if it says “no refresh token”, remove the app's access in the Google account (Security → Third-party access) and connect again.

E-mail log

All mails sent by nuBuilder Forte or nuBuilder Next, with status and error. Click a row for the details and the message. A single entry is deleted with the at the end of its row or with Delete in its detail (after a confirmation; the list keeps its page, search and filters); old entries all at once with Delete entries older than … days. Deleting needs the delete right of nuBuilder Forte's form nuemaillog and is logged. Login codes and password links are logged without the message text.

E-mail templates

Templates with subject, body, recipients, group and language. Choose a form: its fields are listed and inserted as placeholders – into the body with their label, <b>Field Id: </b>#field_id#, into subject and recipients as #field_id# – which are replaced with the record's values when the mail is sent. Code + group + language must be unique. Preview and Test use a record you choose – only of a form you have rights on; passwords, keys and password hashes of the record show as •••. Test needs the right to change templates and sends at most 10 e-mails per hour and user. Templates shipped with nuBuilder Forte (marked template) are read-only – they can be viewed, previewed and tested, but not changed or deleted. Clone makes an editable copy and removes the suffix _template from the code (e.g. nu_send_welcome_email_template → nu_send_welcome_email, the template of the welcome e-mail).

Code, group, category, language, description and the recipients (To, Cc, Bcc) fold away with a click on Template and recipients: the line then shows code · description · To, so subject and body get the room. Your browser remembers whether it was folded; it opens again by itself when one of these fields has an error.
