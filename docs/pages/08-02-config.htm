Configuration (nuconfig.php)

Advanced Every setting of nuconfig.php that nuBuilder Next reads.

For: Administrators (globeadmin, admin roles)

Same file and variable names as nuBuilder. nuBuilder Next reads it on every request. The nuBuilder Next-only settings:

Auto login (nuBuilder's links, wiki page Login): index.php?u=<login name>&p=<hash> logs the user in and opens the start page; add &f=<form id>&r=<record id> to open a form (r empty = list, -1 = new record) or &h=<form id> for another start form. p is never the password: it is a hash shown in the user form (globeadmin, Auto-login link) – HMAC-SHA256 of the stored password hash with $nuConfigSecretKey, so the link stops working when the password changes. The user form offers links that expire (1, 7, 30, 90 days or never – &e= is part of the signed hash) and Revoke links, which ends all links of the user without a password change. Needs $nuConfigAutoLogin = true; not possible for the globeadmin; two-step login, the user's expiry date and the login rate limit apply; the hash is removed from the address bar at once. A link opened while somebody else is logged in asks before it switches the login. Without p the login page opens with the name filled in, and after the login the form opens. Generally, a link opened while logged out leads back to that page after the login.

One-time login link (nuBuilder's Single-User Password Token): index.php?u=<login name or user id>&p=<token> (with &f= / &r= as above) signs the user in once when the token matches LOGIN_TOKEN in the user's sus_json – like nuBuilder without a second factor; afterwards the token is replaced by a new random one, so the same link never works twice (also not for two clicks at the same moment). Ways to get a token:

  • User form (globeadmin) → One-time login link: validity 1 hour, 1 day, 7 days, 30 days or no expiry; Create link shows the link once to copy, the envelope sends it to the user's e-mail address (in the user's language), the red button removes the token.
  • In a procedure: nuCreateLoginToken($userId, $minutes = 0, $formId = '', $recordId = '') returns the link ('' when not possible).
  • REST API: POST /v1/users/{id}/login-link (scope users:login_link, see REST API).
  • Another system writes the token itself, as in nuBuilder's wiki: sus_json → {"LOGIN_TOKEN": "…"}, at least 20 characters; optional "LOGIN_TOKEN_EXPIRES": <Unix time> (nuBuilder Next only – nuBuilder ignores it).

Differences to nuBuilder (all safer, the links stay compatible): exact comparison in constant time, never the globeadmin or an API service user, the user's expiry date and access level apply, wrong tokens count for the login rate limit, every use is logged (Login with via: token), creating, mailing and removing are logged too. Dangerous actions still ask for the password (the session counts as not confirmed). p with 64 hex characters is nuBuilder Next's signed auto-login hash while $nuConfigAutoLogin is on; anything else of 20 characters or more is treated as a token. Switch it off in the Security check (Accept nuBuilder's one-time login tokens); the Security check also shows how many users have a token (stored in plain text, as in nuBuilder) and removes all of them.

Own login page: $nuWelcomeBodyInnerHTML works as in nuBuilder – nuBuilder's HTML can be used as it is (inputs nuusername / nupassword, the submit button). Inline onclick / onsubmit are not run (security policy); nuBuilder Next connects the form itself and adds the security token. style="…" works; image paths core/graphics/… point to nuBuilder's folder. Error messages, "Forgot password?", the language and theme menus stay. nuconfig-sample.php has a commented example.
