Configuration (nuconfig.php)

Advanced The settings of nuconfig.php that matter for nuBuilder Next.

For: Administrators (globeadmin, admin roles)

Same file and variable names as nuBuilder Forte (4.x). nuBuilder Next reads it on every request. The tables list the variables nuBuilder Next reads; Origin says whether a variable comes from nuBuilder Forte (the same meaning there, unless the text says otherwise) or is one nuBuilder Next adds – nuBuilder Forte ignores those. Insert variable in the editor lists them with their defaults.

Security

VariableOriginDefaultMeaning
$nuConfigPasswordMinLengthNext8Minimum length of new passwords
$nuConfigPasswordUpgradeNexttrueRehash md5 passwords to bcrypt at login (false if an old nuBuilder Forte must still read md5)
$nuUseMd5PasswordHashFortefalsenuBuilder Forte's setting (also in Settings): true = new passwords are stored as md5 and never converted – as nuBuilder Forte does, which then accepts md5 only (a bcrypt hash would lock the user out of nuBuilder Forte). md5 logins work regardless of Accept old md5 passwords. Insecure: the Security check shows it in red – switch it off once no nuBuilder Forte needs it (4.5 and later read bcrypt); afterwards md5 passwords become bcrypt at the next login.
$nuConfig2FAAdmin / $nuConfig2FAUserFortefalseTwo-step login for globeadmin / for access levels with "Use two-factor authentication" (authenticator app or e-mail code). The access level form shows whether $nuConfig2FAUser is on; while it is off, the globeadmin can switch it on there (Switch on, or a link to Settings when $nuConfigSettingsFromDB is on).
$nuConfig2FATrustDaysNext30"Remember this device" days (0 = always ask)
$nuConfig2FAIssuerNextnuBuilder NextName in the authenticator app
$nuConfigGlobeadminEmailNextE-mail for globeadmin login codes
$nuConfigSecretKeyNextEncrypts authenticator secrets in the database; key for the HMAC of API secrets and tokens and of auto-login hashes – set a long random value. While it is empty, API clients offers Generate key: a 64-character random key, saved to nuconfig.php (only while empty – a new key would make encrypted 2FA secrets unreadable).
$nuConfigBaseURLNext(detected)The address your users open nuBuilder Next with, e.g. https://www.example.com/nunext (no slash at the end). nuBuilder Next needs it wherever it writes a complete link that is opened somewhere else than the current browser tab: links in e-mails (Forgot password, welcome mail, e-mail templates), the auto-login links in the user form and the REST API addresses (API clients, playground).
Empty: the address is taken from the current page request. That is fine on a simple server, but behind a reverse proxy, in Docker or with several host names it can come out wrong (e.g. http://localhost:8080/nunext), and the link in the e-mail does not open. Forgot password never trusts the visitor's request (the host name could be faked to send a reset link to a foreign site): it uses this setting, otherwise the address the globeadmin last logged in with. Set it on a live server – the Security check warns while it is empty.
$nuConfigTrustProxyNextfalseClient IP from X-Forwarded-For (behind a reverse proxy)

Auto login and own login page

Auto login (nuBuilder Forte's links, wiki page Login): index.php?u=<login name>&p=<hash> logs the user in and opens the start page; add &f=<form id>&r=<record id> to open a form (r empty = list, -1 = new record) or &h=<form id> for another start form. p is never the password: it is a hash shown in the user form (globeadmin, Auto-login link) – HMAC-SHA256 of the stored password hash with $nuConfigSecretKey, so the link stops working when the password changes. The user form offers links that expire (1, 7, 30, 90 days or never – &e= is part of the signed hash) and Revoke links, which ends all links of the user without a password change. Needs $nuConfigAutoLogin = true; not possible for the globeadmin; two-step login, the user's expiry date and the login rate limit apply; the hash is removed from the address bar at once. A link opened while somebody else is logged in asks before it switches the login. Without p the login page opens with the name filled in, and after the login the form opens. Generally, a link opened while logged out leads back to that page after the login.

One-time login link (nuBuilder Forte's Single-User Password Token, needs no setting here): see Sign-in methods → One-time login link.

Own login page: $nuWelcomeBodyInnerHTML works as in nuBuilder Forte – nuBuilder Forte's HTML can be used as it is (inputs nuusername / nupassword, the submit button). Inline onclick / onsubmit are not run (security policy); nuBuilder Next connects the form itself and adds the security token. style="…" works; image paths core/graphics/… point to nuBuilder Forte's folder. Error messages, "Forgot password?", the language and theme menus stay. nuconfig-sample.php has a commented example.

Command line (cron.php)

cron.php runs only on the command line (the web server refuses it). Run it as the web server's user, so files it writes belong to that user.

CommandWhat it does
php cron.phpHousekeeping, e.g. every 15 minutes from cron: removes expired tokens and sessions, old API counters, log rows beyond the retention and temporary files, retries webhook calls, finishes an unattended update whose database steps are pending. Without cron, page views do this now and then.
php cron.php update …Unattended update from a URL, a zip file or GitHub (Unattended update)
php cron.php integrity [--json]The integrity check of the database; exit code 1 when it finds problems
php cron.php iprules offSwitches IP access off when its rules lock everybody out (the rules stay stored)
php cron.php reset --sql=<file> …Developer mode only: Reset database
