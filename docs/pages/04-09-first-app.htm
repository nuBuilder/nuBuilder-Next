Your first application

A small contact manager from start to finish: two tables, two forms, a lookup, a sub-form, a report and an access level.

For: Users with rights on: nuform

This walkthrough builds an application that keeps organisations and the contacts who work for them. Each step names the tool and links to its reference page. If tables, primary keys and foreign keys are new to you, read Database basics first. The interactive tutorial covers similar ground inside the application.

The pattern every form follows

Almost everything a user does is one of two things: find something, or add or change something. A form therefore has two screens:

  1. the list (nuBuilder Forte calls it the browse or search screen): search, filter, sort, then click a row;
  2. the record (the edit screen): the fields of one row, with the action buttons Save, Clone and Delete. Add in the list opens the same screen, just empty.

A tile on the start page (or a button) opens the list, the list opens the record – for customers, invoices, bookings, whatever you build. A user who has learnt this once can use the whole application, and you do not have to design menus: you design a list of forms.

1. The tables

Two tables, named as in Naming tables and columns:

organization:  organization_id (key), org_code, org_name, org_address1, org_suburb,
               org_state, org_postcode, org_office_number, org_office_email, org_notes
contact:       contact_id (key), con_organization_id (foreign key → organization),
               con_firstname, con_lastname, con_email, con_mobile

You can create them in the New form wizard (next step, New table) or beforehand in a database tool. Make the key columns text (VARCHAR(25)) – nuBuilder Next fills them on every new record.

2. The organisation form

  1. Forms → New form (see Creating a form). Step Form: description Organisations (it is shown in the breadcrumbs and in lookups), a short unique code such as org, type Browse and edit.
  2. Step Table and fields: choose organization and the key organization_id – or New table and enter the columns. Every column gets an object; Choose columns and order decides which ones, their labels, which go into the list (here code, name, phone and e-mail) and in what order.
  3. Step Layout and access, then create. The form opens in design mode, already working: its list shows the organisations, a click opens one.

The list's columns come from the form's browse SQL (SELECT * FROM organization) – in design mode click a column title on the list to change its title, width, alignment or format, or to add a filter (see The list).

3. Objects, IDs, tabs and placement

  • The ID decides where a value is saved. An object stores its value in the column with the same name as its ID – org_name saves into organization.org_name. That holds for inputs, selects, text areas, lookups and editors. Buttons (run objects), sub-forms, HTML, words, display and calculation objects store nothing, so their ID only has to be unique on the form. An ID has letters, digits and _ only; check that no space slipped in at the end of IDs, table names and keys.
  • Tabs group the objects: double-click a tab to rename it (Details), + adds one (Notes), and an object's Layout section moves it to another tab.
  • Placement: drag objects where you want them, or type Top and Left in pixels. Objects with the same Left form a column (for example 90 for the left column and 510 for the right one); the order inside a column follows Top. With several objects selected, Arrange lines them up and spaces them evenly (see Fixed gap).
  • Add (icon bar) lists the table's columns that are not on the form yet and every object type – click one to add it to the open tab.

4. Choosing the right object type

  • Input for short values. Its input type sets the kind: text, nuNumber (with a number format, right-aligned looks best), nuDate, e-mail, checkbox …
  • Select for a fixed choice, for example the state. The Options are pairs of stored value and shown text separated by |: NSW|New South Wales|VIC|Victoria|SA|South Australia – or a SELECT whose first column is the value and the second the text, or a JSON list.
  • Text area for longer text such as notes (give it room: width 500, height 300); an editor for formatted text.
  • Automatic numbers: an input of type nuAutoNumber counts on its own – each new record gets the next number when it is saved. Set Last number to the number given last (100099 → the next record gets 100100; a prefix such as INV7 is kept: INV8), and make the object read only (access 1), as users should not type it.

5. The contact form and its lookup

Create the second form the same way, on the table contact, code cont, description Contacts. The foreign key con_organization_id becomes a lookup, so that users pick an organisation instead of typing its key. A lookup has three parts:

  1. its ID = the foreign key column of this table (con_organization_id) – the stored value, never shown;
  2. the code column of the other form's table (org_code) – what the user types or sees in the small box;
  3. the description column (org_name) – shown next to it (Description width sets its width).

The Lookup form is the form whose list the user searches – here org; it must exist before the lookup. To copy more values when an organisation is picked, write PHP in PHP after selection (AB): nuLookupRecord() returns the chosen row, nuSetFormValue() fills a field – for example nuSetFormValue('con_phone', nuLookupRecord()->org_office_number);. JavaScript after the selection goes into the lookup's JavaScript field.

6. The contacts as a sub-form of the organisation

A sub-form shows the child rows on the parent's form – here the contacts of an organisation – and lets users add, change and delete them there.

  1. Create the form for the rows: New form with type Subform on the table contact (its objects are the columns of the grid; leave out con_organization_id, which is filled automatically).
  2. On the organisation form, Add a Sub-form object (for example ID contact_sf, width 900, height 300). Set Subform form to the form of step 1 and Foreign key to con_organization_id; tick Rows can be added / Rows can be deleted as needed and choose the layout Grid (one row per line) or Form.

When the organisation is saved, its new contact rows get its key in con_organization_id. More on using sub-forms: Sub-forms, lookups, files.

7. Getting users to the form

Users without an admin role see the forms and reports of their access level as tiles on their start page – automatically, until you arrange a layout for the level (Start pages of users). The wizard's Access for access levels step grants the new form right away. If you also use nuBuilder Forte's User Home, the wizard can put a button there; buttons of your own are run objects with Open form. To change a form's name in the breadcrumbs, change its description (or the breadcrumb title) in the form settings.

8. A report: organisations by state

A report has three parts: a criteria form where the user chooses what to print, the data (an SQL query that uses the choice) and the layout.

  1. Criteria form: a form of type Launch (no table needed – it saves nothing) with the objects the user fills in, for example the state select of the organisation form (copy it: select it, Ctrl+C, open the criteria form in design mode, Ctrl+V).
  2. Data: in the SQL builder (or a procedure) a query that reads the criteria as hash variables: 
    SELECT org_code, org_name, org_office_email, org_state,
       (SELECT COUNT(*) FROM organization WHERE org_state = '#org_state#') AS total
FROM organization
WHERE org_state = '#org_state#'
    The bracketed query adds a column total with the number of matching organisations, for the report footer. Try the query with Run before you use it (with a real value instead of #org_state#).
  3. Report: Reports → Add – a unique code (orgstate), the description (printed with #description#), the query as data source and the criteria form as launch form.
  4. Layout in the report designer. Put each object into the right band:
    • report header – once, at the top of the first page: the title #description# and State: #org_state#;
    • page header – at the top of every page: the column titles as text, with a line below them (the designer's line object);
    • detail – once per row of the data: the fields org_code, org_name, org_office_email;
    • page footer – at the bottom of every page: Printed: #day#.#month#.20#year# and Page #page# of #pages#;
    • report footer – once, right after the last detail row (not at the bottom of the page): Total: and the field total.
    Set each band's height in its properties, and save now and then; Preview prints the layout as it is.

Users start the report from its tile, a run object (Run report) or nuRunReport('orgstate'): the criteria form opens, Run report makes the PDF.

9. An access level for the users

  1. Access levels → Add: code staff, description Staff; optionally a start form.
  2. Form rights: add every form the users open – the organisation and contact forms with the buttons they may use, and the report's criteria form. A lookup only works when the user may also open its lookup form (here the organisation form, which is in the list anyway).
  3. Reports: tick the report. A report needs both: the report itself and its criteria form – without the form right the report runs straight away without asking for criteria.
  4. Users → Add: name, login, e-mail, the access level Staff and a password (or the welcome e-mail).
  5. Test it: open the user and choose Act as user – you see exactly the start page, forms and buttons the user gets, without knowing the password. Or sign in with the new login in a private browser window.

If you know nuBuilder Forte

  • Objects → Add, Fast Form and Arrange Objects are all part of design mode here: the New form wizard replaces Fast Form, and objects are added, moved and changed on the form itself.
  • A sub-form object offers only forms of type Subform; a lookup offers forms of type Browse or Browse and edit.
  • A report's criteria form needs no table – a Launch form works; nuBuilder Forte's habit of using zzzzsys_setup as the table also works.
  • Users need no nurunreport form: their reports are on their start page. Everything stays compatible – the forms, objects and reports are stored in nuBuilder Forte's tables and open in nuBuilder Forte as well.
