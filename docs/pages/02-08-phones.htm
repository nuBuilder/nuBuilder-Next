Phones and small screens

How nuBuilder Next adapts to phones and tablets, in one place.

For: Everyone

nuBuilder Next has no separate mobile version: every page adapts to the width of the screen. The main differences:

WhereOn a phone
Menu barWithout a logo (Branding): the icons stay in the bar, the areas move into the user menu (☰), and so do the theme and the language – at the top of that menu – so the bar fits also with an environment label. With a logo: the areas are behind the ☰ button, and the pin button next to it keeps the menu open on every page (until it is tapped again; kept per browser). The user button shows only its icon.
Record buttonsSave, Clone, New and Delete show only their icon (Save as a floppy disk); the text is the tooltip.
Header of form pagesInstead of the breadcrumb and the button row: a link ‹ <previous page> (the Back button) and below it the page title with the buttons as plain icons on its right (lists: table / cards, Export, ⋮; records: Save, Clone, New, Delete, ⋮). Add of a list sits next to the search field. The shared setting Back Button on Phones (Settings → Shared settings) shows the back link as ‹ only or hides it; on nuBuilder Next's own pages it does the same with their Back button.
Header of the other listsThe lists of nuBuilder Next (users, forms, procedures, reports, log …) look the same below 576 px: ← Back as a small link above, the title on the left and the buttons as plain icons on its right (Add, ⋮, table / cards, view, Export); the breadcrumb above the list is left out, Back leads to the same page. The bar keeps only Back, Add and the view menu; every other action (Export, Print, Import …) is an entry of the ⋮ menu, with Card or table at its top.
SettingsThe list of sections on the left becomes one selection field above the page (sections and their pages); the subtitle of the page is left out.
Touch screensFields of record pages keep their full size on tablets and phones; the smaller fields are used only with a mouse.
Header of nuBuilder Next's own pagesPages with a breadcrumb and a Back button (a procedure, an admin role, a data export …) show only the link ‹ <previous page>; the record's name stands below it.
Wide tablesBackups, library packs, the Compatibility check, formats and the cloners show each row as a card, every value with the title of its column.
TabletsSystem lists with more than five columns (users, forms, procedures …) show cards up to a width of 992 px, as on phones.
Designer tools of a formBelow 576 px Design, its entries (browse SQL, PHP, JavaScript, columns), the (i) form info and the layout switch (Absolute · Auto · Grid) leave the button row and sit at the top of the ⋮ menu – the row keeps the buttons every user needs.
Tabs with several cardsSuch a tab shows a small ▾. A tap on it – or a long tap on the tab (e.g. General of the user form) – lists its sections – Person, Login credentials, Access & roles …; a tap jumps to that card. On a computer: right-click on the tab.
Start pageA layout without its own phone settings shows a one-column list, and tabs become the side bar. A layout can have separate settings for phone (narrower than 576 px), tablet (narrower than 992 px) and desktop – see Start page of the globeadmin.
Lists of nuBuilder NextBelow 768 px every row is a card (title, badge, up to four lines), or a compact table whose first column stays while the others scroll – set per list in its list view. A button next to the view menu switches between cards and table on your phone; the choice is kept on the device.
Form listsBelow 576 px every row is a card: the first column as its title, the others as Title: value lines. Add shows only its + icon (on the system lists too). The ▦ / ☰ button next to it switches the list to a table (scrolling sideways) and back; the choice is kept per form on the device. No page-size choice (Back / Next stay). The column filters are folded behind the funnel button unless one is set. A list shown inside another form (a run object) gets a compact header, keeps its filters folded behind the funnel and grows to its rows.
Edit formsEvery form puts its objects below each other – also forms with fixed positions (nuBuilder Forte's pixel layout): below 576 px each field gets its label above it and the full width, in the order of their positions (top, then left); content boxes become section titles. Form code can keep the fixed layout with nuNextPhoneLayout(false) in nuOnLoad; nuBuilder Forte's nuPortraitScreen() turns this layout on at any width (capped at 720 px).
DashboardsOne widget per row (tablets: two); table widgets show each row as a block (first column as title).
Admin rolesEach right is a row with its name and the choices None · View · Change as buttons.
Help icons and tooltipsTap instead of pointing.

On large screens (from about 1680 pixels) the content of a page sits in one framed sheet of at most 1600 pixels, centred on a slightly darker background, so the cards do not spread over the whole width; design mode and the report designer keep the full width.

On wider screens forms built with absolute positions keep their positions; the automatic and grid layouts turn the same objects into responsive rows (see Form rendering pipeline), and content boxes with a direction arrange their objects per screen size – see Responsive forms.
