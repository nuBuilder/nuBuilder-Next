Editing nuconfig.php in the browser

Advanced The configuration file editor and its checks.

For: Administrators (globeadmin, admin roles)

Settings → Configuration file (start page tile Configuration file; globeadmin or the admin role right Configuration file (nuconfig.php), a full-access right; not in demo mode) edits nuconfig.php in a code editor with the usual tool buttons (undo / redo, search, replace, comment, spaces and tabs, Format, full screen – no hash variables). The path is shown under the title.

  • Save writes the file only if it passes every check: valid PHP, starts with <?php, runs without an error and without output, sets $nuConfigDBName, and the database connects with the new settings. Save checks right away, without leaving the page: on an error the message appears above the editor and the line PHP reports is marked (for a missing ; that is often the line after it); the file is not written. Check runs the same tests without saving.
  • Before writing, the current file is copied to the backup folder (_backup/ or $nuConfigBackupPath, blocked for the web) as nuconfig-<date-time>.php; the newest 10 are kept. Backups loads one into the editor – Save restores it.
  • Insert variable (above the editor): lists the variables nuBuilder Next reads that the file does not set yet – those of nuconfig-sample.php and the ones only read by the code – in groups, with their default value and the comment of the sample (English, as in the file); a commented-out line counts as not set and is marked. A click inserts $name = default; //-- comment as a line of its own below the line where you last clicked or typed in the editor, otherwise at the end (before a closing ?>); the list updates, so several can be added in a row. Own variable adds one of your own (letters, digits, _), as text, number, true or false, with an optional comment. Nothing is written until Save, which checks the file as usual.
  • If someone else changed the file since the page was opened (FTP, another globeadmin), saving is refused and your text is kept.
  • Changes apply with the next request. A nuBuilder Forte (4.x) that reads the same file is affected too. New globeadmin user name / password: the current session continues, the next login uses the new ones. Saving is logged (nuconfig.php changed, without the content).
  • The web server needs write access to the file and its folder; otherwise the editor is read only. If a saved value still stops the site from working (e.g. a setting nuBuilder Next reads only later), correct the file by FTP or copy a backup over it.
