Database schema

nuBuilder Forte's system tables that nuBuilder Next shares, and the tables it adds.

For: Administrators (globeadmin, admin roles)

The database holds three kinds of tables:

  1. Your application's tables – the data your forms show and save.
  2. nuBuilder Forte's system tables zzzzsys_* – the definition of the application (forms, objects, users, rights …). nuBuilder Next reads and writes them exactly as nuBuilder Forte 4.9 does, so both can work on the same database.
  3. nuBuilder Next's own tables zzzzsys_nunext_* – everything only nuBuilder Next needs.

Keys and conventions

  • Every system table has a text primary key <table>_id (e.g. zzzzsys_form_id); the key columns are VARCHAR(25) text (nu_id() makes nuBuilder Forte-style ids of 15 characters). Ids of nuBuilder Forte's own records start with nu.
  • Column names carry a short prefix of their table: sfo_ form, syt_ tab, sob_ object, sbr_ browse column, sph_ PHP, sev_ event, sus_ user, sal_ access level, slf_ access form.
  • A form hook is a zzzzsys_php row whose id is <form id>_<hook>; that is why sample form ids contain no underscore.
  • nuBuilder Next stores its own options of a nuBuilder Forte row as JSON under the key nunext in nuBuilder Forte's JSON columns (e.g. a form's layout, an object's grid position or a format's options), so nuBuilder Forte ignores them.

How nuBuilder Next's tables are created

nuBuilder Next's tables are defined in code (core/nuinfra.php) and created by the installer or the globeadmin's sign-in on MySQL / MariaDB and SQL Server; missing columns of existing own tables are added by updates. nuBuilder Forte never reads them, its update keeps them, and its app cloner and backups treat them as system tables. The Self-test (developer mode) and the update page compare the actual structure with install/schema_expected.json.
