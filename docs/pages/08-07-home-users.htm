Start pages of users

One tile start page per access level.

For: Administrators (globeadmin, admin roles)

Users without an admin role get a tile start page as well – one per access level, built with the same tiles, groups, tabs and appearance settings as the globeadmin's start page. The globeadmin sees the table My forms and rights while acting as a user (collapsed at the bottom: Forms and rights of this user). The access level's dashboards stay above the tiles.

  • Where to edit: Access levels → an access level → Start page, or the tile Access levels ▾ → Start pages of users (index.php?p=home&for=<access level id>). Needs the admin right Start page layout (the globeadmin always). Start page for switches between Default for all access levels and each access level; the list says whether it has its own page, uses the default or the automatic one.
  • Which page a user gets: the access level's own page; else the default for all access levels; else the automatic page – the forms of the access level (no sub-forms, no nuBuilder Forte (4.x) system forms; the home form first, marked Home form) and the reports it may run. Customise on an access level that shows the default or the automatic page saves a page of its own (starting from what is shown). Use the default removes the access level's own page again; on the default, Remove the default.
  • Preview: the editor shows the page with the rights of the chosen access level – tiles its users may not open are left out. Conditions are not applied there; such tiles and groups carry a funnel (its tooltip lists them). To see a page exactly as one user does, act as that user.
  • Tiles (Customise → Add tile): a form (list, new record -1 or a record id), a report (opens like index.php?p=report&c=<code>, with its launch form when it has one), a procedure (runs with the user's rights – Access levels → Procedures or Global), a page (help, password, security, notifications) or a link. A tile is shown only when the user may open it: form rights of the access level, the report or procedure granted to it. The built-in tiles of the admin page are not offered.
  • Only for (conditions): every tile (in its dialog) and every group (the funnel next to the group name) can be limited to Permission item, Team, Department or Position of the user (user form). Several values separated by commas – any of them is enough; several fields – all must match; case does not matter. A hidden group hides all its tiles. Static per-user rules are best done with permission items. Hiding is not access control: a form stays protected by the rights of the access level.
  • What users change (Customise): Appearance (style, descriptions, navigation … only for themselves) and Personalise: a star and an eye on every tile – own favourites (they replace the page's favourites for this user) and tiles hidden for this user, listed under Hidden by you while personalising. Done saves, Back to the standard removes both. Stored in the user's sus_json (NUNEXT_HOME_VIEW, per page), at most 60 tiles each. Not offered while the globeadmin acts as the user in view mode.
  • Examples in the sample data: sample_sales (Dario) – a sales desk in the style Cards with a favourites row, a New order tile (record -1), a report and a group Pricing only for the permission item sample_discount; sample_manager (Carla) – two tabs Daily work / Insights with group colours, a procedure tile and a group Team lead only for team Lead; sample_editor (Ben) – a list in two columns with New … tiles and a report only for the positions Clerk and Manager. sample_viewer (Anna) and sample_secure (Eva) show the automatic page. Removing the sample data removes these pages too (also pages saved later for a sample access level).
  • Hook: the procedure nu_home_user runs on these pages (not nu_home) – see Start page hooks.
  • Stored in zzzzsys_nunext_list_view (list home_user; access_ids = the access level, ["*"] = the default). Changes are logged (Start page of an access level changed / removed). Users with an admin role keep the admin start page.
