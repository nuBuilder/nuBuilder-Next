Sessions and sign-in flow

How nuBuilder Next signs users in and keeps its own sessions next to nuBuilder Forte's.

For: Administrators (globeadmin, admin roles)

nuBuilder Next has its own sessions and does not use nuBuilder Forte's zzzzsys_session table for its users (it only reads it for the shared login). The login is checked against zzzzsys_user (login name and password) and, for the globeadmin, against nuconfig.php.

  • Passwords: password_hash() hashes (bcrypt / argon2) and nuBuilder Forte's old md5 hashes are accepted. md5 hashes are upgraded at login unless nuBuilder Forte (4.x) must still read them ($nuConfigPasswordUpgrade, $nuUseMd5PasswordHash).
  • Password changed elsewhere: the session keeps a short fingerprint of the stored hash; when the password is changed (also in nuBuilder Forte), the session ends.
  • Time-outs: $nuConfigSessionTimeout (users) and $nuConfigSessionTimeoutGlobeadmin. Passive background requests do not extend them.
  • Logged-in users: one row per session in zzzzsys_nunext_session, updated at most every 30 seconds; the key is a hash of the PHP session id, the id itself is never stored. The globeadmin can end sessions (Logged-in users).
  • Login hooks: nuBuilder Forte's procedures nu_startup and nu_invalid_login run as in nuBuilder Forte; nu_check_password_policy checks new passwords.

All ways to sign in (shared login, auto-login links, tokens) are on Sign-in methods.
