Admin roles

Advanced Sharing parts of the administration with other users.

For: Administrators (globeadmin, admin roles)

Start page → Admin roles gives other users a defined part of the globeadmin's rights in nuBuilder Next. A role is a set of rights, one per tool, each view or change (some tools have one level only, e.g. Database or Setup wizard). A user gets at most one role: the field Admin role on the user form. nuBuilder Forte (4.x) itself does not know these roles – there the user stays a normal user with his access level.

  • The list is a system list like the others: search, list views, export, filter Has users; the Users count opens the users list filtered by the role.
  • Default roles (created once, then editable and copyable): Full administrator (everything), Administrator without system (everything except Update, nuconfig.php, Settings, Global code, Database, File Manager, App cloner, API clients, Webhooks, Admin roles), Developer (forms, procedures, reports, dashboards, prompt generator, data import, debug results and compatibility check to view), User manager (users, access levels, custom user fields, logged-in users, shared list views) and Support (read only) (change log, audit trail, debug results, logged-in users, System status – view only; audit trail – roles created before keep their rights). A role can also have Notifications (view = all notifications and read receipts, change = send).
  • What a user with a role sees: the start page tiles, ▾ menu entries, Ctrl+K results and admin help chapters of their rights – and their normal forms below. Every page checks the right on the server; a page they may only view shows View only and its buttons that change something are switched off. Customise needs the right Start page layout (the layout chosen for them – a shared layout of their role or an own one, see Saved layouts below).
  • Rights on nuBuilder Forte's system forms (users and permission items, access levels, forms with items, files, formats and translations, procedures, reports and SQL builder, e-mail, logs) are added to the user's access level: change = all buttons, view = open and print.
  • On the role form every right links to its tool (new tab); the rights are listed with their area, a Full access column and the levels None / View / Change (a dash where a right has no View level); a click on a column title sorts by that column (a third click goes back to the order of the areas). On a phone the column titles None / View / Change stay at the top; each right shows its name with area and shield below it, and its three choices in the same columns as every other right. On the user form a link next to Admin role opens the chosen role in a new tab.
  • Full access (red shield): Update, nuconfig.php, Global code, Database, File Manager, Data export, App cloner, forms, Publish forms (drafts), procedures, act as another user, Admin roles, API clients, Webhooks and the audit trail lead to full access in the end – PHP code on the server, the whole database, the web folder or the passwords. Give them only to people you would trust with the globeadmin password.
  • Who manages roles: the globeadmin and users with the right Admin roles. Nobody gives rights they do not have themselves, changes their own role or edits the role they hold; a role with users cannot be deleted. Users with a role act as other users only when the role has Act as another user, and never as another admin.
  • Test a role: Test role on the role form (or in its row of the list) lets you work as a user you choose, with this role added – for this session only, nothing is saved. Pick a user with the access level the role is meant for: their access level, permission items and hash variables apply as usual, and the role's admin rights come on top, so you see exactly what a holder of the role will see. The users who already have the role are listed first. View only or Full access (after a confirmation) work as in acting as another user; the coloured bar names the role, and Back to globeadmin returns to the role form. The test uses the saved role – save changes first. Who may test: the globeadmin, and users whose own role has Act as another user and Admin roles (change) – only roles whose rights they have themselves, and never as another admin. Start and end are logged with the role.
  • Review before saving: while you change the rights of an existing role, each changed row is highlighted and shows its level before (was: …). The head of the Rights card counts the changes; Show changed only lists just those rows and Undo changes puts every level back as saved. The marks go once the role is saved.
  • Plugins: rights that switched-on plugins add appear in their own group Plugins, named by the plugin; they go away from the list while the plugin is off.
  • Publish forms (drafts): publishes form drafts; starting and editing a draft only needs the rights on the form.
  • The log names the real user; Security check lists everybody with an admin role and warns when a role holds full-access rights. Two-factor login is not required for admin roles (the access level's 2FA setting applies).
