Start page hooks

Changing start pages with the procedures nu_home and nu_home_user.

For: Administrators (globeadmin, admin roles)

A procedure with the reserved code nu_home (older installations used nunext_home / nunext_home_user – the update renames them unless the new code is taken already) runs every time the tile start page is built (globeadmin and users with an admin role). On the start pages of users the procedure nu_home_user runs instead – the same functions; tile keys there are the own tiles c_… of the page and the hook's x_…; #HOME_PAGE# is user (else admin) and #HOME_ACCESS# the code of the page's access level (* on the default in the editor). In the editor it runs as the globeadmin. Its PHP changes only this page view: badges, descriptions, hidden tiles, extra groups and tiles, banners. Nothing is saved into a layout. Create it under Procedures → Add, code nu_home (suggested in the code field); status Draft or Archived switches it off.

// procedure nu_home – runs every time the tile start page is built
nuHomeCache(60);                                   // keep the result 60 s per user

$open = (int)nuRunQuery("SELECT COUNT(*) FROM orders WHERE status = 'open'")->fetchColumn();
nuHomeSetBadge('c_orders', "$open open", $open > 20 ? 'danger' : 'secondary');

if ('#ADMIN_ROLE#' === 'Developer') nuHomeHideTile('cloner');

nuHomeAddGroup('x_today', 'Today');
nuHomeAddTile('x_backup', ['group' => 'x_today', 'label' => 'Last backup', 'icon' => 'bi-archive', 'page' => 'update']);

nuHomeBanner('Maintenance on Saturday 22:00', 'warning');
nuHomeSetData('openOrders', $open);
  • Tile keys: built-in tiles by their key (users, access, forms, update … – the data-nu-tile attribute of a tile), own tiles c_…, pinned pages, and the hook's own tiles x_….
  • Hash variables: the user's ones (#USER_ID#, #USER_LOGIN#, #GLOBAL_ACCESS#, #ACCESS_LEVEL_CODE#, #USER_DEPARTMENT#, #USER_TEAM#, #LANGUAGE# …) and #ADMIN_ROLE# (name of the user's admin role, empty for the globeadmin), #HOME_LAYOUT# (name of the start page layout), #HOME_SIZE# (large, compact, list, listwide, list2), #HOME_DISPLAY# (groups, tabs) – both derived from the view – and #HOME_VIEW# (the desktop view the person sees as JSON – style, desc, nav, density, icon …).
  • Dynamic tiles are checked like own tiles of the tile editor – a link the editor would refuse is refused here too – and drawn by the same code: search, the compact tooltips and every tile size work. They are not shown in Customise (so they can never be saved into a layout) and cannot be favourites. A form tile is shown only to users with rights on the form. All texts are escaped – a hook cannot add HTML.
  • Errors: a failing hook (an error, an exception, a refused tile or key) leaves the page as it would be without the hook. The globeadmin sees the message above the tiles with a link to the procedure; users with an admin role see nothing. Every error and every echo output goes to Debug results.
  • Off switch: $nuConfigHomeHooks = false; in nuconfig.php (or the row Start Page Hooks in Settings). Safe mode: index.php?p=home&tiles=1&safe=1 skips the hook for one page view (globeadmin only; a note on the page says so).
  • Speed: the hook runs on every visit – nuHomeCache(seconds) (at most 3600) keeps its result in the session of each user (also for the same layout and the same code).
  • Demo mode: the hook runs read only for demo visitors (writes stop it with an error). An active hook is listed as information in the Security check and in System status. Whoever may change procedures may change the hook – there is no extra right.
  • nuAddJavascript() does nothing on this page (the start page allows only scripts from files). Hand values to JavaScript with nuHomeSetData().

JavaScript: nuHome

The JavaScript field of the procedure nu_home (when JavaScript active is on) runs on the tile start page. The page allows only scripts from files, so it is served as index.php?p=homejs&v=<hash> (only for users of the tile page; the browser keeps it until the code changes) and loaded after the page's own script. PHP creates tiles, JavaScript decorates them – there is no addTile() in JavaScript.

// JavaScript of procedure nu_home – runs on the tile start page
nuHome.on('tile', function (tile) {
  if (tile.kind === 'procedure') tile.el.classList.add('border', 'border-warning');
  if (tile.key === 'c_orders' && nuHome.data.openOrders > 20) tile.setHint('Too many open orders – check today');
});
nuHome.on('search', function (query, shownTiles) {
  if (query && !shownTiles.length) console.info('No tile for', query);
});

nuHome.dataThe values of nuHomeSetData().
tile: key, el, source, kind, label, hint, icon, color, badge, group, tab, size, fav, hrefsource: builtin, own, pinned, dynamic · kind: form, page, procedure, url, post (database tools) · size: large, compact, list, listwide, list2 · href: null for procedure and post tiles.
tile: setBadge(text, color), setHint(text), hide(), show(), onClick(fn)Change the tile in place; hidden tiles stay hidden in the search and with Favourites only; fn(event, tile) runs first – return false cancels the tile's own action.
  • Every tile carries data-nu-tile, data-nu-source, data-nu-kind, data-nu-group, data-nu-tab, data-nu-label and data-nu-desc.
  • Every callback runs in try / catch: an error goes to the browser console and – for the globeadmin – to a message at the bottom right (each error once); the other callbacks still run.
  • No style="…" in HTML strings (the page's content security policy blocks it) – set el.style.… from code instead.
  • Safe mode and $nuConfigHomeHooks = false skip the JavaScript too. The Compatibility check scans it with the other procedures.

The result of nuRunQuery() also offers nuBuilder Forte's PDOStatement methods fetch(), fetchColumn(), fetchObject(), fetchAll(), rowCount() and columnCount().
