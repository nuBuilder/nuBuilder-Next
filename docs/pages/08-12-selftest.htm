Self-test

Advanced Checks of the installation in developer mode.

For: Administrators (globeadmin, admin roles)

Admin tools → Self-test (index.php?p=selftest) is shown only to the globeadmin while $nuConfigDevMode = true. Run checks the installation, by group:

  • System: PHP version and extensions (a warning while PHP lacks the PHP2Shell fix – see Security check), writable folders (temp, backups), nuBuilder Next's tables and columns, the database steps of all updates, the structure of nuBuilder Forte's tables, complete language files, red points of the Security check, e-mail set up.
  • Data: sample application installed, a form's browse list, the queries of all system lists, a report as PDF.
  • Forms: save a new record, required / unique fields refused, change a record, sub-form rows (add, change, delete), hash variables, audit trail and restore, delete with sub-form rows.
  • Rights: access levels give exactly the stored rights; the admin role rights are complete.
  • Features: a notification is published, received and read; the housekeeping ran in the last two days.

Results: OK, warning, failed or skipped, with details and duration. The form checks write into the sample application (customers, orders with items) and delete their records and audit rows again; a notification to the globeadmin is created and deleted. Without the sample application they are skipped. Use it on development and test installations – not with live data. Each run is in the log.

Releases are also checked by browser tests outside the application (dev/tests/e2e.js, only in the development package): login, forms, sub-forms, nuBuilder Forte's form events (Before Save, Before Delete, After Save, Before Edit, a lookup's After Browse), lookups, JavaScript events, procedures, permission items, rights, admin roles, demo mode, one-time login links, user import, audit trail, notifications, list views, start page, branding, dashboards, the login limit, CSV import, update check, the self-test, CSRF – and by cross-tests against nuBuilder Forte (4.x) itself (dev/tests/compat.js): the same database opened in nuBuilder Forte 4.9 and in nuBuilder Next, every application form compared (browse list, field values, a save without a change), the same typed input must give the same row, sub-form rows and reports across both, and a save without a change in nuBuilder Next's editors (users, access levels, procedures, SQL builder, report designer, permission items, e-mail templates, form builder) must leave nuBuilder Forte's rows as they were. It can be pointed at a copy of a real nuBuilder Forte database.
