Procedures and hooks

Advanced PHP procedures, form hooks and the global hooks that run for every form.

For: Users with rights on: nuprocedure

Forms → Tools → Procedures lists the PHP procedures (zzzzsys_php) that run buttons, nuRunPHP() and nuRunPHPHidden() start. It shows your own procedures; the filter Origin → System lists those that come with nuBuilder Forte and nuBuilder Next. The lists of items and e-mail templates have the same filter; e-mail templates show the templates of your language (and those without one) until the filter Language shown is cleared. Form events (Before Edit, Before Save …) are edited in design mode's Code tab.

On the PHP tab, code, description, group, category, status and Launch from are in the block Details: collapsed for a saved procedure (its line shows code – description · group; click it to open), open for a new one and after an error in one of these fields.

  • PHP: code (unique; the arrow suggests the codes of nuBuilder Forte's global procedures such as nu_before_save, nu_startup, nu_check_password_policy, nu_send_welcome_email), description, group, category, status, the form it belongs to (Launch from) and Run from a button: how it runs when a button on a form starts it – Hidden in the background (no window, the user stays on the form) or in a New tab that shows its output; empty works like New tab (the same setting as in nuBuilder Forte). The editor has the # menu for hash variables and Insert (functions of the reference and the code snippets). Test now – Hidden / New tab – runs the saved version right away and shows the result; it does not change the setting.
  • JS: with Active, nuOnProcedureRun() runs in the browser before a test run from this page – nuSetProperty('name', value) passes values to the PHP code (#name#), return false cancels.
  • The list: filters Group, Status, Category and Run (as a button / hidden / new tab); the access count opens the Access levels tab.
  • Access levels: who may run it – everyone, or the selected access levels. The globeadmin may run every procedure.
  • Demo access (nuBuilder Forte's switch, on for new procedures): in demo mode only procedures with this switch run – and they cannot change data or send e-mails there.
  • Usage: objects that start it and code that names it. A procedure that objects still use cannot be deleted.
  • History: who changed what and when, with the code before and after.
  • Templates and system procedures are read-only – Clone them to make your own.

PHP hooks and procedures

  • Form hooks as in nuBuilder Forte (4.x): Before Browse, Before Edit, Before Save, After Save, Before Delete, After Delete; lookup After Browse code (nuLookupRecord() = the chosen row with its key as ID).
  • nuOnProcessObjects() and nuOnProcessBrowseRows() (as nuBuilder Forte): a function of that name declared in Before Edit changes the objects before the form is drawn – $f->objects, each with id, label, value, top, left, width, height, read (access 0–4), valid, align; one declared in Before Browse changes the rows of the list page – $f->browse_rows, each row [0] = the primary key and [1], [2] … = the columns as stored, before their format. The function is not called: its body runs with $f, as in nuBuilder Forte.
    function nuOnProcessBrowseRows() {
  for ($i = 0; $i < count($f->browse_rows); $i++) {
    if ($f->browse_rows[$i][1] == '1') $f->browse_rows[$i][1] = '✓';
  }
}
  • Global hooks (as nuBuilder Forte 4.9): a procedure with one of these codes runs for every form – nu_before_save (before each form's Before Browse and Before Save), nu_before_edit (before Before Edit), nu_before_delete (before Before Delete), nu_startup (after each sign-in; a text in $error ends the session and is shown instead), nu_invalid_login (after a failed sign-in, #LOGIN_NAME# = the name typed), nu_check_password_policy (new passwords: $newPassword, $userId; $check = false or nuDisplayError() refuses it – user form, own password, reset link, REST API), nu_after_update (after an update's database steps) and nu_debug_result_added (after each nuDebug(): $nuDebugId, $nuDebugMessage). An error in a save hook stops the save.
  • nuFORMdata: in Before Save and After Save $nudata (as in nuBuilder Forte) and nuHash()['nuFORMdata'] hold the posted edit form (nuBuilder4EditForm) and its sub-forms; nuGetNuDataValue($nudata, '', 'field') reads a value, nuSetNuDataValue($nudata, '', 'field', $value) in Before Save changes what is saved (sub-forms: the sub-form object id, first row). The simpler pair of nuBuilder Next needs neither: nuNextSaveValue('field'[, 'subform_id', $row]) reads, nuNextSetSaveValue('field', $value[, 'subform_id', $row]) changes – any row of a sub-form (0 = the first).
  • Object events: onchange, oninput, onclick, onblur, onfocus, onkeydown, onnuload (when the edit form has loaded, after the calc objects and before nuOnLoad; this as in nuBuilder Forte) and onenter (the Enter key in the field) – these two as in nuBuilder Forte 4.9. Calc objects of a sub-form are calculated per row (nuTotal('qty') = this row's field) and do not make the blank new row an edited one.
  • Procedures (zzzzsys_php): nuRunPHPHidden('code') runs in the background, run objects and nuRunPHP show output.
  • A procedure can send a file: set the headers Content-Type and Content-Disposition: attachment; filename="…", print the file and exit (or call download() of a NuXlsx). nuRunPHP, nuRunPHPHidden, start page tiles and Test now on the procedure page then save it as a download instead of opening a window – see the sample procedures sample_xlsx and sample_xlsx_pss.
  • Hash variables (#RECORD_ID#, #USER_ID#, fields, properties …) – see Hash variables.
  • Your own helper functions: $nuConfigIncludePHP.

Procedures by cron

A procedure that should run by itself – every night, every hour, on the first of the month – is started by the server's cron. The crontab decides when; nuBuilder Next runs the procedure, writes a log entry and sends an e-mail when it fails.

# every day at 6:00
0 6 * * *  php /var/www/html/nunext/nucron.php run my_procedure --quiet

# as a user, with a value the code reads as #PERIOD#
0 2 1 * *  php /var/www/html/nunext/nucron.php run month_end --user=service PERIOD=last_month
  • The code is the procedure's code. Form events cannot be run this way.
  • --user=<login name>: the user the procedure runs as – its rights and #USER_ID#. Without it, the globeadmin. A user needs the right on the procedure, as when starting it from a button.
  • name=value: hash variables of the run, as nuSetProperty() would set them. #NU_CRON# is 1 in every such run, so the code can tell it from a start by hand.
  • Result: what the code prints is printed (--quiet: only when it fails). The run counts as failed when the code throws an error, a query fails with an exception or the code calls nuDisplayError(). Exit code 0 = done, 1 = failed, 2 = wrong call.
  • Log: every run is one entry in the log (Procedure run by cron / … failed, with the duration and the error).
  • E-mail when a run fails: Settings → Data & logs → Scheduled procedures takes one or more addresses; the e-mail names the procedure, the time, the user, the error and the output, and goes through the e-mail settings. --mail=<address> replaces the address for one job, --mail= sends none.

Run the command as the web server's user. A job that runs longer than its interval is started again by cron while the first still runs – guard such code yourself, or use flock in the crontab line.
