Migrating from nuBuilder Forte 4.9

Trying an existing nuBuilder Forte (4.x) application in nuBuilder Next.

For: Administrators (globeadmin, admin roles)

Not supported yet: nuBuilder Next cannot run on an existing nuBuilder Forte database for now – the installer refuses a database that already has nuBuilder Forte's tables. Install nuBuilder Next on a new, empty database and try your application on a copy, never on the live nuBuilder Forte database.

The goal is that nuBuilder Next works on the database of a nuBuilder Forte 4.9 application without converting it: forms, rights, procedures and reports use nuBuilder Forte's own tables and formats, and nuBuilder Forte keeps working on a database that nuBuilder Next set up. Until existing databases are allowed, you can check an application this way:

  1. Export the application's database as a complete SQL dump (phpMyAdmin, mysqldump). The live database stays as it is.
  2. Install nuBuilder Next on a new, empty database (Installation), ideally as a sub-folder of nuBuilder Forte (e.g. /nubuilder4/nunext/), so it finds nuBuilder Forte's libraries.
  3. Import the copy: in developer mode, Reset database deletes the tables of this nuBuilder Next database and imports the dump (MySQL / MariaDB only). Afterwards the database counts as set up by nuBuilder Next.
  4. Run the Compatibility check: it scans all code of the application for nuBuilder Forte functions and shows whether each is supported.
  5. Read the differences for the functions your code uses.
  6. Test the forms, reports and procedures on the copy. nuBuilder Forte can be pointed at the same copy to compare.
  7. Optional: switch forms to the automatic layout to make them work on phones.

The tutorial has a lesson on this (Tutorial).
