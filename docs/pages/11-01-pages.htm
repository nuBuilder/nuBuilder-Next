Pages (custom PHP)

PHP apps of your own that run inside nuBuilder Next.

For: Users with rights on: nuform

A form can be of the type Page (custom PHP): a PHP app of your own (or written by an AI) that runs inside nuBuilder Next. nuBuilder Next checks the login and the access level's right on the page form before any code of the page runs, and hands the page one object, $nu, with the user, the context and the database. The page writes no login code and has a completely free look – nuBuilder Next adds no header, menu or CSS to it.

Creating a page

  1. Forms → Add, type Page (custom PHP). The code is the folder name: letters, digits, _ and -, starting with a letter or digit, at most 64 characters (names starting with _ are reserved).
  2. The editor of a page form shows the folder custom/pages/<code>/ and whether index.php is there. Create from template copies custom/pages/_template/ there (when the folder is writable; otherwise copy it by FTP).
  3. Give access levels the right on the page form, as for any form (view = may open it; the other rights can be read by the page with $nu->rights() and used as the app's roles).
  4. Write the app in index.php (more files, assets/ for css / js / images). Copy AI prompt puts the guide, this page and the list of your tables into the clipboard – paste it into any AI together with a description of the app.

Settings of a page

  • Open in: New tab (default – menus, tiles and run buttons open it in a new browser tab), Inside nuBuilder Next (the page in an iframe below the top bar and breadcrumbs; Iframe height auto = the page reports its height, or a fixed height like 800px) or Whole window.
  • Settings (JSON): the app's configuration (lists, colours, limits), read with $nu->setting('key') (dot paths). Invalid JSON is not saved. No secrets here – the settings are copied by the cloners. Below the field the page editor lists the keys the page reads (every $nu->setting('key', default) in its files) with the default in the code, the file and whether the key is set, and it names keys that are set but never read. When the page folder has a settings.example.json, Insert example fills the field with it (the template has one).
  • Secrets (API keys, passwords): secrets.php in the page folder (guard line first, return ['key' => '…'];), read with $nu->secret('key'). Never in a package, a cloner copy or the builder (it only says whether the file exists).
  • Content-Security-Policy (optional): added to frame-ancestors 'self', which every page gets.
  • Notes: for the developers.

How a page runs

  • index.php?p=form&f=<code> – the normal form address: an iframe page (mode Inside nuBuilder Next) or a redirect to the page's own address. Every way to open a form works: menus, tiles, run buttons, iframe run objects, nuForm(), bookmarks.
  • index.php?p=page&f=<code> – the page's own output (HTML, JSON for its fetch calls, downloads). r (record id), ps (nuSetProperty values) and the opening form and record (pf / pr, accepted only with the view right on that form) are passed on.
  • index.php?p=pageasset&f=<code>&file=assets/… – files of assets/ only (css, js, images, fonts, json, txt, pdf), with the same login and right.
  • Every POST needs the CSRF token ($nu->csrfField(), NuPage.fetch()). A fetch of the page gets JSON answers: 401 login, 400 csrf, 403 forbidden, 404 not_found, 500 server – error details only for the globeadmin.
  • While the globeadmin views as another user, $nu->user() is that user, $nu->realUser() the globeadmin, $nu->readOnly() is true and POSTs are refused. In demo mode readOnly() is true too.

Besides data and files, $nu writes Excel files ($nu->excel()) and, with the PhpSpreadsheet pack, reads Excel and OpenDocument workbooks ($nu->spreadsheet(), $nu->readSpreadsheet()). The complete list of $nu methods and of the JavaScript helpers (NuPage.fetch, toast, resize, refreshParent, openForm …) is in custom/PAGE_GUIDE.md (also part of Copy AI prompt). Forms opened from a page – links with $nu->formUrl() (with target="_top") or NuPage.openForm() – get a breadcrumb trail: their Back returns to the page, and when the page is shown in a launch form's iframe, to that form (its description in the breadcrumbs). The API has a version ($nu->apiVersion(), currently 1): pages that use only $nu keep working when nuBuilder Next changes inside.

API versions

The page API ($nu and NuPage) has a version number – this nuBuilder Next supports version 1. A page declares the version it is written for with $nu->api(1); as the second line of index.php (the template and Copy AI prompt include it; a page without it counts as version 1).

  • Rule: within one version, methods are only added – never removed or changed. A breaking change raises the version; the older version keeps running (through an adapter) for at least 6 months / 20 releases.
  • Unsupported version: the page does not run; the globeadmin sees which version it needs and what this nuBuilder Next supports, other users a short error.
  • Deprecated methods keep working; each call writes a notice to Debug results (once a day per page and method), deprecated NuPage names a warning in the browser console.
  • Before an update: Check package on the update page lists every page the new version would break (unsupported version, unknown or removed $nu->… / NuPage.… calls) or that uses deprecated ones. The update can still be installed.
  • Page editor of a page form: the declared version and the problems with this version; the forms list shows a warning next to the type of such pages.
  • Only calls written as $nu->name( and NuPage.name are found – keep the variable name $nu.

Files, updates, copies

  • Pages live in custom/pages/<code>/, uploaded by FTP. $nuConfigCustomPagesDir in nuconfig.php (an absolute path) moves the pages folder, e.g. outside the web root – the safest setup.
  • Updates never touch custom/pages/ and custom/lib/ – only custom/.htaccess, custom/PAGE_GUIDE.md and custom/pages/_template/ come with nuBuilder Next. A rollback does not change them either. Include custom pages (update page, backups) puts a copy of the folders into a backup.
  • Direct requests of files in custom/ are blocked three ways: the guard line defined('NU_PAGE') || exit; at the top of every PHP file (the page editor warns when index.php lacks it), custom/.htaccess (Apache) and the nginx rule in Web server rules. Security check tests that the folder cannot be reached.
  • Renaming the code of a page form: rename its folder by FTP too (the page editor says so). Deleting a page form keeps its files.
  • The cloner copies a page form with its settings, not its files (it shows the folders to copy). The App cloner copies the folders with the files of the installation, but never secrets.php.

Draft and versions

To improve a page that is in use, work on a draft: the users keep the live version until you publish. The card Draft and versions in the editor of the page:

  • Create draft copies the page's files into custom/pages/<code>/_draft/. Change the files there (File Manager, FTP, git) – the card lists the files that differ from the live version.
  • Open draft shows the page with the draft's files. This view is remembered for the page until you click Show live version in the bar at the bottom right (shown on HTML pages). Only designers (save right on the Form form, nuform) see a draft; everyone else always gets the live files, even with &nudraft=1 in the address.
  • Publish draft makes the draft live. The files it replaces are kept as a version in _versions/.
  • Restore next to a previous version copies it back; the current files become a version first, so a restore can be undone the same way. The newest ten versions are kept.
  • Discard draft deletes the draft.
  • Shared by the draft and the live version: the page's data (_data/, $nu->dataDir()), secrets.php (a draft without its own reads the live one), the page settings and the database. A draft that needs new columns should add them so the live code keeps working.
  • Files and folders starting with a dot (.git, .htaccess) stay in the page folder and are never moved. Built-in pages have no draft unless you made your own copy of them in custom/pages/.
  • Every step is written to the log (Page draft created / published / discarded, Page version restored).
