Access levels

Which forms and buttons a user may use.

For: Users with rights on: nuaccess

Menu Access levels. An access level lists the forms a user may open and, per form, the buttons: Save, Add/New, Delete, Clone, Print. The row itself means "may view". Procedures need their own entry.

The form has two tabs: General (code, description, group, start form, two-factor login, the users with this level) and Form rights (the forms and their buttons; the badge shows how many). The open tab stays after Save and in the address (&tab=rights); an error opens the tab that shows it.

  • Use two-factor authentication: users of this level must confirm their login with a second factor – an authenticator app or a code by e-mail (hover or focus the icon for this hint). It needs $nuConfig2FAUser = true; the form shows whether it is on, and while it is off the globeadmin can switch it on there (Switch on, or a link to Settings when the settings table is used).
  • Reports: the reports users of this level may run (nuBuilder Forte's zzzzsys_access_report); the form shows how many are ticked. They are set on the report itself (see Reports).
  • Adding forms: pick one form from the list (type to search by code or description; forms already in the list are greyed out), or click Several…: search (code, description, table), filter by form group, type and own / nuBuilder Forte (4.x) system forms, tick the forms (or Select all shown) and choose the rights the new rows get – e.g. everything but Delete. Forms already in the list are hidden. Save afterwards.
  • Removing a form: crosses the row out – it is removed when you save the access level. Until then the same button () brings it back. The form builder's lists (tabs, list columns, events, columns of a new table, HTML attributes) work the same way.
  • Data mode and Form type per form (as in nuBuilder Forte 4.9, enforced): No changes to existing records opens existing records read only, without Save – the server refuses a save even from code (“Changes to existing records are not allowed”); new records, Clone and Delete follow their own rights. Browse only shows the list, but no record (also no new one: no Add, rows open nothing); Edit only opens records, but not the list (nor its export). The globeadmin and admin roles with change on the form are not limited.
  • Users card: the users with this level, by default only the active ones – Archived shows the users whose Valid until is in the past, All both (with counts).
  • An access level cannot be deleted while users still have it. Deleting it also removes its form, procedure and report rights; cloning copies them.

Additional access levels

A user has one main access level (nuBuilder Forte's sus_zzzzsys_access_id) and can get more in the user form (Users → Additional access levels), optionally until a date. nuBuilder Next stores them in its own table zzzzsys_nunext_user_access.

  • They only add: on a form a right counts when any level grants it (Save, Add, Delete, Clone, Print); browse and edit screen when any level allows them; No changes to existing records only when every level with the form says so. Procedures, reports and dashboards of every level are open to the user, and the forms list and the automatic start page show them.
  • From the main level only: the start page layout, list views, field data access rules by access level and the hash variables #ACCESS_LEVEL_ID# / #USER_GROUP_ID#.
  • Two-factor login is required when any active level asks for it.
  • Effective rights (button next to Add in the user form, shown once there is an additional level): a dialog with the combined rights as entered in the form – also before saving. Forms with View, Add, Save, Delete, Clone and Print (a form only an additional level grants is marked Additional, a tick only an additional level grants names it), procedures and reports with their levels; search, Only from additional levels, and Copy (tab-separated, e.g. into a spreadsheet). Expired levels are shown crossed out and not counted.
  • Admin rights: with Only the globeadmin grants admin rights (Security check) a level with rights on admin forms can only be added by the globeadmin, nobody changes the additional levels of his own account or the rights of a level he holds, and users with such a level can only be changed by the globeadmin.
  • The Users card of the level lists these users with the badge Additional (an expired one under Archived); a level that is still in use as an additional level cannot be deleted. Changes are written to the log (User changed, field access_extra:<code>).
  • nuBuilder Forte 4.x does not know the table: there the user has only the rights of the main level. The Compatibility check lists these users (G10).
