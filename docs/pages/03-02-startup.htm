Startup and configuration

What happens before a page runs: nuconfig.php, security headers, the session and housekeeping.

For: Administrators (globeadmin, admin roles)

core/nuapp.php is loaded first by index.php, api.php and cron.php (dbadmin.php deliberately not – Adminer's functions would clash). It defines the helpers and loads most classes only when they are first used. nu_boot() then prepares the request:

  1. Configuration – nuconfig.php is read on every request (nu_config(), values through nu_cfg('…')). Without it, a setup hint is shown.
  2. Security headers – a strict Content-Security-Policy (only own scripts, styles and fonts). Pages that run form code allow inline scripts, because forms contain admin-written JavaScript; chart forms also allow Google's chart host, and $nuConfigIncludeJS / $nuConfigIncludeCSS from other hosts are added.
  3. Session – PHP session named nunext, cookie only for nuBuilder Next's folder (another copy on the same domain has its own), HttpOnly, SameSite=Lax, Secure under HTTPS, strict mode. PHP keeps idle sessions at least as long as the longer of the two time-outs.
  4. Time zone of the installation.
  5. Housekeeping – without cron, a page view now and then removes expired tokens and sessions, old log rows and temporary files (see Housekeeping).
  6. Error handler – unexpected errors are logged to PHP's error log; the user sees a short message (details only with $nuConfigDebug = true).

nuBuilder's own include files ($nuConfigIncludePHP) are loaded only when form PHP runs, so lines copied from nuBuilder's nuconfig.php work unchanged. All variables are listed on Configuration (nuconfig.php).
