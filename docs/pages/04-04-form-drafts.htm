Drafts and publishing

Changing a form in a draft, previewing and publishing it.

For: Users with rights on: nuform

A form can be changed in a draft: users keep working with the live form until the draft is published in one step. Design mode's bar shows whether a draft is open and how many changes it holds.

  • A draft starts with the first change in design mode (a form that was never published is changed directly): it copies the complete form definition – form settings, tabs, objects, events, PHP hooks (also of lookups), list columns and SQL builder selects. One open draft per form; the forms list shows it as Draft · author (filter With a draft).
  • Working in the draft: everything works as on the live form; every change is written into the draft only. Undo in the draft bar goes back step by step (last 20 saves). New table columns are created at once (the table is shared with the live form) and listed when publishing.
  • Preview: opens the form as the draft – only for you, with a yellow banner (Leave preview ends it). Forms the draft opens that have a draft of yours too are shown as drafts as well. By default the preview is read-only; when saving is allowed (draft setting, default from the security setting below) Save and Delete change the live data after a confirmation.
  • Changes (button in the design bar): the draft compared with the published form – what changed – form settings, tabs, objects (added, removed, changed, moved), events, PHP and JavaScript line by line, list columns, SQL builder.
  • Publish…: a note, the summary of the changes and the checks (errors such as a missing table column stop it; warnings need a tick). The live form is saved in the history first (before publish), then replaced in one transaction and stored as published vN – note. Versions are never removed by the history's limit.
  • Conflict: when the live form was changed after the draft was started, Publish shows it; publishing anyway needs the form code typed in and overwrites those live changes.
  • Discard deletes the draft; the live form is not touched. Two windows on the same draft: the second save is refused and design mode reloads.
  • Rights: anybody who may change the form may start and edit a draft; publishing needs the globeadmin or the admin right Publish forms (drafts) (see Admin roles).
  • Only through drafts (security setting): design mode then works in a draft for every published form, and new forms start as drafts (status Draft: only form designers can open them until they are published). The globeadmin may still change a form live after a confirmation. While a draft is open, changing the form live asks first, and deleting the form is refused.

Drafts are stored in zzzzsys_nunext_form_draft; nuBuilder Forte (4.x) itself only ever sees the published form.
