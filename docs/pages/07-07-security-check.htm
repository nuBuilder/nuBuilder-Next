Security check, server rules and housekeeping

Advanced Security settings, web server rules, cron and the checklist for a live server.

For: Administrators (globeadmin, admin roles)

Admin tools → Security check (index.php?p=securitycheck, globeadmin) shows what matters for the security of this installation as traffic lights – red: fix it soon, yellow: check it, blue: for information – each with a link to the place where it is fixed. A click on the badge Problem, Check or OK shows only those checks; a second click shows all again:

  • HTTPS, $nuConfigBaseURL, $nuConfigSecretKey (and authenticator secrets stored before the key existed), the globeadmin password (nu or shorter than 8 characters) and its two-factor login, $nuConfigDebug, PHP's display_errors, the PHP version (red while it lacks the fix for PHP2Shell, CVE-2026-109618 / CVE-2026-109619 – fixed in PHP 8.2.35, 8.3.36, 8.4.27 and 8.5.12; PHP 8.1 and older get no official fix. Linux distributions and hosts sometimes backport the fix without changing the version number: then check their security notice and ignore the red point), $nuConfigApiAllowHttp, demo mode, auto-login links and one-time login tokens;
  • users with old md5 passwords, access levels with admin-equivalent rights (see How rights work), hash variables outside quotes (see Compatibility check);
  • whether Records only through the form's list and Do not save read-only and hidden fields are on (orange while off – new installations switch both on, existing ones keep their setting), and whether the upload procedure nu_upload_file_template still stores files in the web root (red);
  • the last housekeeping run, the log retention, the backup folder, and the versions of the libraries taken from nuBuilder Forte (4.x) (TCPDF, PHPMailer, TinyMCE, phpMyAdmin, Tiny File Manager) against the first version without the vulnerabilities known at the time of the release;
  • Files on the web: your browser requests files that the web server must never hand out – README.md, nunext-manifest.json, install/*.sql, docs/, _backup/, temp/ and PHP files of core/ / lang/ (they answer with an empty page). Red means the web server ignores nuBuilder Next's .htaccess files.

Built in (no setting)

  • Login rate limit: 5 failed logins (or wrong second-factor codes) for a name from one address, 20 for a name from anywhere or 30 from one address within 15 minutes lock further attempts – counted in the log, so a client without cookies cannot reset it. Auto-login links, one-time login tokens and the password confirmation count too.
  • "Forgot password" sends links only to $nuConfigBaseURL or, while that is empty, to the address the globeadmin last used – never to the host name of the anonymous request (a forged host name would send the reset link to someone else's server). At most 10 requests an hour per address and 3 links an hour per user.
  • Sessions: the cookie belongs to the nuBuilder Next folder; a login is bound to this folder and database, and a globeadmin login ends when name or password change in nuconfig.php. Strict session ids, Secure cookies also behind a proxy that ends TLS ($nuConfigTrustProxy + X-Forwarded-Proto); with $nuConfigTrustProxy the client address is the last X-Forwarded-For entry (the one your proxy adds).
  • Headers: Content-Security-Policy, X-Frame-Options, Permissions-Policy, Cross-Origin-Opener-Policy, and Strict-Transport-Security on HTTPS.
  • Log: passwords, keys, tokens and password hashes are written as ••• in the record changes.
  • Demo mode: password hashes and secret columns show as ••• in forms, lists and the hash viewer; the SQL builder cannot read zzzzsys_user, sessions, setup, settings or nuBuilder Next's tables.
  • Hash variables in SQL are escaped for the database's mode (also MySQL's NO_BACKSLASH_ESCAPES); they are safe inside quotes only – the Compatibility check lists places without quotes.
  • Update packages are signed (Ed25519); the update page shows Signed by nuBuilder Next, warns for unsigned packages and refuses a package whose signature does not match.
  • Messages and titles: nuSetTitle, nuSetLabelText and nuMessage keep HTML but remove script – <script>, on… attributes, javascript: links – so a record value shown in a title cannot run in another user's browser. Form code that puts onclick buttons into a message can call nuNextSafeHtml(false) on that page; nuSafeHtml(html) cleans HTML for your own code.
  • Images of forms: ?p=file serves a file that image objects show only to users who can open one of those forms (or a form with such a form as sub-form); files without an image object (nuAttachImage, report images) stay open to every signed-in user, as in nuBuilder Forte.
  • No folder listings: the root .htaccess hides the files of folders without an index page (IndexIgnore); _install/ gets a deny-all .htaccess in the package.
  • Package files: every PHP file of core/, pages/ and lang/ ends at once when called directly; .htaccess files block core/, pages/, lang/, install/, docs/, dev/, _backup/, _install/, temp/ and the notes in the main folder (Apache 2.2 and 2.4). TODO.md, CLAUDE.md and dev/ are no longer part of the installed package.

Web server rules

Apache reads the .htaccess files only with AllowOverride All (Debian / Ubuntu's default for /var/www is None). nginx ignores them. Add rules like these (path of your installation), then run the Security check again:

# Apache: virtual host or apache2.conf
<Directory /var/www/html>
	AllowOverride All
</Directory>

# nginx: server block
location ~ ^/nunext/(core|pages|lang|install|docs|dev|_backup|_install|_update|_libsrc|temp|custom|lib|apps)/ { deny all; }   # apps/: built-in pages   # custom/: page forms
location ~ ^/nunext/(README\.md|CHANGELOG\.md|LICENSE|TODO\.md|CLAUDE\.md|nunext-manifest\.json|nuconfig.*\.php|cron\.php)$ { deny all; }
location ~ /NUNEXT-VERSION\.txt$ { deny all; }
location ^~ /nu_uploads/ { deny all; }   # only when the upload template had to create its folder inside the web root
# library packs: vendor/packs/ is closed except the browser packs; vendor/nuconfig.php is covered by the nuconfig rule above
location ~ ^/nunext/vendor/(nuconfig\.php|packs/(nunext-libs\.php|index\.html|[^/]+/nunext-lib\.json))$ { deny all; }
location ~ ^/nunext/vendor/packs/(tcpdf|phpmailer|adminer)(-[^/]*)?/ { deny all; }
location ~ ^/nunext/third_party/((tcpdf|phpmailer|adminer)(-[^/]*)?/|[^/]+/nunext-lib\.json$) { deny all; }   # packs of older versions
# browser cache (Apache: assets/.htaccess and vendor/bundled/.htaccess do it) – files with ?v= never change under their URL
location ^~ /nunext/assets/ { expires 7d; if ($arg_v) { expires 1y; add_header Cache-Control "public, immutable"; } }
location ^~ /nunext/vendor/bundled/ { expires 7d; if ($arg_v) { expires 1y; add_header Cache-Control "public, immutable"; } }

Browser cache: every script, stylesheet and picture of nuBuilder Next is loaded with a version in its address (?v=…), so assets/.htaccess lets browsers keep it for a year without asking again (immutable); after an update the address changes and the new file is loaded. Files without a version (fonts, pictures of a stylesheet) are kept for a week. Needs Apache's mod_headers / mod_expires (without them nothing changes); nginx: the rule above.

Even better for backups: $nuConfigBackupPath outside the web root.

Housekeeping (cron)

cron.php removes expired tokens and sessions, old API counters, log entries beyond Keep the log, PDFs of the REST API whose download link expired and temporary files older than a day, and sends the waiting webhook calls again (every 5 minutes is a good interval when you use webhooks). Run it as the web server's user, e.g. every 15 minutes:

*/15 * * * *  sudo -u www-data php /var/www/html/nunext/cron.php > /dev/null

Without cron a page view does it now and then (as before); once cron has run in the last 25 hours, page views leave it to cron. The web server never runs cron.php.

Checklist for a live server

  1. HTTPS only; $nuConfigBaseURL set; $nuConfigTrustProxy only behind your own proxy.
  2. A long globeadmin password, $nuConfig2FAAdmin = true and a globeadmin e-mail or authenticator.
  3. $nuConfigSecretKey set (API clients page → Generate key).
  4. $nuConfigDebug = false, PHP display_errors = Off, PHP 8.2 or newer.
  5. Files on the web all green; backups outside the web root.
  6. Admin-equivalent rights only for people who may change code and users.
  7. A log retention and cron for the housekeeping.
  8. Demo mode only with a demo database.
