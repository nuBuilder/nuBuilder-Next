Settings

Advanced Every setting of the installation in one place – sections, a search, and nuBuilder Forte's settings table (Setup → Settings).

For: Administrators (globeadmin, admin roles)

The settings centre

Admin tools → Settings opens an overview of all sections; a side bar on the left leads to them and stays on every settings page. Each user sees the sections of the admin rights he has (an admin role with the right Settings, Branding, E-mail … – see admin roles):

  • General: the languages of the installation, the setup wizard, nuBuilder Forte's settings and the configuration file.
  • Look: the side bar for everyone (for users without an own choice), Branding and Themes (their own pages, drawn inside the settings frame), the start page layouts and the start pages of users.
  • Sign-in & security: the Security check with its settings.
  • E-mail: the e-mail settings (server, sign-in, OAuth 2, sender, test).
  • Data & logs: audit trail (record changes, how long, what not), how long notifications are kept, backups (SQL dumps of the newest backups, the clean-up rule), and links to how long the log is kept and to the demo data. The same settings stay on their own pages (audit trail, notifications, update page) – both places change the same values.
  • Code & includes: Global code (global JavaScript and CSS, nuBuilder Forte's Setup header, style and include).
  • Updates & libraries: update from GitHub (repository, automatic check, pre-releases), the update page, library packs and the integrity check.
  • nuBuilder Forte: the settings table described below.
  • Configuration file: the nuconfig.php editor.

Search: the field above the sections (or the key /) searches every setting – the ones on these pages, the security settings, nuBuilder Forte's settings and the variables of nuconfig.php – by title, setting name and description, with the current value where it is no secret. ↑ / ↓ and Enter open a result: the page scrolls to the setting and marks it; a nuBuilder Forte setting opens the list filtered to it, a nuconfig.php variable selects its line in the editor. The start page tile Settings lists the sections under ▾; each step of the setup wizard links to its section (Show in Settings).

Languages of the installation

The card Languages (section General) lists the eleven languages of nuBuilder Next. Only the ticked ones are offered – in the language menus, on the sign-in page, in the user form (Language) and in the setup wizard; a link or a stored user language that is not ticked shows the default language instead (German, else English, else the first ticked one). The number next to a language counts the users who have chosen it. Save languages stores the choice (logged): a language ticked now gets its welcome e-mail template at once, the built-in templates of languages taken away are deleted (own templates stay), and the users of a removed language are named in the message. At least one language stays ticked. The installer sets the first choice (step Options, Languages to include); installations from before keep all eleven. With one language without variants the language menu is hidden.

On screens narrower than 800 px the column Description is hidden; the (i) next to a setting's title shows its description on tap or click.

Admin tools → Settings (globeadmin) edits nuBuilder Forte's settings table zzzzsys_config – the same rows as nuBuilder Forte's Setup form. $… settings are PHP variables of nuconfig.php; the others are JavaScript options (nuUXOptions['…']).

While $nuConfigSettingsFromDB is not true, a notice above the list says the settings are not used; its button Use these settings sets $nuConfigSettingsFromDB = true; in nuconfig.php after a confirmation (same checks and backup as Configuration file) and reloads the page.

  • Search (title, setting, value, description), category, and filter buttons with counts (All · Used · Not yet · Not needed) by what a setting means for nuBuilder Next. The page opens with Used (after a save with errors: All, so every field with an error is visible). Each of nuBuilder Forte's settings has a tag after its title (the reason on hover): Used – nuBuilder Next reads it ($nuConfig2FAAdmin, $nuConfig2FAUser, $nuConfigDemoSavingAllowedIds, $nuConfigIsDemo, $nuConfigGlobeadminHome, $nuConfigIncludeApexCharts, $nuConfigTitle, nuDebugMode, nuHideTabTitleIfOnlyOne); Not yet – not built yet, only nuBuilder Forte (4.x) uses it for now (e.g. sticky browse headers, close after save, user form labels, keep session alive); Not needed – nuBuilder Next has its own solution or it is always on (form title icons → ⋮ menu, updater and backups, session timeouts, keeping the session alive (sessions end only after the inactivity timeout; every click counts), two-factor e-mail code, Ace / Select2 themes, TinyMCE and Google Charts loaded automatically). The list is NuSettings::STATUS in core/nusettings.php. $nuConfigTitle (as in nuBuilder Forte) names the application: it replaces "nuBuilder Next" in the browser tab ("Forms · title") and appears above Sign in on the login page. true / false settings are a selection, numbers a number field, the Ace theme a list of themes; known values are suggested.
  • Changed values are marked and Save turns red; only changed values are stored and logged (Settings changed). marks settings nuBuilder Forte applies only after a new login or a browser restart.
  • Import copies the values set in nuconfig.php into the table (as nuBuilder Forte's Import button): PHP variables and nuUXOptions['…'] = …; lines (also inside nuBuilder Forte's $nuJSOptions); commented lines are skipped, settings that nuconfig.php does not set stay as they are. Only possible without unsaved changes.
  • If the table is missing (database set up with nuBuilder Next's own install scripts, older nuBuilder Forte), the page names the database and the database's message and offers Create settings table: the table as in nuBuilder Forte with nuBuilder Forte's default settings. The installer now creates it too.
  • The table is used only with $nuConfigSettingsFromDB = true in nuconfig.php (nuBuilder Forte's setting): its values then replace those of nuconfig.php – in nuBuilder Next from the next page on, as typed values (no eval). Database access, $nuConfigSecretKey and the switch itself always come from nuconfig.php.
