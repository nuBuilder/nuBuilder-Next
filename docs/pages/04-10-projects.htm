Projects

Keep the forms, procedures, reports and tables of one piece of work together – with notes and to-dos – and move them to another installation as one file.

For: Developers (globeadmin, admin roles with the right Projects, users who may change forms)

An application grows: an order system soon has a dozen forms, procedures for its buttons, reports, SQL queries and e-mail templates. A project lists the parts that belong together. The parts stay where they are – a form can belong to several projects, and removing it from a project changes nothing else. Open the projects from the start page tile Projects (index.php?p=projects). The ticket system sample comes with a project to look at.

Parts

  1. Projects → Add: a name, optionally a code (letters, digits, _ . -; made from the name when empty) and a description.
  2. Tab Parts → Add parts: choose the kind – forms, procedures, reports, SQL queries, tables, e-mail templates, snippets or help pages – search and tick. Picks of several kinds and searches are added together.
  3. Suggest related lists what the parts already in the project use and is not in it yet: the sub-forms, lookups and run buttons of a form, its table and the tables of its list SQL, procedures and reports named in its code, the launch form and data source of a report, the tables of an SQL query. Untick what does not belong and add the rest.

Each part links to its editor (form in design mode, procedure, report …) in a new tab. A part deleted elsewhere stays in the list, marked No longer exists here, until you remove it.

Notes and to-dos

Notes are written in Markdown (**bold**, lists with -, `code`, links). A pinned note is shown on the Overview.

A to-do has a title, optionally details, a user it is for, a due date and the part it is about. The user gets a notification (the bell) when the to-do is given to them, and again on the day it is due. Tick it on the Overview or the To-do tab when it is done. Your own open to-dos of all projects are listed above the list of projects.

The Overview also shows the recent changes of the project's forms from the form history and their open drafts.

Working on a project

Work on this on the project page narrows the lists of forms, procedures, reports, SQL queries and e-mail templates to the project's parts – their filter Project is set for you. Choose another project or none in that filter to see more; Stop working on it ends it. The choice lasts until you sign out and only affects you.

Export and import

Export writes one JSON file with the project, its notes and to-dos and its parts: forms with their tabs, objects, list columns, events and code, procedures, reports, SQL queries with their clauses, e-mail templates, snippets, help pages and the structure of the tables. Package with table rows (globeadmin only) also contains the rows of the tables, up to 20,000 per table.

Import project (globeadmin) reads such a file and shows each part with its state here – new, the same, different, exists, conflict – and what will happen. Nothing changes before you confirm:

  • New parts are added with their ids. A form that exists and differs is replaced only when you choose Replace; its version before the import stays in the form history, so you can go back.
  • A form whose code another form already uses is skipped. An open draft of a replaced form stays and may conflict when it is published.
  • Tables that exist here are never changed. New tables (and views) are created on MySQL / MariaDB only, with their rows when the package has them.
  • A project with the same code gets the new parts; its notes and to-dos stay. Otherwise a new project is made with the package's notes and to-dos.

Access rights are not part of a package: give the access levels their rights on the new forms, procedures and reports afterwards (Access levels). Back up the database before a larger import (Backups).

Who may do what

Viewing projects needs the admin right Projects (view) or the save right on the Forms form; changing them the right Projects (change), the save right on the Forms form or the globeadmin. Import and the export with table rows are for the globeadmin. Projects are stored in nuBuilder Next's own tables; nuBuilder Forte does not see them.
