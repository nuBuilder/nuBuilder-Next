Data export

Advanced Saved exports of tables, views and queries to Excel or CSV – and the same exports through the REST API.

For: Administrators (globeadmin, admin roles with Data export)

Admin tools → Data export (also Forms → Tools; index.php?p=dataexport) keeps a list of exports that can be run again and again. The admin right Data export decides who may use it: view = run the saved exports, change = create and edit them. It is a full-access right, because any table of the database can leave the server this way. The counterpart for the other direction is the Data import.

An export

  • Name, code, description. The code (letters, digits, _) names the export in the REST API; it is made from the name when left empty.
  • Format: Excel (.xlsx, one sheet per dataset) or CSV (one file; several datasets become a ZIP with one CSV each). CSV options: separator, line ends (CRLF for Excel / LF), UTF-8 BOM, header row, text for NULL, date and date-time formats, decimal separator, yes/no values and the protection against formulas (a text starting with = + - @ gets a leading apostrophe – switch it off for files that go into another system).
  • File name with the placeholders {code}, {name}, {date}, {time}, {datetime}; empty = {code}_{date}.
  • Datasets – one or more; each becomes a sheet or a file and is one of:
    • Table or view: tick the columns and put them in order (↑ ↓), give them a heading and a format, add conditions (type-aware operators – contains, between, one of, is empty, yes / no …; all or any of them) and sort columns. System tables (zzzzsys_…) are offered but marked; columns that look like a secret (password, token, key) are exported only when ticked. For re-import puts the key column first and uses the column names as headings, so the file can be edited in Excel and loaded with the Data import, which updates the rows by their key.
    • Query (SQL): one SELECT (or WITH … SELECT) in the code editor. #name# placeholders are asked for every time the export runs – quoted or not, the values go into the query as parameters; #USER_ID#, #TODAY# and the other system hash variables are filled in. Check query tells whether it is accepted and which parameters it has; after a Preview the result columns are listed for headings and formats.
    • SQL builder query: a saved query of the SQL builder, used as it is.
  • Preview shows the first 20 rows as they will be exported; Count rows the number of rows.

Values and formats

Values are taken raw from the database and typed by the column: integers and decimals become numbers, bit / tinyint(1) yes/no, dates and date-times real Excel dates, everything else text – so a text column keeps its leading zeros. A number with more than 15 digits and a date before 1900 are written as text (Excel could not show them exactly). Excel formats per column: a choice by type (#,##0.00, dd.mm.yyyy …), text or any format code of your own; the default is by type. Formats never change the stored value. Text is never written as a formula.

Exports are streamed: rows are written to the file while they are read, so the size of a table does not matter. An Excel sheet that reaches Excel's row limit (1,048,576) continues on "name (2)". The query runs in a read-only transaction.

Running, moving and the REST API

  • Run in the list or on the export builds the file and downloads it; an export with parameters asks for them first. Every run is written to the Log (Data export run: code, format, rows per dataset, duration – never the data), and the export shows its run count and last run.
  • Download definition (JSON) saves the export as a file; Upload definition in the list creates it on this or another installation (a taken code gets a suffix). Duplicate copies an export.
  • REST API (scope exports:run; the client's service user needs the admin right Data export): GET /v1/exports lists the exports with their parameters, POST /v1/exports/{code}/run with {"params": {"name": "value"}} answers with the file itself (Content-Disposition, X-Export-Rows). See REST API.
