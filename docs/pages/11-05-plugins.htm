Plugins

Extensions written by other developers: a folder of PHP code that adds pages, tiles, rights, events and REST routes.

For: the globeadmin (installing) and developers (writing plugins)

A plugin is a folder plugins/<id>/ with a plugin.json (name, version, what it needs) and a plugin.php. Its PHP talks to nuBuilder Next only through one object, $plugin – a fixed interface with a version number, so a plugin keeps working across updates. Plugins change nuBuilder Next only: nuBuilder Forte on the same database does not see them, and a plugin's data goes into tables of its own.

A plugin runs with full rights, like a procedure: install only plugins whose author you trust. The signature, the check before installing and the safe mode below limit the risk, but cannot remove it.

Installing and switching on

  1. Copy the folder to plugins/ on the server (FTP, SFTP, file manager of the host). This works always and is the safer way.
  2. Or upload the package (a .zip) on Update → Plugins. Uploading is off until you switch on Allow uploading plugins on that tab – switch it on only while you install, so no PHP code can arrive through the browser otherwise. Check package shows the plugin's name, version, signature, tables and what it needs before Install; a newer version replaces the installed one (a plugin that was on stays on).
  3. Switch on in the list. The plugin must fit this installation (plugin API version, nuBuilder Next version, PHP version and extensions, MySQL or SQL Server); a plugin without a signature asks once more.

The list shows every plugin with its version, its status (On, Off, Switched off after an error with the message) and its signature. Settings appears for plugins that have settings. Remove deletes the folder; with Also delete its tables and stored data its tables (zzzzsys_nunext_plg_<id>_…), stored values and data folder go too.

Signatures, errors and safe mode

  • Signature: a signed plugin lists the hash of every file in plugin.json, signed with an Ed25519 key. Keys nuBuilder Next trusts: its own and the keys you add under Trusted signing keys. Files changed since signing = the plugin cannot be switched on. Not signed or Signed with a key that is not trusted here = allowed after a question (add the developer's key to trust it).
  • Errors: a plugin whose code throws an error – or ends PHP with a fatal error inside its folder – is switched off at once and the error is logged (Log, event Plugin switched off after an error); the page goes on without it. Switch it on again after the author fixed it.
  • Safe mode: ?safe=1 at the end of an address loads no plugin on that page (globeadmin only).
  • Locked out: php nucron.php plugins off switches every plugin off from the server's command line (plugins off <id> one, plugins list, plugins on <id>).
  • Updates never touch plugins/. Check package on the update page lists the plugins the new version would stop because it no longer supports their plugin API version.
  • Admin rights: rights a plugin adds appear in the admin roles in the group Plugins; a plugin's REST routes need the scope plugin:<id> of the API client.

Writing a plugin

The example plugin of the development package (dev/plugin-skeleton/) uses every part below: copy it to plugins/<your id>/, change the id in plugin.json and switch it on.

{
  "id": "notes",                    // = the folder: a–z, 0–9, _, starting with a letter, up to 20
  "name": "Notes",
  "version": "1.0.0",
  "description": "Short notes for the team",
  "author": "…", "url": "https://…",
  "api": 1,                         // plugin API version it was written for
  "requires": { "nunext": "…", "php": "8.1", "extensions": [], "db": ["mysql", "sqlsrv"] },
  "tables": ["notes"],              // short names – removed with "also delete its data"
  "network": false                  // shown before installing: does it call other servers?
}

plugin.php runs once per request while the plugin is on, with $plugin in scope. It registers what the plugin adds; the work happens in the functions it registers:

<?php
declare(strict_types=1);
/** @var NuPluginApi $plugin */
$plugin->right('use', $plugin->t('right_use'));
$plugin->route('main', fn(array $req) => '<p>' . h($plugin->t('hello')) . '</p>', ['title' => $plugin->t('title'), 'right' => 'use']);
$plugin->tile('main', ['label' => $plugin->t('title'), 'icon' => 'bi-sticky', 'route' => 'main', 'right' => 'use']);
$plugin->on('record.before_save', fn(array $e) => str_contains(json_encode($e['values']), 'forbidden') ? 'Not saved: forbidden word.' : null);

js($file, $where) · css($file, $where) · asset($file)Files of assets/ on every page (app), the form pages (form) or both (all); the address of such a file. The strict Content-Security-Policy applies: no inline scripts or styles in the plugin's HTML.

dataDir()A folder for files (custom/plugindata/<id>/, closed to the web, kept by updates).
api($method, $pattern, $fn)A REST route api.php/v1/plugins/<id>/<pattern> (items/{item}); $fn($parts, $body) returns the answer or [status, body, headers]. Scope plugin:<id>; it runs as the client's service user.
task($name, $fn)A task for the server's cron: php nucron.php plugin <id> <name> [name=value …] (runs as the globeadmin).

log($event, $details) · user() · csrfField() · path($file) · nunext()A log entry, the signed-in user, the form token for its POST forms (every POST is checked), a file of its folder, nuBuilder Next's version and plugin API version.

The record events run for saves of forms (also through the REST API and the calendars) after the validation rules and the hook procedure nu_before_save, before the form's Before Save / Before Delete.

Signing and packaging

  1. php dev/plugin_sign.php --keygen my-plugins.key once: the secret key into the file (keep it), the public key printed – the installations add it under Trusted signing keys.
  2. php dev/plugin_sign.php plugins/notes my-plugins.key --zip=notes-1.0.0.zip after the last change: hashes and signature into plugin.json, and the package to upload.

The interface keeps its methods within a plugin API version: new methods may be added, none is changed or removed. A new version is announced (marked as outdated on the update page) before an older one is dropped.
