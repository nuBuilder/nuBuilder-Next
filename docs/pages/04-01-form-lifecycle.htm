Form lifecycle and event order

Advanced Which PHP hooks and JavaScript functions run, and in which order, when a list or a record is opened, saved or deleted.

For: Users with rights on: nuform

The same hooks as in nuBuilder Forte 4.9 run, in the same order. PHP hooks run on the server and can stop the step with an error (nuDisplayError()); JavaScript hooks run in the browser, and a hook that returns false cancels the action.

Opening a list

  1. PHP: global hook nu_before_save (as in nuBuilder Forte (4.x) it also runs before every Before Browse), then the form's Before Browse.
  2. Server: the list query (browse SQL with search, filters, sort and paging) runs; the page is drawn.
  3. JavaScript: nuLoadBrowseGlobal() (Setup → Header), then the form's nuOnLoad(formId, formCode), then nuOnPageLoad(page, info) and the event nu:pageload of Global JS (page hook).

Opening a record

  1. Server: the record is loaded (a new record has the id -1).
  2. PHP: global hook nu_before_edit, then the form's Before Edit. nuSetFormValue() here changes what is shown; nuAddJavascript() adds code for the browser.
  3. Server: objects are drawn; field data access is applied.
  4. JavaScript: scripts inside HTML objects, then nuLoadEditGlobal(), then nuOnLoad(formId, formCode). Values set while loading do not mark the form as changed.
  5. JavaScript: after a save that reloaded the form, nuAfterSave() / nuAfterSaveGlobal().

Saving

  1. JavaScript: nuBeforeSaveGlobal(), then the form's nuBeforeSave() – false cancels.
  2. Server: concurrent-edit check, validation of required / unique fields and masks.
  3. PHP: global hook nu_before_save, then Before Save – nuDisplayError() stops the save; #nuFORMdata# holds the posted values.
  4. Server: one transaction writes the record and its sub-form rows and records the audit trail.
  5. PHP: After Save (#RECORD_ID# is the saved record; nuReturnNewRecord() opens another one).
  6. JavaScript: the form reloads; nuOnLoad(), then nuAfterSave() / nuAfterSaveGlobal(). Save & Close: nuCloseAfterSaveGlobal() returning false keeps the form open.

The server side in detail: How a save works.

Deleting

  1. JavaScript: nuBeforeDelete() – false cancels.
  2. PHP: Before Delete – an error stops the delete.
  3. Server: the record and its sub-form rows are deleted in one transaction (audit trail).
  4. PHP: After Delete; JavaScript: nuAfterDelete() / nuAfterDeleteGlobal().

Other events

  • Lookups: the lookup's After Browse PHP runs when a row is chosen (nuLookupRecord()); in the browser nuOnLookupPopulated() / nuOnLookupPopulatedGlobal().
  • Procedures started from the browser (nuRunPHPHidden(), run objects) run with the current form's hash.
  • Object events (onchange, onclick, onblur …) are the JavaScript of zzzzsys_event rows, bound when the form loads.
  • More hooks the runtime calls when a form defines them (formatting, calendars, selects, popups, messages, action buttons): see the Function reference, group hooks.
