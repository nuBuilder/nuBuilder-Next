Password policy

Rules for new passwords, a check against known leaked passwords and – only where required – a regular change.

For: Administrators (globeadmin, admin role right Security check)

Settings → Sign-in & security → Password policy (index.php?p=pwpolicy) applies wherever a password is set: the user form, Change password, the reset link, the welcome e-mail link and the REST API. Below each of these password fields a checklist shows the rules and ticks them while typing; breaking a rule names all broken rules at once. nuBuilder Forte's hook procedure nu_check_password_policy still runs afterwards. Changing the policy asks for the password again.

Rules

  • Minimum length – empty uses $nuConfigPasswordMinLength from nuconfig.php; the higher of the two counts. 12 characters or more is the current recommendation – length protects better than special characters. At most 72 bytes (bcrypt).
  • Character classes (upper-case, lower-case, digit, special character) – off by default. NIST SP 800-63B and the BSI advise against such rules: they lead to predictable passwords such as Summer2026!.
  • Not the login, the name or the e-mail name (parts of 4 characters or more) – on by default.
  • Known leaked passwords – Online asks Have I Been Pwned with k-anonymity: only the first 5 characters of the password's SHA-1 hash are sent to api.pwnedpasswords.com, the answer lists hundreds of hashes and the comparison happens on the server – the password never leaves it. Offline uses the list of the 10,000 most common passwords that comes with nuBuilder Next. The default uses the online check and falls back to the list when the server cannot reach the service.
  • Also check at sign-in – a user whose password is found in a leak must choose a new one right after signing in. The result is remembered for 30 days per password, so the sign-in stays fast.

Regular change

Off by default (never), as current best practice recommends: change a password when it is leaked, not on a calendar. Where a rule of your organisation requires it, choose 30 – 365 days for all users and, under Per access level, another interval for the users of a level (with several access levels the shortest one counts). The age is counted from the last change (PASSWORD_CHANGED_TIME, as nuBuilder Forte stores it); a user without a recorded change starts counting at the next sign-in. Within the reminder time (7, 14 or 30 days) users see a note with a link to Change password after signing in; an expired password must be changed right after signing in.

The globeadmin's password is set in nuconfig.php ($nuConfigDBGlobeadminPassword), so it only gets a reminder after signing in – with a link to the nuconfig.php editor – and never a lock-out. Its age counts from the day nuBuilder Next first saw the password; a leaked globeadmin password is reported the same way.

Try a password

The card at the end checks a typed password (and optionally a login) against the current rules, including the leak check. Nothing is stored or logged.
