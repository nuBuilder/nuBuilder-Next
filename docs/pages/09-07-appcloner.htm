App cloner (copy the whole application)

Advanced Test and development copies of the whole application.

For: Administrators (globeadmin, admin roles)

Admin tools → App cloner (globeadmin, MySQL / MariaDB or SQL Server – source and target are the same kind) copies the whole application – e.g. for a test or development copy:

  • Database: into another database on the same or another server (it can be created). Choose what is copied: nuBuilder Forte (4.x) system tables and views, own tables and views, system records (nu…), application records (forms, users …), data of own tables, functions, procedures, triggers, events – all tables or chosen ones. When the target is not empty: stop, add to it, or empty it first. Sessions and one-time tokens (password reset links) are left out by default.
  • Files (optional): the nuBuilder Forte folder – with nuBuilder Next inside – into another folder; folders to leave out (e.g. .git, backups) can be listed. The database settings in the copied nuconfig.php files are changed to the target database.
  • 1:1 copy (MySQL / MariaDB): tables exactly as SHOW CREATE TABLE gives them (engine, row format, partitions, collations per column, comments, generated columns, AUTO_INCREMENT values), all indexes (unique, prefix, descending, ignored / invisible, fulltext, spatial), CHECK constraints and foreign keys (ON DELETE / ON UPDATE), MariaDB sequences with their current value, every row byte for byte (binary data, BIT, geometry, JSON, emoji, zero dates), views in dependency order after the functions they may call, functions and procedures with their own sql_mode, triggers in their execution order (FOLLOWS / PRECEDES) and events with their time zone. Like mysqldump the copy runs with sql_mode = 'NO_AUTO_VALUE_ON_ZERO' only, so also data a strict server would refuse (zero dates, old ENUM definitions) arrives unchanged. Not copied (they do not belong to the database): users and privileges; DEFINER becomes the target's user. An object that cannot be created is a warning in the log – the rest is still copied.
  • Live database (MySQL / MariaDB): all tables are read in one consistent snapshot (START TRANSACTION WITH CONSISTENT SNAPSHOT, as mysqldump --single-transaction) – a record saved while the clone runs is either completely in the copy or not at all (InnoDB tables; MyISAM tables have no snapshot). Each table is read once with one streaming query, so large tables are not slower towards the end. TIMESTAMP values are read and written in UTC (time_zone '+00:00'), so a copy to a server in another time zone keeps the same moments. INSERT statements are at most about 1 MB (and at most half of the target's max_allowed_packet), so tables with large BLOBs no longer break the copy or the import; a single row larger than max_allowed_packet is reported as a warning and the clone goes on. The rows of a table are written in one transaction; the SQL file wraps each table in SET autocommit = 0 … COMMIT and DISABLE KEYS / ENABLE KEYS, which makes the import noticeably faster.
  • Dry run shows every step and how many rows and files would be copied, without changing anything. Run asks once more and shows the log while it runs; at the end the record counts of source and target are compared.
  • Download SQL exports the database as an SQL file instead – for an import with phpMyAdmin elsewhere. On shared hosting, where PHP cannot create databases, create the database in the control panel and use Add to it, or import the SQL file.
  • Safety: the target can't be this database, the target folder can't be inside the nuBuilder Forte folder (or the other way round), and nothing outside the target is deleted. DEFINER is removed from views and routines so they work with another database user; routines the user may not read are reported. The password of the target is not stored.
  • Saved configurations: the App cloner opens with a list of saved configurations (with a search once there are more than ten) – Add opens a new one with code and description; Save, Clone (an unsaved copy with a new code; Save stores it with the saved password of its source) and Delete as on other pages. They are stored in nuBuilder Forte's table zzzzsys_app_cloner – the same configurations nuBuilder Forte's App cloner opens, and the other way round. Not saved: the target password (a password saved with nuBuilder Forte's App cloner is used when the field stays empty), Create it when it does not exist and Leave out sessions (both on when a configuration is opened). Download SQL, Dry run and Run work with the values on the page, saved or not.
  • SQL Server: tables, views, functions, procedures and DML triggers of your schema (usually dbo). The structure is read from SQL Server's catalog: columns with IDENTITY, defaults, computed columns, primary key, unique and check constraints, indexes (XML, spatial and columnstore indexes are reported and left out). Foreign keys are added after the data, so the order of the tables does not matter; functions come before the views that may use them. Data is copied in batches (max. 1000 rows per INSERT) with IDENTITY_INSERT. Collation instead of character set; INSERT only (no INSERT IGNORE / REPLACE); SQL Server has no events (SQL Server Agent jobs are not copied). The SQL file separates batches with GO – run it in SQL Server Management Studio or with sqlcmd -S server -d newdb -i file.sql; it can be run again on the same database (foreign keys and tables are dropped first). Encrypted modules cannot be read and are reported.
