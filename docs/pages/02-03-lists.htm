Lists (browse)

Searching, sorting, filtering, paging, printing and exporting lists.

For: Everyone

  • Search: type into the search field and press Enter. Several words must all match. Dates are found as they are displayed. As in nuBuilder Forte (4.x), "two words" in double quotes are searched together, and a minus leaves rows out: GmbH -Berlin, -"on hold". Accents and case do not matter (cafe finds Café). The words found are highlighted in the list – in form lists only in the columns that are searched, in nuBuilder Next's own lists in every column; form code can mark other text with $(…).nuHighlight(…) (colour: CSS variable --nu-highlight, elements with the class nuNoHighlight are left out). Back to all records: the button right of the search (shown while a search or a column filter is active, also in form lists) removes the search words and column filters – sorting, rows per page and a filter set by form code stay; Esc in the search field and the browser's × in the field remove the search words and show the list again at once. On a computer the cursor is already in the search field of nuBuilder Next's own lists (Users, Access levels, Forms …).
  • Same look everywhere: browse lists of your own forms look like nuBuilder Next's lists – the search field (350 px, search button on the right) sits inside the list card, the table has the same header and row height. Form code keeps working: #nuSearchField, #nuSearchButton, #nuBrowseTable, nuHideSearchField(), nuDisableSearchField().
  • Filters of nuBuilder Next's own lists (group, status, type, dates …) are hidden behind the filter button (funnel) right of the search field; they stay open while a filter is set, and the × button resets search and filters. Some views open with their filters shown (the log) – a saved list view can do the same.
  • Form info (globeadmin only): next to Delete (before the layout buttons) shows the form's title, code, description, type, form ID, table, primary key and browse SQL – in a record also its ID and, from the audit trail, when it was created and last changed (and by whom; not in the audit trail when nothing was recorded). copies one value, Copy all everything as “Label: value” lines. Next to the browse SQL, shows it in a large dialogue (with Copy) and opens a new tab with the form's list in design mode and the code window on the browse SQL. Esc or a click outside closes it.
  • Sort: click a column title; click again to reverse the order.
  • Column width (as in nuBuilder Forte (4.x) – browse lists of your forms, lookups and nuBuilder Next's own lists such as users, forms, procedures or the log): drag a column title to the left or right – with the mouse or a finger – to make the column narrower or wider (at least 40 px; the right edge of a title shows the resize cursor; a narrow column ends with …). A click without moving still sorts. The widths stay while you page, sort and search in that list (in the own lists per view) and are gone when the browser tab is closed – they are not saved; the column widths of a saved list view stay as they are. Form code can switch this off with nuDisableBrowseResize().
  • Filter: columns with a filter have a list with the column title next to the search field (as in the users list); choosing a value keeps the search words. The filter button (funnel) shows or hides the lists; it is filled while a filter is set.
  • Open a record: click the row. Add creates a record (if you have the right). The buttons of a list or record (Add, Print, Save, Clone, Delete …) sit right after its title, so they stay close on wide screens.
  • Pages: below the list, the total number of records; when the records fill more than one page also Back / Next and the page size – a list that fits on one page shows only the total. With several pages, click the page size (e.g. 50 per page) to show 10, 25, 50, 100, 250 or 500 rows – the choice stays while you page, sort and search in that list (it is in the address, per=); opened again from the menu, the list uses its own size again. Phones show no page size. The forms list shows up to 500 forms per page (list view Default), so the pager appears there only from the 501st form. Back / Next change the page; click Page x / y, type a page number and press Enter to jump there (Esc cancels).
  • Export menu (if you have the print right; not shown while the list has no records): HTML page (print) – the current list in a new tab –, CSV … and Excel (a real .xlsx with typed cells) – search, sort and filters apply. In the print view of the system lists the × after a column title hides that column (for printing and Copy); Undo shows the last one again, Reset view all of them – the browser remembers the hidden columns per list.

nuBuilder Next's own lists

  • Active filters appear as chips below the search – also the view's own ones such as Status: Active while the filter panel is folded; the × of a chip removes that filter.
  • Empty lists say what the list is for and offer the first record (Add the first one) instead of a search field; when the search or a filter hides every row, Show all removes them.
  • Users list (see Users): columns Position (after Department / Team) and Code (after Login name), both sortable; Created and Last changed (when and by whom, in the view All columns); filters such as Position (all, one position or "(no position)"), access level, permission item.
  • The users list has no row buttons: open the user to clone, archive or delete them. The access levels list has only a Clone button in the rows (hidden below 768 px); delete an access level on its page.
  • Forms list: filter Group (all, one group or "(no group)"); the column Status shows nuBuilder Forte's form status (Active, Draft, Archived – set in design mode). Form designers can also right-click the status (long press on touch screens) and pick another one; the same rules as in design mode apply (an open draft asks first or is refused, Only through drafts lets only the globeadmin change a published form), and the change is kept in the form's history. By default archived forms are hidden (filter Status: All except archived); choose All or one status to see them. Further filters: Type and With a draft (forms with an open draft). The column Access levels counts the levels that have the form – a click opens the dialogue to change them (users with rights on the access level form); the table opens in the database tool for users who may use it.

Advanced search (form lists)

The button next to the search of a form's list opens the Advanced search: one row per condition – a column of the list, a condition and a value. Add condition adds a row, all / any decides whether every condition or one of them must match, Apply shows the list. The conditions appear as chips below the search – on a chip removes that one, (Back to all records) or Clear removes all. They work together with the normal search and the column filters, and stay with paging, sorting, Print and Export; the address of the page can be shared.

  • Text: contains, does not contain, equals, is not, starts with, ends with, is one of / is none of (values separated by ;, or chosen from the list for columns with a filter), is empty, is not empty.
  • Numbers (columns with a number format): equals, is not, less / greater than, at most / at least, between, empty. 1'234.50 and 1234,5 are both understood.
  • Dates (columns with a date format): on, before, after, between, today, the last 7 / 30 days, this month, this year, empty.

My searches (below the conditions): give the current search a name and Save it – it is listed there for you on this form from then on; a click uses it, deletes it. Columns that are hidden in the list (width 0) or hidden / masked by field data access are not offered.

Form code: nuNextAdvancedSearch() returns the current search, nuNextAdvancedSearch([{column: 'Country', op: 'in', value: ['GB', 'DE']}], 'all') sets one and reloads the list; Before Browse reads it as #ADV_SEARCH# (JSON).

Export: HTML page, CSV, Excel

Lists (form browse lists and nuBuilder Next's own lists such as Users, Access levels, Log, Files …) have an Export menu with an HTML page (print), CSV … and Excel; the HTML page has a Print button when your access level has the right Print on the matching form. As in nuBuilder Forte it opens the list as a table in a new tab – with the current search, filters and sort and all rows, not only the page you see (up to 5,000).

  • Copy puts the table on the clipboard – it pastes as a table into Excel, Word or an e-mail (as tab-separated text into plain-text fields). To print, use the browser's print command (Ctrl+P).
  • Export CSV asks for the delimiter (semicolon, comma, tab, pipe; default $nuConfigCSVSeparator), the file name, whether the first row holds the column titles and whether the file starts with a UTF-8 BOM (so that Excel shows umlauts correctly) – then the download starts (up to 50,000 rows). Your choices are remembered in this browser.
