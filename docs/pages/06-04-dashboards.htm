Dashboards

KPI tiles, charts and tables from SQL, on start pages and forms.

For: Administrators (globeadmin, admin roles)

Admin tools → Dashboards (globeadmin) builds dashboards from SQL. A dashboard is a set of widgets and can be shown on the start page of users and anywhere on any launch or edit form.

  • Widgets: KPI tile – first column = value, optional second = previous value (change ▲▼ in %), third = a note; colour by thresholds (low / high, higher is better). Chart (ApexCharts) – columns, bars, line, area, pie, donut, radial: first column = categories (x axis), every further column = one series named after the column; pie / donut: label and value. Table – the rows as returned (up to 100). Per widget: width (quarter … full; tablets show two, phones one per row), number format, decimals, text before / after (e.g. USD), chart height, stacked, a link (form list, report or address), cache and automatic refresh.
  • Data sources: SQL – exactly one SELECT; a saved SQL builder query; or a PHP procedure that hands over its rows with nuDashboardData($rows) (a list of arrays, e.g. [['month' => 'Jan', 'sales' => 120], …]; the user does not need access to the procedure). Everything runs read-only (rolled-back READ ONLY transaction, 10 s time limit) – a widget cannot change data.
  • Hash variables: the user's (#USER_ID#, #USER_CODE#, #ACCESS_LEVEL_CODE#, #LANGUAGE# …), the date filter #DATE_FROM# / #DATE_TO# (YYYY-MM-DD) and on forms #RECORD_ID# and the fields of the record (#cus_id#). Values are escaped – write them in quotes: WHERE ord_customer_id = '#RECORD_ID#'. The values of the saved record are read from the database, not from the browser; fields that are not saved (criteria of a launch form, display fields) come from the page. Widget titles may contain hash variables too (Orders of #cus_name#).
  • Start page: Show on the start page + access levels (none ticked = every user). Users see the dashboards of their access level above their forms, in the dashboards' order. The globeadmin's start page keeps its tiles.
  • On forms: add an HTML object in the form builder with <div data-nu-dashboard="CODE"></div> – position, size and tab as for any object (make it large enough; it scrolls otherwise). nuBuilder Forte (4.x) shows an empty box there, so the form keeps working in nuBuilder Forte. In form JavaScript: nuNextDashboard('CODE', 'element_id'); nuNextDashboardRefresh() (or nuNextDashboardRefresh('CODE')) reads the data again, e.g. after the criteria of a launch form changed. Everyone who may open the form (and the record) sees the dashboard, unless access levels are ticked. On a new record, widgets that use #RECORD_ID# or a field show Available after saving; after saving they are filled. The dashboard page shows the snippet to copy and the forms that use it.
  • Date filter: shown above a dashboard when one of its widgets uses #DATE_FROM# / #DATE_TO# – today, yesterday, last 7 / 30 / 90 days, this / last month, this quarter, this / last year, all or custom dates. Each user's last choice is remembered in the browser; the default comes from the dashboard.
  • Test on the widget page runs the widget before saving (with a date range and an optional #RECORD_ID#) and shows the preview and the rows. The dashboard page shows a live preview of all widgets.
  • Cache: results are kept per user for the widget's cache time (default 60 s), so a busy start page does not run every query on every visit; the refresh button reads them again. Errors are shown in full to the globeadmin only, users see Not available.
  • Examples in the sample data (Admin tools → Sample data): sample_sales (start page of sample_manager / sample_sales: KPIs, charts, latest orders, date filter), sample_products (start page of every sample level: SQL, the SQL builder query sample_orders and the PHP procedure sample_dashboard_data), sample_customer (customer form, tab Statistics, #RECORD_ID#) and sample_country (sample start form: the field home_country filters, its onchange calls nuNextDashboardRefresh('sample_country')).
  • Stored in nuBuilder Next's tables zzzzsys_nunext_dashboard and zzzzsys_nunext_widget (part of backups and App cloner copies). Charts use the bundled ApexCharts (loaded only where a dashboard has a chart) and follow dark mode and the branding accent colour. Pages with dashboards allow style attributes and a per-page style nonce for ApexCharts; scripts stay restricted.
