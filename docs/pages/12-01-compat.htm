Compatibility check

Which nuBuilder functions your application uses and whether they work.

For: Administrators (globeadmin, admin roles)

Start page → Compatibility check scans all code of your application – form JavaScript, object events, lookup code, HTML objects, the setup header and procedures – for calls of nu…() functions and shows for each one whether nuBuilder Next supports it:

  • supported – works in nuBuilder Next; stub – exists but does nothing yet; missing – a nuBuilder function nuBuilder Next does not have (the call fails); unknown – not a nuBuilder function (typo, other library); your own – defined in your code or $nuConfigIncludePHP.
  • Each row shows the number of calls and where they are; form names link to the builder. Show supported functions too lists everything, Include nuBuilder's own forms also scans the nu… forms.
  • Run it after importing an application into a database used by nuBuilder Next, and before opening it to users.
  • nuBuilder 4.9 features: the features of the nuBuilder 4.9 compatibility review your application uses, with the places (form, object, procedure, line of nuconfig.php) and since which version nuBuilder Next supports them – red = not supported yet, test these places by hand. IDs as in the review: C1–C6 (browse columns with table names or aliases, AS aliases, browse SQL without the primary key, SELECT * over joins, nu_filter_match, access conditions), M1–M10 (scripts in HTML objects, nuAddBrowseTitleSelect, multi-value filters, selects from a procedure, files into the file system, $nuConfigIncludeJS / …CSS, nuAfterSave, nuFORM methods, report PDFs from PHP, SSO), N1 (nuSERVERRESPONSE), I3 (MyISAM tables). Also the points of the nuBuilder 4.9 gap analysis – not only function names: G1 access levels with data mode / form type, G2 global hook procedures, G3 calc objects on sub-forms, G4 events onnuload / onenter, G5 nuFORMdata, G6 scripts, frames, styles or images from other sites (blocked by the Content Security Policy), G7 hash variables nuBuilder Next does not set (#USER_GROUP_ID#, #USER_A11Y#, lower-case internals such as #form_id#), G8 hidden procedures that read #RECORD_ID# / #FORM_ID# (values can differ from nuBuilder's).
  • Hash variables outside quotes: #field# is escaped for a quoted string only. In WHERE id = #field# or $x = #field#; a user can put SQL or PHP into a field value. The list shows every procedure, hook, browse SQL, select / display SQL and SQL builder query with such a variable (also SQL inside PHP strings, nuRunQuery("… = #x#")). Fix: '#field#' in quotes, or parameters (nuRunQuery($sql, [$value])). Variables the server sets (#USER_ID#, #FORM_ID#, #TABLE_ID# …) are not listed; #RECORD_ID#, #ID# and #CODE# are – they come from the browser.
