First steps

What nuBuilder Next is, how the start page works and how to find your way around.

Welcome to nuBuilder Next

nuBuilder Next is a modern front end for nuBuilder Forte 4 applications. It runs on the same database as nuBuilder Forte (4.x) – the same forms, users, access levels, procedures and reports – so both can be used side by side: an application built in one opens in the other.

  • nuBuilder Forte's tables all start with zzzzsys_. nuBuilder Next reads and writes them in nuBuilder Forte's formats and adds only its own tables (zzzzsys_nunext_…: log, sessions, two-factor data, settings, dashboards …).
  • The globeadmin is the main administrator. Its name and password are not stored in a user record but in the configuration file nuconfig.php. The globeadmin may do everything.
  • All other people are users. What they may do comes from their access level – exactly as in nuBuilder Forte. In addition, nuBuilder Next can give a user an admin role: a defined part of the globeadmin's rights.

How this tutorial works

  • There are three tutorials: Basic – the essentials –, Advanced – everything in Basic plus in-depth lessons for developers and administrators (marked Advanced) – and Coming from nuBuilder Forte – what works differently and what is new, for people who know nuBuilder Forte. The buttons at the top switch at any time; lessons you have done stay done.
  • The lessons come in parts: Basics (finding your way, users and rights), Building applications (forms, code, reports, e-mail), Administration (settings, security, updates) and – in the advanced version – In depth (event order, code functions, drafts, data access, operations).
  • Each lesson explains one topic. Links with open the page in a new tab, so this lesson stays open; links with open the matching chapter of the documentation.
  • A green Try it box suggests a small exercise. When you are done, click Done – next lesson. Your progress is saved; the start page tile shows it.
  • The tutorial is in English, like the documentation. The pages themselves follow your language.

Look at the list of lessons on the left (below on a phone). Then click Done – next lesson.

The start page and navigation

After signing in, the globeadmin sees the start page: tiles in groups such as Users & rights, Development, Communication, System, Look, Data and Integration. Each tile opens one area.

  • + on the right of a tile opens a new record straight away (e.g. a new user). ▾ opens a menu with the pages behind the tile (e.g. Forms → New form, Cloner, Formats, Translations …).
  • Badges on tiles show information at a glance: an update of the Sample data, how many points of System status need a look.
  • The search field above the tiles filters them as you type (/ jumps into it). Below, More results also lists forms, procedures, reports and the pages of the ▾ menus. English words always work, too.
  • Ctrl+K (or the magnifier in the top bar) opens the same search on every page.
  • The top bar: the logo always leads back to the start page; the theme button switches light / dark / automatic; the language menu changes the interface language; the user menu (top right) holds Help, this tutorial, the database tools and Sign out (System status and Security are start page tiles).
  • Back (first button on every page) goes one level up – from a record to its list, from a list to the start page.
  1. Open the start page and type mail into the search field – see which tiles stay.
  2. Press Ctrl+K, type users and press Enter.
  3. Switch the theme to dark and back.

Working with forms and lists

Everything your users do happens in forms: a list (nuBuilder Forte calls it browse) and an edit form for one record. nuBuilder Next's own pages (users, access levels …) work the same way.

Lists

  • Type into the search field and press Enter – several words must all match. Click a column title to sort; click again to reverse.
  • Filters sit behind the funnel button next to the search field; × resets search and filters.
  • Click a row to open the record; Add creates a new one. Print opens the list in a new tab – with Copy (for Excel) and Export CSV.

Edit forms

  • As soon as something changes, Save turns red. Ctrl+Shift+S saves. Leaving with unsaved changes asks first.
  • Clone copies the record into a new, unsaved one (yellow frame) – nuBuilder Next's own pages (procedures, reports, access levels …) do the same: the copy is only stored when you save it. Delete asks first.
  • A red * after a label means "required", a key means "must be unique" – hover it for the explanation.
  • The ⋮ button at the end of the toolbar lists everything you can do on this form, each with its keyboard shortcut. As globeadmin you also find the design shortcuts, Inspect record and the hash variables there.
  • Sub-forms (rows inside a record): typing in the empty last row adds a row. Lookups: type a code or click the search button.
  1. Open the sample customer list, search for a customer and open it.
  2. Change a field – watch Save turn red – and save with Ctrl+Shift+S.
  3. Open the ⋮ menu and look at the entries.
  4. Open an order and add a line in its sub-form.

Users and rights

Who may sign in, and what they may do: users, access levels, permission items and admin roles.

How rights work

Before creating users it helps to know the model – it is nuBuilder Forte's:

  1. Every user has exactly one access level. Without one the login is refused.
  2. An access level lists the forms the user may open. Per form: view (the row exists), Save, Add / New, Delete, Clone and Print.
  3. Procedures (PHP code) and reports are allowed per access level too.
  4. Permission items are named switches your own code checks – for finer rules ("may approve invoices").
  5. The globeadmin may do everything.

nuBuilder Next's own pages are protected by nuBuilder Forte's system forms: the users page by nuuser, access levels by nuaccess, design mode by nuform, procedures by nuprocedure and so on. Give an access level the row nuuser and its users see the users page.

Admin-equivalent rights: changing rights on nuform, nuprocedure, nuselect, nusetup, nuuser or nuaccess amount to full control – PHP on the server, SQL on every table, the passwords of all users. With Only the globeadmin grants admin rights (Security check, on by default) only the globeadmin hands them out.

How rights work

Access levels

Access levels define what a group of users may do. Create one per role in your organisation (e.g. sales, accounting, read only).

  • Forms: add a single form from the list, or Several… to pick many at once (search, filter by group and type) and set the buttons they get – e.g. everything but Delete.
  • Removing a form crosses its row out; it disappears when you save. Until then the same button brings it back.
  • Procedures and reports: on their own tabs.
  • From the form: on any form, ⋮ → Access levels… (or Tools in design mode, or the number in the forms list's column Access levels) shows every level for that one form – the quick way to give a new form to several levels at once.
  • Use two-factor authentication: users of this level confirm the login with an authenticator app or an e-mail code.
  • The level's start form (nuBuilder Forte's home form) opens in nuBuilder Forte after signing in; in nuBuilder Next it is the first tile of the level's automatic start page (next lesson).
  • An access level with users cannot be deleted. Clone copies it with all rights – the quickest way to a similar level.
  1. Open Access levels and open sample_editor: see which forms and buttons it has.
  2. Clone it as tutorial_level, remove the Delete right on the customer form and save.

Creating and managing users

Users lists everybody who may sign in (active users by default; the filter shows expired and archived ones).

  • New user: full name (it fills first and last name), e-mail, login name (unique), access level and a password – the magic wand creates a strong one. Change password at next login makes the user choose his own.
  • Welcome e-mail (when e-mail is set up): instead of telling the user a password, send a personal link to set one. The password field can then stay empty. With Preview the e-mail before sending you see the mail before the user is saved – recipient, subject and text with every placeholder filled in; you can change the text or choose another template, and the link to set the password stays in place.
  • Valid until: the login works through that day. Archive sets it to yesterday – the user can no longer sign in, but all data stays. Delete removes the user for good.
  • Language: the user's interface language (empty = browser). Position, department, team suggest values of the other users.
  • Reset 2FA removes the user's authenticator app – e.g. after a lost phone.
  • Import… in the users list creates many users at once from a CSV file, with the same checks as the user form; existing logins are skipped.
  • The View button switches the list's layout: Default, Compact, All columns or your own views – columns, order, filters and the cards on a phone. Shared views can be limited to access levels.
  1. Create a user tutorial_user with the access level tutorial_level from the last lesson (or sample_viewer) and a generated password.
  2. Archive the user, look at the list with the filter All, then clear Valid until again.

Permission items

Sometimes users of the same access level need different rights – one sales person may give discounts, the others may not. Permission items solve this:

  • An item has an ident (the name used in code, e.g. sales_discount) and a group.
  • Assign users on the item, or tick items at the bottom of the user form – both edit the same list.
  • Your code asks: PHP nuUserHasPermission('sales_discount'), JavaScript the same, SQL #USER_PERMISSIONS#. Used in code on the item shows where.
Always check on the server (e.g. in Before Save) – a check in the browser alone can be bypassed.

Seeing the application as a user

To check what a user really sees – menu, forms, buttons, rights – you do not need his password: Act as user (the icon in front of the name in the user form, or a row of Logged-in users).

  • View only: everything the user sees, but nothing can be changed. The bar on top is blue.

Logged-in users

Logged-in users shows every active session: user, address, browser, login time and last activity (green = active in the last five minutes).

  • End session signs one user out at his next click – e.g. after changing his rights.
  • Log out all others before maintenance work; Log out everyone includes you.

Admin roles: sharing the administration

Nobody but the globeadmin should know the globeadmin password. When others need to help – a colleague who manages users, a developer, support – give them an admin role.

  • A role is a set of rights, one per tool, each view or change. A user gets at most one role (field Admin role in the user form).
  • Five default roles: Full administrator, Administrator without system, Developer, User manager, Support (read only) – editable and copyable.
  • A user with a role sees the tiles, menu entries, search results, help chapters and tutorial lessons of his rights. Pages he may only view show View only.
  • Rights marked full access (red) – Update, nuconfig.php, Database, forms, procedures, acting as another user … – lead to full control in the end. Give them only to people you would trust with the globeadmin password.

Open Admin roles and look at the default role User manager. Give tutorial_user this role, then act as that user and look at the start page.

Building forms

From a database table to a working form: design mode, objects, layouts and run buttons.

Forms, tables and the forms list

A nuBuilder Forte form shows the records of one table (or a view): the list (browse) shows some columns, the edit form all fields. Types: browse and edit, browse only, edit only, launch (a start page or a criteria form without table) and subform (rows inside another form).

The forms list shows all forms with group and status (Active, Draft, Archived). Click a form to open it as a user would; the button opens it in design mode. nuBuilder Forte's own forms (nu…) are not changed here.

Open the forms list, filter by status, then open sample_order in design mode ().

Forms and design mode

Creating a form

New form asks in three steps: the form (description, code, type), the table and its fields, then the layout and who may use it. For the table there are two ways:

  • Existing table: pick the table and its primary key – objects and list columns are generated from the columns; Choose columns and order picks only some of them, their labels and their order.
  • New table: enter the columns (name, label, type, length, required). The table gets a nuBuilder-Forte-style text primary key and, if you like, audit columns (created / updated at / by) that are filled on every save.

Afterwards the form opens in design mode. Give your forms a meaningful code and a group – the forms list and the access level page filter by them.

A new form is not yet in any access level: only the globeadmin can open it until you add it to an access level.

Create a form tutorial_task with a new table tutorial_task and the columns tsk_title (text, required), tsk_due (date) and tsk_done (checkbox), with audit columns. Open it and add two records.

Creating a form

Settings, the list, code and history

  • Form settings: in design mode with nothing selected (or the window icon in the icon bar) – description, code, group, type, status, table, the list's rows per page, the layout and Show tab order; Tools leads to Change with AI, Data access and Delete form.
  • Layouts: absolute (pixel positions as in nuBuilder Forte), auto (responsive rows worked out from the positions) and grid (12 columns). Auto and grid work well on phones.
  • The list: Design on the form's list – click a column title to change its title, column or SQL expression, width, alignment and format; drag titles to reorder, + adds a column.
  • Code (icon bar): the form's JavaScript, CSS, PHP hooks and browse SQL in one editor; Ctrl+S saves. History keeps the last 100 states of the form – compare any of them with now or restore it.
  • If an object's ID has no column in the table yet, the panel offers to add it; Change column… in an object's Tools changes its type.
On any form page, Ctrl+Shift+A opens design mode, Ctrl+Shift+H with Add, Ctrl+Shift+O with Structure.

Designing a form

Design mode: changing a form where it runs

Open a record and click Design in the form's toolbar. The form stays as it is – with its data and tabs – and gets a bar at the top, an icon bar on the left and a properties panel on the right.

  • Select and move: click an object, Ctrl+click for more, drag to move, the corner handle to resize, arrow keys for small steps; Delete deletes after a question, Ctrl+D duplicates.
  • Properties: Content, Behaviour (access, validation, events), Layout and Style – More settings opens the rest. With nothing selected the panel shows the form's settings.
  • Structure (icon bar, Ctrl+K) lists the tabs and objects – search, click to select, drag to change the order. Add lists the table's columns that are not on the form yet and every object type: click to add, or drag onto the form.
  • Tabs: double-click a tab to rename it, + adds one, drag to reorder; right-click to hide, move or delete it.
  • Changes of a published form go into a draft: users keep the published form until you click Publish.
  1. Open a record of tutorial_task and click Design.
  2. Rename the label of tsk_title in the panel and drag tsk_done next to it.
  3. Add a Word / text object from Add, then Publish with a short note – or Discard to throw the changes away.

Design mode

Object types

Objects are the fields and elements of a form. The most important ones:

  • Input – text, number, date, checkbox, file, button, masks (IBAN, phone). Text area and WYSIWYG editor for longer texts.
  • Select – a list of values or SQL; searchable, also with multiple values.
  • Lookup – picks a record of another form (e.g. the customer of an order): type a code or search in a list.
  • Display and calculation – show a value from SQL or calculate from other fields (e.g. the order total).
  • Sub-form – rows of another table inside the record (order lines).
  • Run – a button or iframe that opens a form, runs a procedure or a report.
  • HTML, content box, image, chart, word (a label).

Every object has an access setting (editable, read only, hidden, hidden for users, globeadmin only) and a validation (none, required, unique, both) – checked on the server, too.

Open the sample form All objects and click through its tabs – every object type is there. Then open it in design mode to see how each is set up.

Object types · Run objects

Code: events, hash variables and the code editor

Forms come alive with code – exactly as in nuBuilder Forte:

  • PHP events on the form's Code tab: Before Browse, Before Edit, Before Save, After Save, Before Delete, After Delete. Typical: check values in Before Save and stop with nuDisplayError('…').
  • JavaScript of the form and object events (onchange, onclick …) run in the browser.
  • Hash variables such as #RECORD_ID#, #USER_ID# or #cus_name# (a field of the record) are replaced before the code runs. In SQL always put them in quotes: WHERE cus_id = '#RECORD_ID#'.
  • Code fields open the code editor with a double-click: colours, search and replace, Format, full screen.
  • ⋮ → Hash variables on any form shows the values available there.
The Prompt generator builds a prompt for an AI tool with the right nuBuilder Forte context (scopes, functions, your table columns) – useful when you write code for a new event.

In tutorial_task, add a Before Save event that refuses a due date in the past:

if ('#tsk_due#' !== '' && '#tsk_due#' < date('Y-m-d')) {
    nuDisplayError('The due date is in the past.');
}

Show tsk_done as a coloured badge in the list of tutorial_task: add it as a list column if it is not one, then put this into the list's JavaScript (Code in design mode) – the number is the column's position, counted from 0:

nuBrowseStyleBadge(2, [
    {equals: '1', label: 'Done', bg: '#d1e7dd', icon: 'check'},
    {default: true, label: 'Open', bg: '#cfe2ff'}
]);

The first rule that matches wins. Without code, design mode does the same: select the column title → Show as badge → Colour rule.

Procedures, reports and dashboards

Server code, PDF reports and dashboards with key figures and charts.

Procedures

Procedures are PHP code stored in the database (zzzzsys_php). A run button, a tile or nuRunPHP('code') starts them – in a new tab (output visible) or hidden (background work, then a message).

  • Access levels tab: who may run it. Usage: which objects and code start it. History: every change with the code before and after.
  • Hidden / New tab on the page run the saved version as a test.
  • Some codes have a special meaning in nuBuilder Forte: nu_before_save (for every form), nu_startup, nu_check_password_policy, nu_send_welcome_email.
  • Debug with nuDebug($value) – the output appears under Debug.

Create a procedure tutorial_hello with echo 'Hello ' . '#USER_ID#';, run it in a new tab, then write nuDebug('test'); into it, run it hidden and look at Debug.

Procedures in the documentation

Reports and the SQL builder

Reports produce PDFs in nuBuilder Forte's format (they work in both). A report has:

  • A data source: a table or view, an SQL builder query, or a procedure that fills a temporary table #TABLE_ID#.
  • An optional launch form for criteria (e.g. a date range); its fields are available as hash variables.
  • The layout in the report designer: bands (report header, page header, groups, detail, footers) with fields, texts, lines, boxes and images.
  • Access levels that may run it.

The SQL builder creates queries graphically: add tables, tick columns, drag a column onto another to join, add conditions and sorting. Run shows the first rows.

The PDF needs TCPDF – taken from nuBuilder Forte when nuBuilder Next sits in nuBuilder Forte's folder. Without it the report pages say so.

Open the sample report sample_customers (customers by country) in the designer, look at its bands and run Preview. Then open the SQL builder query sample_orders.

Dashboards

Dashboards show key figures, charts and tables – on the start page of users (per access level) or inside any form.

  • A dashboard holds widgets: KPI tiles (value, change in %, colour by thresholds), charts (columns, bars, line, area, pie, donut …) and tables.
  • Data comes from one SELECT, an SQL builder query or a PHP procedure – always read-only.
  • #DATE_FROM# / #DATE_TO# add a date filter; on forms #RECORD_ID# and the record's fields filter the data.
  • On a form: an HTML object with <div data-nu-dashboard="CODE"></div>.
  • Tables that open a record: give the table's query a column nu_record_id (the record's key – it is not shown) and choose the form: a click on a row opens that record, with Open in a new tab in a tab of its own.

Start page hooks

A procedure with the code nu_home runs every time the tile start page is built (nu_home_user on the start pages of users). Its PHP can put a badge on a tile (an open count, a warning), change a description, hide a tile for some admin roles, add a group with extra tiles or show a banner above the tiles – only for that page view, nothing is saved into the layout.

  1. Open Procedures and add a procedure with the code nu_home.
  2. PHP: nuHomeSetBadge('users', 'hook', 'info'); nuHomeBanner('Hello from the start page hook'); – save.
  3. Open the start page: the banner is above the tiles, the Users tile carries the badge. A mistake in the code? The page still shows, with the message above the tiles.
  4. Set the procedure's status to Draft to switch it off again.

The procedure's JavaScript runs on the start page too: nuHome.on('tile', function (tile) { … }) is called for every tile and can change its badge or description, hide it or react to a click.

index.php?p=home&tiles=1&safe=1 opens the start page without the hook. All functions: Start page hooks.

E-mail, look and data

E-mail: settings, test mail and templates

Password links, two-factor codes, welcome e-mails and your own mails need a mail server. E-mail → Settings uses nuBuilder Forte's settings:

  • SMTP server, port (465 = SSL/TLS, 587 = STARTTLS), user, password and sender. The password is never shown again – leave the field empty to keep it.
  • Test mail shows the whole conversation with the server – the fastest way to find a wrong setting.
  • E-mail log: every mail with its status and error.
  • Templates: subject and body with placeholders (#cus_name#), per language. Clone nuBuilder Forte's nu_send_welcome_email_template to write your own welcome e-mail.

Enter your mail server and send a test mail to yourself. If it fails, read the server conversation.

For messages inside the application use Notifications: the bell in the top bar turns red for the recipients – everybody, single users, departments, teams, positions or access levels – with read receipts and, if needed, a confirmation ("Got it") or an e-mail as well.

Importing and exporting data

  • Export: every list with the Print right has Print – a table in a new tab with Copy (pastes into Excel) and Export CSV. Search, filters and sort apply.
  • Import: CSV import in three steps – file (encoding and separator are detected), mapping (columns matched by name, dates and numbers converted, fixed values, nuID() for nuBuilder Forte ids), check (a complete trial run that changes nothing) and import. Add new records, update existing ones or both.

Running the installation

Settings, security, logs, updates and backups – what keeps an installation healthy.

Configuration: nuconfig.php and the setup wizard

nuconfig.php holds the database access, the globeadmin login and many settings – the same file and variable names as nuBuilder Forte. nuBuilder Next's own settings start with $nuConfig… too (session timeouts, password length, two-factor login, base URL …).

  • The Setup wizard asks for the most important ones in four steps: language and time zone, look and tools, security, sample data.
  • Configuration file (nuconfig.php) edits the file directly. Saving checks the PHP, runs it and tests the database connection first; the old file is kept as a backup.
  • Important on a live server: $nuConfigBaseURL (the address in e-mail links), $nuConfigSecretKey (encryption key), $nuConfigTimezone.
A broken nuconfig.php stops the whole site – and nuBuilder Forte too, if it reads the same file. The editor refuses to save a file that does not pass its checks; if something still goes wrong, copy a backup from _backup/ over it by FTP.

nuBuilder Forte can keep its settings in a table instead of nuconfig.php. Settings edits that table; it is only used with $nuConfigSettingsFromDB = true (the page offers to switch it on).

Security check and two-factor login

Updates and backups

New versions are installed on the Update page – no FTP needed:

  1. Choose nunext.zip and click Check package: version, changed files, what's new, database changes, and whether the package is signed by nuBuilder Next. Nothing changes yet.
  2. Developing in depth

Which code runs when, the function references, global code, page forms and forms written with an AI.

Event order: what runs when

The same hooks as in nuBuilder Forte 4.9 run, in the same order. PHP hooks run on the server and stop a step with nuDisplayError(); a JavaScript hook that returns false cancels the action.

  • Opening a list: global hook nu_before_save (as in nuBuilder Forte), the form's Before Browse, the list query – then in the browser nuLoadBrowseGlobal(), the form's nuOnLoad(formId, formCode) and the page hook of Global JS.
  • Opening a record (a new one has the id -1): nu_before_edit, Before Edit (nuSetFormValue() changes what is shown, nuAddJavascript() adds code), the objects are drawn – then scripts in HTML objects, nuLoadEditGlobal(), nuOnLoad(). Values set while loading do not mark the form as changed.
  • Saving: nuBeforeSaveGlobal() and nuBeforeSave() in the browser; on the server the concurrent-edit check, validation, nu_before_save, Before Save, one transaction for the record, its sub-form rows and the audit trail, then After Save; the form reloads and runs nuOnLoad(), then nuAfterSave().
  • Deleting: nuBeforeDelete(), Before Delete, one transaction, After Delete, nuAfterDelete().
Only the fields a user edited are written when an existing record is saved – changes others made to other fields stay. In Before Save, nuGetNuDataValue() / nuSetNuDataValue() read and change the posted values.

In tutorial_task, add to the form's JavaScript:

function nuOnLoad(formId, formCode) { console.log('loaded', formId); }
function nuBeforeSave() { return confirm('Save this task?'); }

Open a record with the browser's console open, change a field and save – cancel once, confirm once.

Form lifecycle and event order · How a save works

Code functions, hash variables and debugging

Forms written for nuBuilder Forte run their code unchanged – nuBuilder Next has nuBuilder Forte's PHP and JavaScript functions, plus a few of its own.

  • The Code reference (tab of the help) lists every PHP and JavaScript function with parameters, return value, an example and a sample result.
  • In every code editor, Insert in the toolbar offers these functions, and suggestions appear while you type.
  • Hash variables (#RECORD_ID#, #USER_ID#, #ACCESS_LEVEL_CODE#, fields of the record, values set with nuSetProperty()) are replaced in SQL, PHP and HTML – not in JavaScript, where nuGetProperty('name') reads them.
  • Debugging: nuDebug($a, $b) writes to Debug results; the globeadmin's right-click on a label opens the object menu (properties, rename, access, validation).

Add nuDebug('#tsk_title#', '#USER_ID#'); to the Before Save of tutorial_task, save a record and look at Debug results. Remove the line afterwards.

Drafts: change a form without disturbing users

In design mode, the first change starts a draft – a copy of the whole form. Users keep working with the live form while you change the draft; Publish replaces it in one step.

  • Save and Undo (20 steps) work in the draft only; Preview shows the draft to you alone, with a yellow banner.
  • Compare with live lists every change – objects, events, code line by line, list columns.
  • Publish… checks the draft, asks for a note and keeps the live form in the history first. Publishing needs the globeadmin or the admin right Publish forms (drafts).
  • The Security setting Only through drafts makes drafts the rule.

Start a draft of tutorial_task, rename a label, Preview it, look at Compare with live and publish it with a note.

Drafts and publishing

Data access: fields and list columns per user

nuBuilder Forte's read only and hidden only change the display. Data access (design mode → Tools → Data access) is enforced on the server:

  • Modes per field: Editable, Protected (never saved from the browser), Insert only / Update only, Masked (e.g. •••• 1234) and Withheld (not sent at all).
  • A default plus rules for an access level, a user, a permission item, a team or a department – the most specific rule wins; a rule can have an SQL condition.
  • List columns can be hidden per subject: a hidden column is not read, searched, sorted or exported.
  • Preview as user shows what a user gets and which rule decided it.

Familiar things, new places

Your nuBuilder Forte application in nuBuilder Next: what stays, and what you find somewhere else.

Same application, new front end

nuBuilder Next opens the same database as nuBuilder Forte (4.x): the same forms, objects, users, access levels, procedures, reports and SQL builder queries – stored in the same zzzzsys_ tables and formats. Both can run side by side on one database: what you build or change in one opens in the other.

  • Your forms keep their code: Before Browse, Before Edit, Before Save, After Save, Before Delete, the form's JavaScript, nuOnLoad, object events and procedures run as in nuBuilder Forte, with nuBuilder Forte's PHP and JavaScript function names.
  • nuBuilder Next only adds its own tables (zzzzsys_nunext_…) for what nuBuilder Forte does not have – log, sessions, settings, dashboards, audit trail …
  • This tutorial has two parts: What works differently (where familiar things are now) and New in nuBuilder Next. Each lesson links to the page and to the documentation.

Functions that behave differently or were not ported are listed with the reason in the documentation: Differences and functions not ported.

Run the Compatibility check: it scans your application's code for things that need attention in nuBuilder Next.

Start page and navigation

Instead of nuBuilder Forte's home form with its launch buttons, nuBuilder Next opens a start page with tiles.

  • Administrators see the admin tools as tiles (users, forms, procedures, reports, settings …); Customise arranges them, saves layouts and marks favourites.
  • Users get a start page per access level with tiles for their forms and reports – made automatically from their rights or arranged by you (user start pages). A level's home form from nuBuilder Forte still works.
  • The top bar has a search (Ctrl+K: any page, form, procedure, report), notifications, light / dark mode, language and the user menu. An optional side bar shows favourites and recently used pages.
  • The breadcrumb above each page replaces nuBuilder Forte's breadcrumb and Back – the browser's Back button works too.
  • Everything works on phones: lists become cards, the menus fold.

Press Ctrl+K, type the code of one of your forms and open it.

Forms at work

Your forms open as they are; the frame around them is nuBuilder Next's (Working with forms).

  • Buttons: Back, Save (turns red with unsaved changes, Ctrl+S), Clone, New, Delete – as nuBuilder Forte's action buttons. Leaving with unsaved changes asks first.
  • Layout: Absolute shows the pixel positions of nuBuilder Forte; Auto and Grid arrange the same objects in rows – useful on small screens. The choice is kept per form.
  • Browse lists: the form's browse SQL runs unchanged; search, sortable columns, column filters, page size and an export menu (HTML page, CSV, Excel) are built in.
  • Validation: No blanks shows a red *, No duplicates a key symbol – both are checked again on the server.
  • Two people on one record: nuBuilder Next shows who else has it open and, on Save, which fields someone else changed meanwhile (concurrent edits).

Open a record of one of your forms, switch between Absolute, Auto and Grid, and change a field without saving – then try to leave the page.

Building forms

nuBuilder Forte's form and object property screens are replaced by design mode on the form itself (Designing a form).

  • Design mode (the globeadmin and users with the save right on forms): Design on a record changes the form where it runs – select, move, a properties panel, tabs, new objects from the table's columns – like nuBuilder Forte's arrange mode and object properties in one (design mode).
  • Everything in one place: form settings, the list's columns (Design on the list, right-click a title for its menu), objects, tabs, code and history – all in design mode; Structure in the icon bar lists every object per tab, ? shows the keyboard shortcuts.
  • An object's ⋮ menu (or a right-click on it) clones it, changes its database column or deletes it; several objects move together with Ctrl + click and the arrow keys.
  • Drafts: changes can be made in a draft, previewed and compared, and published when they are ready – the live form stays as it is meanwhile (form drafts). Every published change is kept in the history and can be restored.
  • New form replaces Fast Form: table (new or existing), fields, list columns and the place on the User Home in one wizard. The Form cloner copies forms as nuBuilder Forte's Cloner does.
  • What design mode offers is stored in nuBuilder Forte's tables – a form built here opens in nuBuilder Forte.

Open one of your forms in design mode, select an object and move it with the arrow keys – then use Undo.

Code: what stays, what changed

  • Same events and functions: PHP hooks and procedures use nuBuilder Forte's functions (nuRunQuery, nuSetProperty, nuGetProperty, nuDisplayError …), form JavaScript nuBuilder Forte's (nuGetValue, nuSetValue, nuHide, nuMessage …). Hash variables (#RECORD_ID#, #USER_ID# …) work as before.
  • Code editors with syntax colours, an Insert menu of all documented functions and suggestions while typing; the documentation has a function reference with examples (Code reference).
  • Security: nuBuilder Next's own pages allow no inline scripts or styles (Content Security Policy). Form pages still run your form code as nuBuilder Forte does.
  • Setup → Header / Style / Include still apply to forms; code for all pages (also the start page and the admin pages) goes into Global code.
  • A few nuBuilder Forte functions behave differently or were left out on purpose – each with its reason: Differences and functions not ported.

Open a procedure, place the cursor in the PHP code and pick a function from the Insert menu.

Users, rights and settings

  • The user form is laid out in cards: person, login, access and account settings; a user can have additional access levels with an end date, and custom user fields extend it without changing zzzzsys_user.
  • Access levels work as in nuBuilder Forte. New: admin roles give a user part of the globeadmin's tools (e.g. only users, or only reports) – in nuBuilder Forte that was all or nothing.
  • Settings: nuBuilder Forte's Setup form is split into Settings (also the values of nuconfig.php, with descriptions), E-mail (with a connection check and test mail), Branding and Themes.
  • Updating: instead of copying files, Update installs a signed package – with a backup first, a check of the database changes and a way back.

Open Settings and find a setting you know from nuconfig.php.

Reports and the SQL builder

  • Reports use nuBuilder Forte's layout format: the report designer was rebuilt, but a report saved in either product prints the same in both (PDF with TCPDF).
  • The SQL builder stores its queries in nuBuilder Forte's format – tables, joins, clauses – with a preview of the result.
  • New: reports can be run through the REST API and sent as e-mail; dashboards show numbers and charts from SQL, SQL builder queries or procedures.

What nuBuilder Forte does not have

Features that are new in nuBuilder Next.

Security and sign-in

  • The Security check lists weak points of the installation with a fix for each (passwords, file rights, settings, libraries).

  • Work as a user (impersonate): see what a user sees – read only or with full access – without knowing the password.

Working with data

  • CSV import into any table with a field mapping and a dry run; Excel export of every list.

  • Forms with AI: describe a form, copy the prompt into any AI chat and paste the answer back – it becomes a draft (new form).

Integration

  • A REST API with clients, scopes and tokens: records of forms, users, reports as PDF, notifications – and the API playground to try it in the browser.
  • Page forms: a form type for your own PHP pages inside nuBuilder Next, with drafts and versions (pages).

Operation and administration

  • The App cloner copies the whole application – database and files – to a test installation.
  • Branding and Themes: own logo, colours, fonts and density, per access level.
  • Sample data, the self-test (developer mode) and this tutorial help to learn and check an installation.
  • Translations in eleven languages, light and dark mode, and an accessible layout.
